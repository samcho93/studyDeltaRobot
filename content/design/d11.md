## 학습 목표

- 처음 보는 요구사항 카드를 받아 **요구사항 표 → 치수 → 구동 → 툴·궤적 → 검증 → 보고서**의 순서로 델타로봇을 설계할 수 있습니다.
- 모든 설계 판단을 시뮬레이터·`deltarobot` 실행 결과(숫자)로 뒷받침하고, 불합격 → 수정 → 합격의 반복 기록을 남길 수 있습니다.
- 정해진 양식의 **설계 검증 보고서**를 작성하고 동료의 보고서를 루브릭으로 평가할 수 있습니다.

## 캡스톤 흐름

@fig[d11-design-loop] 캡스톤의 여섯 단계. ⑤ 검증에서 ✖가 나오면 원인이 된 단계로 돌아가고, 그 반복도 보고서에 남깁니다.

D08~D10에서 한 과정을 이번에는 **팀이 스스로** 합니다. 강사는 요구사항 카드만 나눠 주고, 설계안·검증·보고서는 팀이 만듭니다.

## 요구사항 카드

팀마다 한 장을 뽑습니다(강사가 숫자를 바꿔 새 카드를 만들어도 됩니다). 괄호 안은 검증 방법입니다.

| 카드 | 작업 | 페이로드 | 작업 실린더 | 속도 | 정밀도 | 제약 |
|---|---|---|---|---|---|---|
| A 약국 | 약병을 트레이 3곳으로 분류 | 30 g | D ≥ 250, H ≥ 60 mm | 40 사이클/분 (축소 Adept 150 mm) | 분해능 ≤ 2 mm | 모터는 스마트 서보 이하 가격대 |
| B 물류 | 소포를 컨베이어에서 상자 2곳으로 | 1.0 kg | D ≥ 600, H ≥ 150 mm | 40 사이클/분 (Adept 305 mm) | 분해능 ≤ 1 mm | 흡착, 유지력 SF 2 |
| C 전자 | 칩 부품을 트레이에서 기판으로 | 5 g | D ≥ 200, H ≥ 30 mm | 60 사이클/분 (축소 Adept 100 mm) | 분해능 ≤ 0.1 mm | 관성비 ≤ 5 |
| D 제과 | 케이크 위 크림 짜기 (그리기 장면) | 0.3 kg (크림 튜브) | 지름 200 mm 원을 한 높이에서 | 50 mm/s, 등속 ≥ 90 % | 백래시 오차 ≤ 0.3 mm | 벨트 또는 유성 감속 |

## 검증 스크립트 템플릿

위쪽 두 블록(요구사항, 설계안)만 바꿔 쓰는 판정 스크립트입니다. 결과를 **마크다운 표**로 출력하므로 보고서에 그대로 붙일 수 있습니다.
아래 출력은 예시 요구(5 g, D 200 × H 40 mm, 축소 Adept 150 mm 40 사이클/분, 분해능 2 mm)에 `edu_dynamixel` + `suction_20`을 넣은 결과입니다.

```python run
import math, itertools
from deltarobot import DeltaDesign, DeltaRobot
from deltarobot import kinematics as kin
from deltarobot import dynamics as dyn

# ---- 1. 요구사항 (팀 카드에서 옮겨 적기) -----------------------------------
REQ = {"payload": 0.005, "D": 0.20, "H": 0.04, "across": 0.15, "cpm": 40,
       "res": 0.002, "sf": 1.5}
# ---- 2. 설계안 ---------------------------------------------------------------
design = DeltaDesign.preset("edu_dynamixel").copy(
    tool="suction_20", payload=REQ["payload"])
SPEED, ACCEL = 0.5, 5.0
# ------------------------------------------------------------------------------

def tcp_resolution(d, p):
    dth = math.radians(d.motor_spec["resolution_deg"]) / d.ratio
    J = kin.jacobian(d, kin.ik(d, p), p)
    return max(math.sqrt(sum(sum(J[r][c] * s[c] * dth for c in range(3)) ** 2 for r in range(3)))
               for s in itertools.product((-1, 1), repeat=3))

def holding_force(d):
    t = d.tool_spec
    return 2 * t["friction"] * t["force"] if t["kind"] == "gripper" else t["force"]

rows = []
def item(name, value, op, limit, unit=""):
    ok = value >= limit if op == ">=" else value <= limit
    rows.append((name, value, op, limit, unit, ok))

problems = design.validate()
item("설계 오류 수", len(problems), "<=", 0)
c = kin.work_cylinder(design, REQ["H"])
item("작업 실린더 D", c["diameter"] * 1000, ">=", REQ["D"] * 1000, "mm")
zc, rc = (c["z_top"] + c["z_bottom"]) / 2, c["diameter"] / 2
pts = [(0, 0, zc)] + [(0.9 * rc * math.cos(a), 0.9 * rc * math.sin(a), zc) for a in (0, 2.1, 4.2)]
item("TCP 분해능(최악)", max(tcp_resolution(design, p) for p in pts) * 1000, "<=", REQ["res"] * 1000, "mm")

robot = DeltaRobot(design, scene="empty")
robot.set_speed(SPEED, ACCEL)
z = robot.scene.surface_z + 0.02
robot.move_to(-REQ["across"] / 2, 0, z)
t0 = robot.time
robot.arch_to(REQ["across"] / 2, 0, z, height=0.025)
robot.tool_on()                                   # 들고 가는 구간을 표시 (유지력 계산용)
robot.arch_to(-REQ["across"] / 2, 0, z, height=0.025)
robot.tool_off()
item("사이클", 60 / (robot.time - t0), ">=", REQ["cpm"], "회/분")
res = robot.analyze()
for key, name in (("peak_ratio", "피크 토크 비"), ("rms_ratio", "RMS 토크 비"),
                  ("speed_ratio", "속도 비"), ("curve_ratio", "속도-토크 곡선 비")):
    item(name, res[key], "<=", 1.0)
data = dyn.analyze(design, robot.backend.frames)
a = max(math.sqrt(f["a"][0] ** 2 + f["a"][1] ** 2 + (f["a"][2] + 9.81) ** 2) for f in data if f["tool"])
item("유지력 여유 (카탈로그/필요)", holding_force(design) / (REQ["payload"] * a * REQ["sf"]), ">=", 1.0)

print("| 항목 | 결과 | 요구 | 판정 |")
print("|---|---|---|---|")
for name, v, op, lim, unit, ok in rows:
    print("| %s | %.2f %s | %s %g | %s |" % (name, v, unit, op, lim, "✔" if ok else "✖"))
print("관성비 %.1f (참고), 문제: %s" % (res["inertia_ratio"], problems + res["problems"] or "없음"))
```

```text
| 항목 | 결과 | 요구 | 판정 |
|---|---|---|---|
| 설계 오류 수 | 0.00  | <= 0 | ✔ |
| 작업 실린더 D | 338.77 mm | >= 200 | ✔ |
| TCP 분해능(최악) | 0.46 mm | <= 2 | ✔ |
| 사이클 | 51.85 회/분 | >= 40 | ✔ |
| 피크 토크 비 | 0.12  | <= 1 | ✔ |
| RMS 토크 비 | 0.14  | <= 1 | ✔ |
| 속도 비 | 0.70  | <= 1 | ✔ |
| 속도-토크 곡선 비 | 0.34  | <= 1 | ✔ |
| 유지력 여유 (카탈로그/필요) | 170.21  | >= 1 | ✔ |
관성비 0.0 (참고), 문제: 없음
```

이 예시는 모두 통과했지만 **속도 비 0.70**이 다른 비(0.12~0.34)보다 훨씬 큽니다. XM430의 최고 속도(4.8 rad/s, 대표값)가 이 설계의 병목이라는 뜻이고,
사이클을 더 올리려면 속도가 먼저 막힙니다. 보고서에는 이런 **가장 큰 비와 그 원인**을 반드시 적습니다.

:::tip 템플릿은 출발점일 뿐
템플릿의 사이클은 축소 Adept 한 번입니다. 카드의 실제 작업(분류·컨베이어·그리기)을 수행하는 **응용 프로그램**을 따로 만들어
그 결과(점수, 개/분, `analyze()`)를 함께 제출해야 합니다. D08(분류), D09(컨베이어 추적), D10(그리기)의 프로그램을 고쳐 쓰세요.
:::

## 설계 검증 보고서 양식

```markdown
# <팀명> 델타로봇 설계 검증 보고서 — 카드 <A/B/C/D>

## 1. 요약 (5줄 이내)
- 최종 설계 한 줄 (치수, 모터·감속기, 툴)
- 핵심 결과 (작업 실린더, 사이클, 가장 큰 사용률과 그 항목)
- 합격/불합격 판정

## 2. 요구사항
- 요구사항 표 (항목 · 수치 · 근거)
- 가정 목록 (카드에 없어서 팀이 정한 것)
- 요구 변경 기록 (있다면, 이유와 함께)

## 3. 설계
### 3.1 치수 (R, r, L, l, w) — 스윕 표와 선택 근거
### 3.2 구동 (모터, 감속기, 감속비) — 후보 비교표, 관성비
### 3.3 툴 — 유지력 계산 (F_req = m·max|a−g|·SF)
### 3.4 궤적 — 프로파일, 속도·가속도, 아치 높이·반지름

## 4. 검증
### 4.1 판정표 (템플릿 출력 붙여넣기)
### 4.2 응용 프로그램 결과 (점수, 개/분, analyze(), 그래프 캡처)
### 4.3 반복 기록 (안 · 바꾼 것 · 결과 · 판정 · 원인과 조치)

## 5. 부품표 (BOM)
- 카탈로그 id · 수량 · 질량 · 비고 ("대표값, 데이터시트 확인")

## 6. 한계와 향후 과제
- 모델이 다루지 않는 것 (탄성·진동, 마찰, 탈조, 유지력의 실제 값 …)
- 실물로 옮길 때 확인할 항목

## 첨부
- 설계 JSON (시뮬레이터 연결 탭) · URDF · Python 코드 · 공유 링크
```

## 자주 나는 오류와 해결

| 증상·메시지 | 원인 | 해결 |
|---|---|---|
| `ValueError: 설계 오류: ...` (예: `planetary 의 감속비는 [3, 5, 6, 9, 10, 15, 20, 30, 50] 중에서 고르세요`) | 카탈로그 밖의 값 | 메시지의 목록에서 선택, `design.validate()`를 먼저 출력 |
| `WorkspaceError: 작업영역 밖: ... — 팔 길이로 닿지 않음` | 축소 Adept 거리(`across`)가 작업 실린더보다 큼 | `across ≤ 0.8 × D` |
| `WorkspaceError: 경로 중간 작업영역 밖: ... — 모터 각도 한계` | 아치가 작업영역 위로 나감 | 아치 높이↓, 작업 z↓ |
| `경고: 관절 속도 ... set_speed()로 속도를 낮추세요` | 모터 최고 속도 초과 (Playground는 계속 실행) | 판정표의 속도 비 확인, 속도↓ 또는 감속비 조정 |
| `analyze()` 문제 목록의 `피크 토크 초과 (안전율 1.2 포함)` / `RMS(연속) 토크가 정격을 넘습니다 — 과열 위험` | 구동계 부족 | D04 절차로 감속비·모터 재선정 |
| `RuntimeError: 가상 시간 600 s 제한을 넘었습니다 (무한 루프인가요?)` | 응용 프로그램의 대기 루프가 끝나지 않음 | 종료 조건(시간·부품 수) 추가 |
| 동료가 실행하니 숫자가 다름 | 시뮬레이터에 저장된 설계와 코드의 설계가 다름 | 코드에 `DeltaDesign(...)`/`copy(...)`로 설계를 명시 |

## 과제

1. 카드 한 장을 골라 보고서 양식 1~2절(요약·요구사항)을 캡스톤 전에 미리 작성해 오세요.
2. 검증 템플릿에 "가장자리 조건수 ≤ 2.5"(D03)와 "관성비 ≤ 10"(D04) 항목을 추가하세요.
3. 캡스톤 후, 여러분 팀 설계에서 모델이 다루지 않는 위험(탄성 진동, 탈조, 흡착 누설 등) 세 가지와 실물 시험 방법을 적으세요.
