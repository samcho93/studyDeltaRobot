## 학습 목표

- RC 서보·스마트 서보·스테퍼·BLDC·AC 서보의 **속도-토크 특성**을 `dynamics.available_torque` 모델로 비교할 수 있습니다.
- **피크 토크, RMS 토크, 속도(속도-토크 곡선), 관성비** 네 기준으로 모터를 판정하고, 결과 숫자의 의미를 설명할 수 있습니다.
- 감속비가 토크·속도·관성비에 주는 영향을 알고, 관성 정합 감속비 $N* = √(J_load/J_rotor)$ 를 출발점으로 감속비를 고를 수 있습니다.
- 감속기 종류별 효율과 백래시가 설계에 주는 영향을 말할 수 있습니다.

## 네 가지 판정 기준

T08의 간이 동역학 모델로 궤적을 따라 출력축 토크 τ(t)를 구하면, 모터 쪽 값은 감속비 N과 효율 η로 바뀝니다.

$τ_m = τ / (N·η)$,  $ω_m = N·θ̇$,  반사 관성 $J_drive = (J_rotor + J_gear)·N²$

`robot.analyze()`(= `dynamics.evaluate`)는 이 값으로 네 가지를 봅니다. 모두 **1 이하이면 통과**입니다.

| 기준 | 계산 | 의미 |
|---|---|---|
| 피크 비 `peak_ratio` | max τ_m × 1.2 / 피크 토크 | 가장 센 순간을 낼 수 있나 |
| RMS 비 `rms_ratio` | RMS τ_m × 1.2 / 정격 토크 | 계속 돌려도 과열되지 않나 (발열 ∝ 전류² ∝ 토크²) |
| 속도 비 `speed_ratio` | max ω_m / 최고 속도 | 그 속도로 돌 수 있나 |
| 곡선 비 `curve_ratio` | 매 순간 τ_m × 1.2 / 가용 토크(ω_m) | **같은 순간에** 속도와 토크를 동시에 낼 수 있나. 스테퍼는 가용 토크를 1.5로 한 번 더 나눔 |
| 관성비 `inertia_ratio` | 부하 관성(모터축 환산) / 로터 관성 | 판정에는 안 들어가는 참고값. 크면 서보 튜닝이 어렵고 진동 |

1.2는 `safety_factor` 기본값, 1.5는 스테퍼의 탈조 여유 `dynamics.STEPPER_MARGIN`입니다.

## 모터 종류와 속도-토크 모델

카탈로그의 모든 모터 사양은 **교육용 대표값**입니다. 실제 선정에서는 반드시 제조사 데이터시트를 확인하세요.

```python run
from deltarobot import DeltaDesign, catalog
from deltarobot import dynamics as dyn

print("모터          종류         피크   정격   최고속도  |  가용 토크 @ 0%  50%  90% 최고속도")
for mid, m in catalog()["motors"].items():
    d = DeltaDesign().copy(motor=mid, gearbox="none", gear_ratio=1)
    w = m["max_speed"]
    a = [dyn.available_torque(d, f * w) for f in (0.0, 0.5, 0.9)]
    print("%-15s %-11s %5.2f  %5.2f  %6.1f   | %6.2f %6.2f %6.2f  N·m" % (
        mid, m["kind"], m["peak_torque"], m["rated_torque"], w, *a))
```

| 종류 | 모델 (`available_torque`) | 장점 | 약점 | 어울리는 곳 |
|---|---|---|---|---|
| RC 서보 `rc_servo` | 정지 토크에서 무부하 속도까지 직선: `peak·(1−ω/ω_max)` | 싸고 배선이 쉬움, 감속기 내장 | 피드백 없음, 분해능 1°급, RMS 여유 작음 | 교육용 탁상 델타 (D08) |
| 스마트 서보 `smart_servo` | RC 서보와 같은 직선 | 엔코더·전류 제어, 버스 연결, 분해능 0.088° | 최고 속도가 낮음(4.8 rad/s) | 연구·교육용 중형 |
| 스테퍼 `stepper` | 풀아웃 곡선을 직선화: 피크 → `torque_at_max_speed` | 오픈루프로 위치 제어, 저렴, 저속 토크 | **토크가 모자라면 조용히 탈조**, 고속 토크 급감 | 느린 정밀 작업, 그리기 (D10) |
| BLDC (QDD) `bldc` | 최고 속도까지 피크 유지(드라이브가 전류 제한) | 백드라이브 가능, 충돌에 강함, 저감속비 | 드라이버·엔코더 설정이 필요 | 협동·연구용 |
| AC 서보 `ac_servo` | 최고 속도까지 피크 유지 | 고속·고분해능(0.0003°), 산업 표준 | 비싸고 무거움, 서보팩 필요 | 산업용 고속 피킹 (D09) |

일체형 서보(RC 서보·Dynamixel)는 감속기가 케이스 안에 있어 카탈로그 값이 이미 **출력축 기준**입니다(`integrated_gear: true`).
그래서 설계에 외부 감속기를 지정해도 무시되고(`design.ratio == 1`), 관성비는 0으로 나옵니다.

:::info AC 서보·BLDC 곡선이 평탄한 이유
실제 서보 모터는 고속에서 역기전력 때문에 쓸 수 있는 토크가 줄어드는 구간이 있습니다.
이 강의의 모델은 드라이브가 최고 속도까지 피크 전류를 유지한다고 **단순화**했습니다. 최고 속도 근처(속도 비 0.8 이상)를 쓰는 설계라면
데이터시트의 속도-토크 곡선으로 다시 확인하세요.
:::

## 같은 일을 시켜 보기 — 구동계 비교

`industrial_picker` 치수(L = 350, l = 800 mm), 페이로드 0.5 kg으로 Adept 사이클(25/305/25 mm)을 3 m/s, 30 m/s²로 한 번 돌리고,
구동계만 바꿔 판정합니다.

```python run
import math
from deltarobot import DeltaDesign, DeltaRobot

def adept_check(d, speed, accel, across=0.305, up=0.025):
    robot = DeltaRobot(d, scene="empty")
    robot.set_speed(speed, accel)
    z = robot.scene.surface_z + 0.02
    robot.move_to(-across / 2, 0, z)
    t0 = robot.time
    robot.arch_to(across / 2, 0, z, height=up, radius=up)
    robot.arch_to(-across / 2, 0, z, height=up, radius=up)
    T = robot.time - t0
    return T, robot.analyze()

base = DeltaDesign.preset("industrial_picker").copy(payload=0.5)   # L=0.35, l=0.8, 0.5 kg
combos = [("rc_servo_mg996r", "none", 1), ("dxl_xh540_w270", "none", 1),
          ("stepper_nema23", "belt", 5), ("bldc_qdd", "planetary", 9),
          ("ac_servo_200w", "planetary", 20), ("ac_servo_400w", "planetary", 20)]
print("구동계                        사이클  피크   RMS   속도  곡선  관성비  판정")
for mot, gb, n in combos:
    d = base.copy(motor=mot, gearbox=gb, gear_ratio=n)
    T, r = adept_check(d, 3.0, 30.0)
    print("%-16s %-9s %2d:1  %.2f s  %5.2f %5.2f %5.2f %5.2f %6.1f   %s" % (
        mot, gb, n, T, r["peak_ratio"], r["rms_ratio"], r["speed_ratio"], min(r["curve_ratio"], 99),
        r["inertia_ratio"], "✔" if r["ok"] else "✖"))

# 관성 정합 감속비 N* = sqrt(J_load / J_rotor)
d = base.copy(motor="ac_servo_400w", gearbox="planetary", gear_ratio=20)
J_load = d.arm_inertia - d.drive_inertia + d.moving_plate_mass * d.upper_arm ** 2 / 3
J_rotor = d.motor_spec["rotor_inertia"]
print("J_load = %.4f kg·m², J_rotor = %.1e kg·m²  ->  N* = %.1f" % (J_load, J_rotor, math.sqrt(J_load / J_rotor)))
```

- 사이클 시간(0.60 s)은 모두 같습니다. 궤적은 **TCP 속도·가속도 설정**으로 정해지고, 모터는 그 궤적을 "따라갈 수 있는지"만 판정받기 때문입니다.
- RC 서보는 피크 비 20.56 — 필요한 토크가 피크 토크의 약 17배(20.56 / 1.2)입니다. 크기가 맞지 않는 모터입니다.
- XH540(스마트 서보)은 속도 비가 0.90으로 거의 한계인데 곡선 비는 5.18입니다. **빨리 도는 순간 토크가 반 이하로 떨어지는** 직선 특성 때문입니다.
- NEMA23 + 벨트 5:1은 관성비 66.5 — 모터 로터에 비해 부하가 너무 무겁습니다. 오픈루프 스테퍼라면 탈조 위험이 큽니다.
- AC 200 W + 20:1은 통과하지만 RMS 비 0.89로 여유가 작고, AC 400 W + 20:1은 모든 비가 0.5 이하입니다.

## 감속비 고르기

감속비 N을 키우면 모터 쪽 토크는 1/N로 줄고(좋음), 모터 속도는 N배로 늘고(나쁨), 반사 관성은 N²배로 늘어납니다.

@fig[d04-ratio-sweep] AC 400 W + 유성 감속기에서 감속비만 바꿨을 때의 사용률(왼쪽)과 관성비(오른쪽, 로그 축). 점선 세로선은 관성 정합 감속비 N*.

```python run
from deltarobot import DeltaDesign, DeltaRobot

base = DeltaDesign.preset("industrial_picker").copy(payload=0.5, motor="ac_servo_400w", gearbox="planetary")
print(" N   사이클   피크   RMS   속도  관성비  판정")
for n in (5, 10, 15, 20, 30, 50):
    robot = DeltaRobot(base.copy(gear_ratio=n), scene="empty")
    robot.set_speed(3.0, 30.0)
    z = robot.scene.surface_z + 0.02
    robot.move_to(-0.1525, 0, z)
    t0 = robot.time
    robot.arch_to(0.1525, 0, z, height=0.025, radius=0.025)
    robot.arch_to(-0.1525, 0, z, height=0.025, radius=0.025)
    r = robot.analyze()
    print("%2d  %.2f s  %5.2f %5.2f %5.2f %6.1f   %s" % (
        n, robot.time - t0, r["peak_ratio"], r["rms_ratio"], r["speed_ratio"], r["inertia_ratio"],
        "✔" if r["ok"] else "✖ " + "; ".join(p.split(" (")[0].split(":")[0] for p in r["problems"])))
```

### 관성 정합 감속비 N*

부하 관성 $J_load$를 모터(로터 관성 $J_rotor$)로 감속비 N을 거쳐 가속한다고 합시다. 모터 토크 $τ_m$이 주어졌을 때 부하의 각가속도는

$α = N·τ_m / (J_load + N²·J_rotor)$

이고, 이것을 N으로 미분해 0으로 놓으면 $N²·J_rotor = J_load$, 즉 $N* = √(J_load/J_rotor)$ 에서 가속도가 **가장 큽니다**.
이때 관성비(모터축에서 본 부하/로터)는 정확히 1입니다. 위 계산에서 N* = 42.3이 나왔습니다.

그런데 표를 보면 N = 50(관성비 0.7)은 N = 20보다 피크 비가 0.36 → 0.21로 낮아지는 대신 속도 비가 0.16 → 0.41로 커졌습니다. 실제 선택은 N*에서 출발해 다음을 함께 봅니다.

- **중력·정지 토크**: 델타는 팔 무게와 이동판 무게를 항상 들고 있어 순수 관성 부하가 아닙니다(N*는 관성만 고려).
- **속도 여유**: N이 크면 모터가 빨리 돌아야 합니다. 더 빠른 사이클로 올릴 여지를 남기려면 속도 비를 0.5 이하로.
- **관성비 경험칙**: 서보를 쉽게 튜닝하려면 관성비를 대략 10 이하(고응답이면 더 작게)로 두는 것이 흔한 경험칙입니다.
- **카탈로그 감속비**: 유성 `[3, 5, 6, 9, 10, 15, 20, 30, 50]`처럼 정해진 값 중에서 골라야 합니다(없는 값은 `ValueError`).
- **백래시·효율·가격**: 단수가 늘면 효율이 떨어지고 백래시가 쌓입니다.

이 예에서는 N = 20(관성비 4.5, 속도 비 0.16, 모든 비 0.5 이하)이 균형이 좋습니다. D09에서 이 조합을 씁니다.

## 감속기 종류 — 효율과 백래시

| id | 이름 | 감속비 | 효율 η | 백래시 [arcmin] | 반사 관성(모터축) | 비고 |
|---|---|---|---|---|---|---|
| `none` | 직결 | 1 | 1.0 | 0 | 0 | 일체형 서보, QDD 실험 |
| `belt` | 타이밍 벨트 | 2~5 | 0.95 | 6 | 5e-6 | 싸고 조용함, 벨트 장력 관리 |
| `planetary` | 유성 | 3~50 | 0.90 | 10 | 1e-5 | 산업용 델타의 표준 |
| `cycloidal` | 사이클로이드 | 11, 29, 59 | 0.85 | 1 | 2e-5 | 충격에 강함, 무거움 |
| `harmonic` | 하모닉 드라이브 | 30~100 | 0.75 | 0.5 | 1.5e-5 | 백래시 최소, 고감속 |

(카탈로그 대표값) 효율은 모터 쪽 토크를 $1/η$ 만큼 키웁니다. 하모닉(η = 0.75)은 같은 감속비의 유성(0.90)보다 모터가 20 % 더 힘을 내야 합니다.
백래시는 TCP에서 **야코비안 배율**로 커져 보이며(D10에서 계산), 토크 방향이 바뀌는 순간(가속 → 감속, 중력과 반대 방향 힘)에 드러납니다.

:::design 모터·감속기 선정 절차
1. D02의 요구와 D03의 치수로 **대표 동작**(Adept 또는 실제 작업)을 정한다.
2. 후보 구동계마다 `robot.analyze()` — 피크·RMS·속도·곡선 비가 모두 1 이하인 것만 남긴다.
3. 남은 후보 중 **관성비 ≤ 10**, **속도 비 ≤ 0.5**(향후 증속 여유), 가장 큰 비 ≤ 0.7 정도를 목표로 고른다.
4. 정밀도 요구가 있으면 분해능·백래시를 J로 환산해 확인한다 (D10).
5. 질량·가격·전원·제어 방식(버스/펄스)을 비교해 최종 결정하고, 근거 숫자를 보고서에 남긴다.
:::

## 자주 나는 오류와 해결

| 증상·메시지 | 원인 | 해결 |
|---|---|---|
| `ValueError: 설계 오류: planetary 의 감속비는 [3, 5, 6, 9, 10, 15, 20, 30, 50] 중에서 고르세요` | 카탈로그에 없는 감속비 | 목록의 값 중에서 선택 |
| 감속기를 바꿨는데 결과가 그대로 | 일체형 서보(RC·Dynamixel)는 외부 감속기를 무시 | `design.ratio`로 실제 감속비 확인 |
| 문제 목록에 `피크 토크 초과 (안전율 1.2 포함)` | 가장 센 순간의 토크 부족 | 감속비↑, 더 큰 모터, 가속도↓, 이동 질량↓ |
| `RMS(연속) 토크가 정격을 넘습니다 — 과열 위험` | 평균적으로 계속 센 일을 함 | 대기 시간 확보, 더 큰 모터, 경로·프로파일 개선(D06) |
| `속도-토크 곡선 초과: 해당 속도에서 낼 수 있는 토크보다 큰 토크가 필요합니다` | 고속 구간에서 토크 부족(서보 직선·스테퍼 풀아웃) | 감속비 조정, 최고 속도 제한, 모터 종류 변경 |
| `모터 최고 속도 초과` / `경고: 관절 속도 ... set_speed()로 속도를 낮추세요` | 감속비가 너무 크거나 TCP 속도가 너무 빠름 | 감속비↓ 또는 `set_speed()`↓ |
| 관성비가 수십~수백 | 로터가 너무 가볍거나 감속비가 너무 작음 | N을 N* 쪽으로, 로터 관성이 큰 모터 |
