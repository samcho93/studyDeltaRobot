## 학습 목표

- 책상 위 사탕 분류 로봇의 요구사항을 **수치 표**로 만들고, 시뮬레이터 설계 탭과 Python 분석으로 한 항목씩 판정할 수 있습니다.
- 1차 설계안이 **불합격**하는 이유를 숫자로 찾고, 치수·속도를 고쳐 **합격** 설계에 도달하는 반복 과정을 기록할 수 있습니다.
- 카탈로그 id로 부품표(BOM)를 만들고, 분류 장면에서 실제로 동작하는 Python 프로그램을 완성할 수 있습니다.

## 과제 소개

과학 축제 부스에 놓을 **사탕 분류 델타**를 만듭니다. 쟁반 위의 사탕(빨강·파랑·초록)을 흡착컵으로 집어 같은 색 상자에 넣습니다.
예산이 작아 모터는 **RC 서보(MG996R급)** 3개, 구조물은 **3D 프린팅**입니다. 시뮬레이터의 분류 장면(`pick_place`)이 이 부스를 대신합니다.

## 1단계 — 요구사항 표

| 항목 | 요구 | 근거 |
|---|---|---|
| 페이로드 | 10 g (사탕 1개) | 포장 사탕 최대 질량 |
| 작업 실린더 | **D ≥ 200 mm, H ≥ 40 mm** | 쟁반(지름 약 120 mm) + 상자 3개를 한 원 안에 배치, 아치 30 mm + 상자 높이 |
| 사이클 | **30 개/분 이상** (한 개 2.0 s 이내) | 관람객 대기 시간 |
| 정밀도 | TCP 분해능(최악) **≤ 5 mm** | 흡착컵 Ø20이 사탕 윗면(약 15 mm)을 덮는 허용 오차 |
| 툴 | 흡착컵 `suction_20` | 포장지 윗면이 평평, 색과 무관하게 집기 |
| 구동 | RC 서보 `rc_servo_mg996r` × 3, 직결 | 예산. 피드백 없음, 분해능 약 1°(대표값) |
| 모터 검증 | 피크·RMS·속도·곡선 비 모두 ≤ 1 (안전율 1.2) | `robot.analyze()` |

:::info RC 서보의 한계를 요구사항에 반영하기
MG996R급 서보는 위치 피드백을 밖으로 주지 않고, 데드밴드 때문에 1° 정도 이하의 움직임은 잘 따라오지 못합니다(카탈로그 `resolution_deg: 1.0`, 대표값).
그래서 정밀도 요구를 **±5 mm 수준**으로 잡았습니다. 이보다 정밀해야 하면 스마트 서보(0.088°)로 바꿔야 합니다 — 아래 과제 2.
:::

## 2단계 — 설계 반복 (v0 → v1 → 최종)

### v0: 더 작고 싸게 (불합격)

"책상 위니까 작을수록 좋다"는 생각으로 `edu_servo`보다 작게, 팔을 모두 PLA로 뽑는 안을 먼저 검토합니다.
R = 70, r = 30, L = 80, l = 160 mm (l/L = 2.0), 위팔·아래팔 모두 `pla_print`.

### v1: edu_servo 치수 (작업영역 합격)

v0이 작업영역에서 떨어지자 크기를 키웁니다. l/L = 2.2, R − r = 50 mm인 `edu_servo` 치수(R = 80, r = 30, L = 100, l = 220 mm)로,
아래팔은 강성을 위해 알루미늄 튜브(`al_tube`)로 바꿉니다.

### 판정 스크립트

두 안의 작업 실린더와 분해능을 보고, v1으로 분류 동작을 세 가지 속도로 돌려 사이클과 모터를 판정합니다.

```python run
import math, itertools
from deltarobot import DeltaDesign, DeltaRobot
from deltarobot import kinematics as kin

REQ = {"D": 0.200, "H": 0.040, "cpm": 30, "res": 0.005}    # 사탕 분류 요구사항

def tcp_resolution(d, p):
    dth = math.radians(d.motor_spec["resolution_deg"]) / d.ratio
    J = kin.jacobian(d, kin.ik(d, p), p)
    return max(math.sqrt(sum(sum(J[r][c] * s[c] * dth for c in range(3)) ** 2 for r in range(3)))
               for s in itertools.product((-1, 1), repeat=3))

def geometry_check(name, d):
    c = kin.work_cylinder(d, REQ["H"])
    zc, rc = (c["z_top"] + c["z_bottom"]) / 2, c["diameter"] / 2
    pts = [(0.0, 0.0, zc)] + [(0.9 * rc * math.cos(a), 0.9 * rc * math.sin(a), zc)
                              for a in (0, math.pi / 3, 2 * math.pi / 3, math.pi)]
    res = max(tcp_resolution(d, p) for p in pts)
    print("%s: D x H = %.0f x %.0f mm (요구 %.0f x %.0f) %s | TCP 분해능 최악 %.1f mm (요구 %.0f) %s" % (
        name, c["diameter"] * 1000, c["height"] * 1000, REQ["D"] * 1000, REQ["H"] * 1000,
        "✔" if c["diameter"] >= REQ["D"] else "✖", res * 1000, REQ["res"] * 1000,
        "✔" if res <= REQ["res"] else "✖"))

def sort_run(d, speed=None, accel=None):
    robot = DeltaRobot(d, scene="pick_place")
    if speed:
        robot.set_speed(speed, accel)
    robot.home()
    bins = {b["color"]: b for b in robot.bins()}
    t0 = robot.time
    parts = robot.parts()
    for p in parts:
        robot.arch_to(p["x"], p["y"], p["top"], height=0.03)
        robot.tool_on()
        robot.wait(0.2)
        b = bins[p["color"]]
        robot.arch_to(b["x"], b["y"], robot.scene.surface_z + b["h"] + 0.015, height=0.03)
        robot.tool_off()
        robot.wait(0.1)
    cpm = 60 * len(parts) / (robot.time - t0)
    r = robot.analyze()
    print("  속도 %.2f m/s, 가속도 %.1f m/s^2: %.1f 개/분 %s | 피크 %.2f RMS %.2f 속도 %.2f %s" % (
        robot.speed, robot.accel, cpm, "✔" if cpm >= REQ["cpm"] else "✖",
        r["peak_ratio"], r["rms_ratio"], r["speed_ratio"], "✔" if r["ok"] else "✖ " + r["problems"][-1]))

base = DeltaDesign.preset("edu_servo").copy(payload=0.010, tool="suction_20")
v0 = base.copy(base_radius=0.07, effector_radius=0.03, upper_arm=0.08, forearm=0.16,
               upper_arm_material="pla_print", forearm_material="pla_print")
geometry_check("v0", v0)
geometry_check("v1", base)
print("v1 분류 속도 시험")
sort_run(base)                 # 기본 속도
sort_run(base, 0.6, 6.0)       # 욕심낸 속도
sort_run(base, 0.3, 3.0)       # 최종
```

```text

v1: D x H = 248 x 40 mm (요구 200 x 40) ✔ | TCP 분해능 최악 3.9 mm (요구 5) ✔
v1 분류 속도 시험
  속도 0.19 m/s, 가속도 1.9 m/s^2: 24.0 개/분 ✖ | 피크 0.22 RMS 0.41 속도 0.35 ✔
경고: 관절 속도 6.23 rad/s 가 모터 한계 6.00 rad/s(감속 후)를 넘습니다 — set_speed()로 속도를 낮추세요
  속도 0.60 m/s, 가속도 6.0 m/s^2: 47.7 개/분 ✔ | 피크 0.47 RMS 0.52 속도 1.01 ✖ 모터 최고 속도 초과
  속도 0.30 m/s, 가속도 3.0 m/s^2: 33.0 개/분 ✔ | 피크 0.24 RMS 0.42 속도 0.56 ✔
```

### 반복 기록

| 안 | 바꾼 것 | D × H [mm] | 사이클 [개/분] | 피크 / RMS / 속도 비 | 판정 | 원인과 조치 |
|---|---|---|---|---|---|---|
| v0 | R70 r30 L80 l160, 전부 PLA | 180 × 42 | — | — | ✖ | 작업영역 부족 → 크기를 키움 |
| v1-a | edu_servo 치수, 기본 속도 0.19 m/s | 248 × 40 | 24.0 | 0.22 / 0.41 / 0.35 | ✖ | 모터 여유는 큰데 느림 → 속도↑ |
| v1-b | 0.6 m/s, 6 m/s² | 248 × 40 | 47.7 | 0.47 / 0.52 / **1.01** | ✖ | 서보 최고 속도(6 rad/s) 초과 + 속도-토크 곡선 초과 → 속도↓ |
| **최종** | 0.3 m/s, 3 m/s² | 248 × 40 | **33.0** | 0.24 / 0.42 / 0.56 | ✔ | 사이클 10 % 여유, 속도 비 0.56 |

- v0의 분해능(3.0 mm)이 v1(3.9 mm)보다 좋은 것은 팔이 짧아 야코비안이 작기 때문입니다. **작은 로봇 = 정밀하지만 좁다.**
- RC 서보에서 가장 먼저 막히는 것은 토크가 아니라 **속도**(6 rad/s)와 **RMS**(정격 0.35 N·m가 피크 1.08 N·m의 1/3)입니다.
- 최종안의 RMS 비 0.42는 흡착 대기(0.2 s)와 놓기 대기(0.1 s) 동안에도 팔 무게를 들고 있는 토크가 포함된 값입니다.

:::design 시뮬레이터로 같은 과정 밟기
1. **설계** 탭: 프리셋 `edu_servo` → 페이로드 0.01 kg, 툴 `suction_20`. R·r·L·l 슬라이더를 v0 값으로 바꾸고 재질을 `pla_print`로 → **[설계 검증]** 의 D×H 확인.
2. 슬라이더를 `edu_servo` 값으로 되돌리고 아래팔 재질 `al_tube` → 다시 [설계 검증].
3. **작업** 탭: 장면 "분류", 데모 "분류 데모", 궤적 설정 속도 0.6 m/s·가속도 6 m/s² → 재생 → **분석** 탭 ω 그래프가 한계선을 넘는 순간 확인.
4. 속도 0.3 m/s·가속도 3 m/s²로 바꿔 다시 재생 → 검증 결과 ✔, 분당 사이클 확인.
5. **연결** 탭에서 설계 JSON을 내보내 보고서에 첨부합니다.
:::

파생값(`deltarobot.design.summary(design)`, 최종 설계): 위팔 질량 32.0 g(허브 포함), 아래팔 한 쌍 56.9 g(볼 컵 포함),
**이동판 질량 165.4 g — 페이로드(10 g)의 16.5배**, 팔 관성 약 5.5×10⁻⁴ kg·m², 위팔 수평 자세 정적 토크(팔 자중) 0.057 N·m, 모터 3개 165 g.
사탕보다 **로봇 자신의 이동 질량**이 토크를 좌우한다는 것이 탁상형 델타의 특징입니다.

## 4단계 — 응용 프로그램: 색깔별 사탕 분류

최종 설계로 분류 장면의 사탕 6개를 색깔별 상자에 넣습니다. 흡착 실패를 확인하고, 상자가 없는 색은 건너뜁니다.

```python run
from deltarobot import DeltaDesign, DeltaRobot

# D08 최종 설계: edu_servo 치수 + MG996R 직결 + 흡착컵 Ø20, 사탕 10 g
design = DeltaDesign.preset("edu_servo").copy(payload=0.010, tool="suction_20")
robot = DeltaRobot(design, scene="pick_place")
robot.set_speed(0.3, 3.0)             # 설계 검증에서 정한 속도·가속도
ARCH = 0.03                           # 아치 높이 [m]
VACUUM = 0.2                          # 흡착 압력이 차오르는 시간 [s]

bins = {b["color"]: b for b in robot.bins()}
drop_z = robot.scene.surface_z + bins["red"]["h"] + 0.015     # 상자 위 15 mm 에서 놓기

robot.home()
t0 = robot.time
for p in sorted(robot.parts(), key=lambda q: q["color"]):      # 색깔별로 모아서
    b = bins.get(p["color"])
    if b is None:
        print("%s: %s 상자가 없어 건너뜀" % (p["id"], p["color"]))
        continue
    robot.arch_to(p["x"], p["y"], p["top"], height=ARCH)
    got = robot.tool_on()
    robot.wait(VACUUM)
    if got is None:
        print("%s: 흡착 실패 — 위치를 확인하세요" % p["id"])
        robot.tool_off()
        continue
    robot.arch_to(b["x"], b["y"], drop_z, height=ARCH)
    robot.tool_off()
    robot.wait(0.1)
    print("%5.2f s  %s (%s) -> 상자 %s" % (robot.time, p["id"], p["color"], b["id"]))
robot.home()

n = robot.scene.score()
print("분류 결과:", n)
print("평균 %.1f 개/분" % (60 * n["total"] / (robot.time - t0)))
res = robot.analyze()
print("피크 %.2f  RMS %.2f  속도 %.2f  속도-토크 %.2f  ->  %s" % (
    res["peak_ratio"], res["rms_ratio"], res["speed_ratio"], res["curve_ratio"],
    "통과" if res["ok"] else res["problems"]))
```

마지막 홈 복귀까지 포함해도 평균 32.2 개/분으로 요구(30 개/분)를 넘고, 6개 모두 맞는 상자에 들어갔습니다.
분류 장면의 부품 크기·상자 위치는 설계의 작업 실린더에 맞춰 자동으로 배치되므로(`default_scene`), 설계를 바꾸면 좌표를 하드코딩하지 말고
항상 `robot.parts()`·`robot.bins()`에서 읽어야 합니다.

:::tip URDF로 조립 확인
`tools/urdf-viewer.html`은 시뮬레이터의 마지막 설계를 불러옵니다. 최종 설계로 URDF 뷰어를 열어 θ 슬라이더를 움직여 보고,
위팔이 서보 혼에서 얼마나 돌아야 하는지(모터각 한계 −40° ~ 86°)를 3D 프린팅 부품 설계에 반영하세요. URDF는 D07에서 자세히 다룹니다.
:::

## 과제

1. 최종 설계에서 사탕 순서를 "가까운 것부터"(현재 위치에서 가장 가까운 부품)로 바꾸는 탐욕 알고리즘을 구현하고, 개/분이 얼마나 늘어나는지 측정하세요.
