## 학습 목표

- "빠르고 정확한 로봇"처럼 막연한 바람을 **페이로드·작업 실린더(D×H)·사이클·정밀도** 네 가지 수치 요구사항으로 바꿀 수 있습니다.
- 업계 표준 벤치마크인 **Adept 사이클**(25 mm 상승 → 305 mm 이동 → 25 mm 하강 → 복귀)을 설명하고, 작은 로봇에 맞게 축소해 쓸 수 있습니다.
- 요구사항 표를 만들고, 시뮬레이터 **[설계 검증]** 과 Python 스크립트로 설계안이 요구를 만족하는지 ✔/✖ 로 판정할 수 있습니다.

## 요구사항은 숫자여야 한다

설계는 "무엇을 만족해야 하는가"가 정해져야 시작할 수 있습니다. 요구가 "적당히 빠르게"면 어떤 설계도 통과할 수 없고
어떤 설계도 떨어뜨릴 수 없습니다. 델타로봇은 거의 항상 아래 네 가지로 요구를 정리합니다.

| 요구 | 기호·단위 | 무엇으로 검증하나 | 관련 챕터 |
|---|---|---|---|
| 페이로드 | m [kg] | 모터 토크(피크·RMS), 툴 유지력 | T08, D04, D05 |
| 작업 영역 | 작업 실린더 D × H [mm] | `kinematics.work_cylinder(d, H)` | T07, D03 |
| 속도 | 사이클/분 (Adept 사이클) | 기록한 동작의 시간, `robot.analyze()` | D04, D06 |
| 정밀도 | 분해능·반복정밀도 [mm] | 야코비안 × 모터 분해능, 백래시 | T06, D10 |

여기에 **환경**(책상 위/라인 설치, 전원 종류), **예산**(모터 종류가 거의 결정됨), **안전**(속도 제한, 비상정지)을 덧붙입니다.

:::info 페이로드와 이동판 질량은 다릅니다
요구사항의 페이로드는 **옮길 물건의 질량**입니다. 모터가 실제로 움직이는 것은 이펙터 판 + 툴 + 페이로드 + 아래팔 절반을 합친
**이동판 질량**(`design.moving_plate_mass`)입니다. 10 g짜리 사탕을 옮기는 `edu_servo`도 이동판은 약 165 g으로 페이로드의 16배가 넘습니다 — D08에서 직접 확인합니다.
:::

## Adept 사이클 — 속도 요구의 공통 언어

"분당 몇 번"은 **어떤 동작을** 반복하느냐에 따라 달라집니다. 그래서 스카라·델타 로봇 업계는 오래전부터
**Adept 사이클**을 공통 벤치마크로 씁니다(Adept Technology가 제품 사양 비교에 쓰던 동작이라 이 이름이 붙었습니다).

1. 집는 점에서 **25 mm 수직 상승**
2. **305 mm(12인치) 수평 이동**
3. **25 mm 수직 하강** — 놓는 점
4. 같은 경로로 **되돌아오기** — 여기까지가 **1 사이클**

@fig[d02-adept-cycle] 위: `trajectory.arch_path`로 만든 Adept 경로(모서리는 반지름 = 높이/2로 둥글림). 아래: 같은 경로를 `industrial_picker` 기본 속도·가속도와 S-커브로 왕복할 때의 TCP 속도. 이 설정이면 1 사이클이 1.43 s(약 42 사이클/분)입니다.

제조사 카탈로그의 "사이클/분" 값은 보통 이 동작을 정해진 페이로드로 반복한 결과이고, 모서리를 얼마나 둥글리는지, 정지 대기(dwell)를 넣는지는
회사마다 조금씩 다릅니다. 그래서 **비교할 때는 조건(페이로드·경로·대기 시간)을 같이 적는 것**이 원칙입니다.

:::design 작은 로봇은 축소 Adept 사이클
`edu_servo`의 작업 실린더 지름은 약 224 mm(H = 80 mm)라 305 mm를 한 번에 갈 수 없습니다.
이럴 때는 수평 거리를 작업 실린더 지름의 70~80 % 정도로 줄인 **축소 사이클**을 쓰고, 요구사항 표에 그 거리를 반드시 적습니다
(예: "25/150/25 mm 축소 Adept, 40 사이클/분").
:::

## 말로 된 요구를 수치로 바꾸기

| 고객의 말 | 수치 요구 | 계산 근거 |
|---|---|---|
| "사탕을 분당 30개 분류" | 30 사이클/분 → 한 개당 2.0 s 이내 | 60 / 30 |
| "흡착 0.2 s는 기다려야 해요" | 움직임 예산 = 2.0 − 0.2 − 0.1(놓기) = 1.7 s | 정지 대기는 사이클에서 뺀다 |
| "A5 종이 전체에 그리기" | D ≥ 257 mm (종이 대각선) | √(210² + 148²) ≈ 257 |
| "컨베이어 폭 200 mm + 상자 두 개" | D ≥ 컨베이어·상자를 모두 덮는 원 | 평면 배치도를 먼저 그린다 (D09) |
| "부품 높이 30 mm, 아치 25 mm" | H ≥ 30 + 25 + 여유 | 수직 이동 범위 |
| "구멍에 핀을 꽂는다 (공차 ±0.5 mm)" | TCP 분해능·백래시 합 ≤ 0.5 mm | D10의 J·Δθ 계산 |
| "무거운 박스도 가끔" | 페이로드 = **가장 무거운 경우** | 평균이 아니라 최대 |

여유(safety margin)도 요구사항에 포함합니다. 이 강의의 검증 함수(`robot.analyze()`)는 토크에 **안전율 1.2**를 기본으로 곱하고,
스테퍼에는 탈조를 막기 위해 가용 토크를 1.5로 한 번 더 나눕니다(`dynamics.STEPPER_MARGIN`).

:::tip 요구사항 표는 한 페이지로
요구사항 표는 설계가 끝날 때까지 바뀌지 않는 **계약서**입니다. 설계 도중 요구를 슬쩍 낮추고 싶어지면 표를 고치는 대신
"요구 변경 기록"에 이유와 함께 남기세요 (D11 보고서 양식).
:::

## 실습 (Python) — 요구사항 판정 스크립트

아래 스크립트는 요구사항 딕셔너리 `REQ`를 받아 다섯 항목을 ✔/✖ 로 판정합니다. `adept_cycle()`은 축소 Adept 사이클 한 번의 시간을,
`tcp_resolution()`은 세 모터가 모두 분해능 1칸씩 틀렸을 때 TCP가 얼마나 움직이는지($δ p = J·δθ$)를 계산합니다.

```python run
import math, itertools
from deltarobot import DeltaDesign, DeltaRobot
from deltarobot import kinematics as kin

def adept_cycle(robot, across=0.305, up=0.025):
    """Adept 사이클 1회(25 mm 상승 → across 이동 → 25 mm 하강 → 되돌아오기) 시간 [s]"""
    z = robot.scene.surface_z + 0.02
    robot.move_to(-across / 2, 0, z)
    t0 = robot.time
    robot.arch_to(across / 2, 0, z, height=up)
    robot.arch_to(-across / 2, 0, z, height=up)
    return robot.time - t0

def tcp_resolution(d, p):
    """모든 모터가 분해능 1칸씩 틀릴 때 TCP 최악 오차 [m]"""
    dth = math.radians(d.motor_spec["resolution_deg"]) / d.ratio
    J = kin.jacobian(d, kin.ik(d, p), p)
    return max(math.sqrt(sum(sum(J[r][c] * s[c] * dth for c in range(3)) ** 2 for r in range(3)))
               for s in itertools.product((-1, 1), repeat=3))

def check(design, req):
    d = design.copy(payload=req["payload"])
    c = kin.work_cylinder(d, req["H"])
    robot = DeltaRobot(d, scene="empty")
    T = adept_cycle(robot, req["across"])
    res = robot.analyze()
    zc = (c["z_top"] + c["z_bottom"]) / 2
    acc = tcp_resolution(d, (0.0, 0.0, zc))
    rows = [("작업 실린더 D [mm]", c["diameter"] * 1000, ">=", req["D"] * 1000),
            ("사이클 [회/분]", 60 / T, ">=", req["cpm"]),
            ("TCP 분해능 [mm]", acc * 1000, "<=", req["res"] * 1000),
            ("모터 검증 (피크 비)", res["peak_ratio"], "<=", 1.0),
            ("모터 검증 (RMS 비)", res["rms_ratio"], "<=", 1.0)]
    for name, val, op, lim in rows:
        ok = val >= lim if op == ">=" else val <= lim
        print("  %-18s %8.2f  (요구 %s %g)  %s" % (name, val, op, lim, "✔" if ok else "✖"))

REQ = {"payload": 0.2, "D": 0.25, "H": 0.08, "across": 0.20, "cpm": 25, "res": 0.0005}
print("edu_dynamixel, 요구:", REQ)
check(DeltaDesign.preset("edu_dynamixel"), REQ)
```

```text
edu_dynamixel, 요구: {'payload': 0.2, 'D': 0.25, 'H': 0.08, 'across': 0.2, 'cpm': 25, 'res': 0.0005}
  작업 실린더 D [mm]        338.77  (요구 >= 250)  ✔
  사이클 [회/분]             25.93  (요구 >= 25)  ✔
  TCP 분해능 [mm]           0.39  (요구 <= 0.5)  ✔
  모터 검증 (피크 비)           0.18  (요구 <= 1)  ✔
  모터 검증 (RMS 비)          0.26  (요구 <= 1)  ✔
```

`edu_dynamixel`은 이 요구를 모두 만족합니다. 그런데 모터 검증 비가 0.18·0.26으로 **여유가 매우 큰 반면** 사이클은 25.93으로 겨우 통과합니다.
사이클이 느린 원인은 모터가 아니라 **기본 속도 설정**(`speed = 0.25·(L+l)/0.43` m/s)이라는 뜻입니다 — 속도를 올릴 여지가 있습니다.
이렇게 판정표는 "통과/불합격"뿐 아니라 **어디에 여유가 있고 어디가 병목인지**를 보여 줍니다.

:::check 스스로 확인
- 요구 `REQ["cpm"]`을 40으로 올리면 어떤 항목이 ✖ 가 되나요? `DeltaRobot` 생성 직후 `robot.set_speed(0.5, 5.0)`을 넣으면 다시 ✔ 가 되나요?
- `REQ["res"]`를 0.0002(0.2 mm)로 조이면 XM430(분해능 0.088°)으로 만족할 수 있나요? 만족하지 못한다면 무엇을 바꿔야 할까요?
- 페이로드를 0.5 kg으로 올렸을 때 피크 비와 RMS 비 중 어느 쪽이 먼저 한계에 가까워지나요?
:::

## 자주 나는 오류와 해결

| 증상·메시지 | 원인 | 해결 |
|---|---|---|
| `WorkspaceError: 작업영역 밖: (0.300, 0.000, -0.300) m — 팔 길이로 닿지 않음` | Adept 305 mm를 작은 로봇에 그대로 적용 | 축소 사이클(작업 실린더 D의 70~80 %)을 쓰고 거리를 표에 적기 |
| `WorkspaceError: 경로 중간 작업영역 밖: ... — 모터 각도 한계` | 아치 높이가 커서 궤적 꼭대기가 작업영역 위로 나감 | 아치 높이를 작업 실린더 H 안으로, 또는 z를 더 낮게 |
| 사이클은 느린데 모터 비는 0.2 수준 | 기본 속도·가속도가 보수적 | `set_speed()`로 올려 보고 다시 판정 |
| 사이클 수치가 카탈로그와 크게 다름 | 대기 시간·경로·페이로드 조건이 다름 | 비교할 때 조건을 같이 적기 |
| `ValueError: 설계 오류: ...` | `copy()`에 잘못된 값(예: r ≥ R, 없는 감속비) | 메시지의 항목을 고친 뒤 다시 실행 |

## 과제

1. 여러분 주변의 "옮기는 작업"(급식 배식, 약 포장, 택배 분류 등) 하나를 골라 요구사항 표(페이로드·D×H·사이클·정밀도·환경·예산)를 작성하세요. 각 숫자에 근거를 한 줄씩 붙입니다.
2. `check()`를 `industrial_picker`와 `REQ = {"payload": 1.0, "D": 0.6, "H": 0.2, "across": 0.305, "cpm": 40, "res": 0.0005}`로 실행하고 결과를 해석하세요.
3. 판정표에 "관성비 ≤ 10" 항목을 추가하세요(`res["inertia_ratio"]`). 일체형 서보는 왜 0이 나오는지 D04를 읽고 설명하세요.
