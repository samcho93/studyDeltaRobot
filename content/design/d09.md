## 학습 목표

- 컨베이어 피킹 셀의 요구사항(0.5 kg, 60 사이클/분)을 셀 배치도와 함께 수치로 정리할 수 있습니다.
- AC 서보·유성 감속기·흡착컵 조합을 **모터 검증 + 유지력 + 실제 작업 사이클**의 세 관점에서 판정하고, 불합격 원인을 하나씩 제거할 수 있습니다.
- 컨베이어 속도로 **집는 순간의 부품 위치를 예측**하는 추적 피킹 프로그램을 작성할 수 있습니다.

## 과제 소개

과자 봉지(최대 0.5 kg)가 컨베이어를 따라 **1초에 하나씩** 들어옵니다. 델타로봇이 봉지를 흡착해 색(빨강·파랑)별 상자 두 곳에 넣습니다.
놓치거나 흘려보내는 봉지가 없어야 하고, 라인은 하루 종일 돌아갑니다(→ RMS 토크가 중요). 구동은 산업 표준인 **AC 서보 + 유성 감속기**입니다.

## 1단계 — 요구사항 표와 셀 배치

| 항목 | 요구 | 근거 |
|---|---|---|
| 페이로드 | 0.5 kg | 가장 무거운 제품 |
| 작업 실린더 | **D ≥ 800 mm, H ≥ 100 mm** | 컨베이어(폭 약 200 mm)의 집기 구간 + 상자 2개가 한 원 안에, 부품 높이 + 아치 |
| 공급 속도 | 1 s마다 1개 = **60 사이클/분** | 라인 속도 |
| 로봇 사이클 | 집기 → 놓기 → 다음 집기 평균 **≤ 1.0 s** (60 사이클/분 이상) | 공급보다 빨라야 밀리지 않음 |
| 집기 성공 | 놓침 0, 흘려보냄 0 (30개 연속) | |
| 유지력 | 카탈로그 흡착력 ≥ m · max\|a − g\| · **SF 2** | 고속 수평 이동 (D05) |
| 구동 | AC 서보 + 유성 감속기, **관성비 ≤ 10** | 서보 튜닝 여유 |
| 모터 검증 | 피크·RMS·속도·곡선 비 ≤ 1 (안전율 1.2) | 연속 운전 |

:::info Adept 사이클과 이 셀의 사이클
업계 사양의 "사이클/분"은 D02의 Adept 사이클(25/305/25 mm)로 잽니다. D04에서 AC 400 W + 유성 20:1, 3 m/s·30 m/s²로 Adept 사이클 한 번이 0.60 s(100 사이클/분)였습니다.
실제 셀은 컨베이어 → 상자 거리가 305 mm보다 길고, 흡착·해제 대기와 추적 계산이 들어가므로 **현장 작업으로 다시 재야** 합니다.
이 장에서는 아치 높이 25 mm는 Adept와 같게 두고, 수평 거리는 셀 배치가 정하는 "현장판 Adept 사이클"을 씁니다.
:::

셀 배치는 `default_scene(design, "conveyor")`가 설계의 작업 실린더에 맞춰 만듭니다. 이 설계에서 컨베이어는 y = −197 mm(폭 197 mm),
x = −570 ~ +570 mm, 속도 87.8 mm/s이고, 상자 A(빨강)·B(파랑)는 y = +219 mm, x = ∓154 mm에 있습니다. 기본 장면은 부품이 2초마다 들어오므로
프로그램에서 **1초 간격으로 바꿔** 60 사이클/분 공급을 만듭니다(장면은 dict이므로 `spawn`의 시각만 고치면 됩니다).

@fig[d09-cell-layout] 최종 설계의 셀 평면도. 초록 실선은 부품 윗면 높이에서 실제로 도달 가능한 경계, 점은 아래 프로그램이 부품을 실제로 집은 위치(예측한 x)입니다.

## 2단계 — 응용 프로그램: 컨베이어 추적 피킹

컨베이어 위 부품은 계속 움직이므로, 로봇이 도착할 때 부품이 **어디에 있을지** 예측해서 그 점으로 가야 합니다.

$x_pick = x_now + v_conv · T(x_pick)$

도착 시간 T는 목표 위치에 따라 달라지므로 식이 자기 자신을 참조합니다. **반복 대입**으로 풉니다: 현재 x로 T를 계산 → x를 갱신 → 다시 T … (3번이면 충분히 수렴).
T는 움직이기 **전에** `trajectory.arch_path()`와 `trajectory.Profile(...).T`로 계산할 수 있습니다 — 로봇이 쓰는 것과 똑같은 궤적 계산이기 때문입니다.

맨 위 설정 블록만 바꾸면 2단계의 모든 설계안을 같은 프로그램으로 판정할 수 있습니다.

```python run
import math
from deltarobot import DeltaDesign, DeltaRobot, default_scene
from deltarobot import trajectory as traj
from deltarobot import dynamics as dyn

# ---- 설계 반복 때 바꾸는 값 ------------------------------------------
MOTOR, RATIO, TOOL = "ac_servo_400w", 20, "suction_40"
SPEED, ACCEL = 3.0, 30.0          # TCP 속도 [m/s], 가속도 [m/s^2]
H, RAD = 0.025, 0.025             # 아치 높이, 모서리 반지름 [m]
DWELL = 0.05                      # 흡착·해제 확인 시간 [s]
# ----------------------------------------------------------------------

design = DeltaDesign.preset("industrial_picker").copy(
    motor=MOTOR, gearbox="planetary", gear_ratio=RATIO, tool=TOOL, payload=0.5)

# 기본 컨베이어 장면은 2 s마다 부품 1개(30개/분) -> 1 s 간격(60개/분)으로 바꾼다
scene = default_scene(design, "conveyor")
for n, s in enumerate(scene["conveyor"]["spawn"]):
    s["t"] = 1.0 + 1.0 * n

robot = DeltaRobot(design, scene=scene)
robot.set_speed(SPEED, ACCEL)
conv = robot.scene.conveyor()
v = conv["speed"]                                   # 컨베이어 속도 [m/s]
bins = {b["color"]: b for b in robot.bins()}
place_z = robot.scene.surface_z + bins["red"]["h"] + 0.02

def move_time(p0, p1):
    """아치 궤적 하나에 걸리는 시간 — 움직이기 전에 계산"""
    path = traj.arch_path(p0, p1, H, RAD)
    return traj.Profile(robot.profile, path.length, robot.speed, robot.accel).T

def plan_pick(part):
    """도착 시각의 부품 x 를 예측: x = x_now + v * T(x) 를 3번 반복해 수렴"""
    x = part["x"]
    for _ in range(3):
        x = part["x"] + v * move_time(robot.position, (x, part["y"], part["top"]))
    return x

robot.move_to(-0.25, conv["y"], place_z)
picked, missed, busy = 0, 0, 0.0
while robot.time < 36.0:
    target = None
    for part in sorted(robot.parts(), key=lambda p: -p["x"]):   # 가장 하류(앞선) 부품부터
        if part["on"] != "conveyor":
            continue
        x = plan_pick(part)
        if robot.reachable(x, part["y"], part["top"]):
            target = (part, x)
            break
    if target is None:
        robot.wait(0.02)                                          # 부품이 들어올 때까지 대기
        continue
    part, x = target
    t0 = robot.time
    robot.arch_to(x, part["y"], part["top"], height=H, radius=RAD)
    got = robot.tool_on()
    robot.wait(DWELL)
    if got is None:
        missed += 1
        robot.tool_off()
        continue
    b = bins[part["color"]]
    robot.arch_to(b["x"], b["y"], place_z, height=H, radius=RAD)
    robot.tool_off()
    robot.wait(DWELL)
    picked += 1
    busy += robot.time - t0                                       # 집기 -> 놓기 한 사이클

left = [p for p in robot.parts() if p["on"] == "conveyor"]
lost = len(conv["spawn"]) - picked - len(left)
cyc = busy / picked
print("집음 %d, 놓침 %d, 흘려보냄 %d, 평균 사이클 %.3f s -> 최대 %.1f 사이클/분" % (
    picked, missed, lost, cyc, 60 / cyc))
print("분류 결과:", robot.scene.score())
res = robot.analyze()
print("피크 %.2f  RMS %.2f  속도 %.2f  관성비 %.1f  ->  %s" % (
    res["peak_ratio"], res["rms_ratio"], res["speed_ratio"], res["inertia_ratio"],
    "통과" if res["ok"] else res["problems"]))

# 흡착 유지력 (D05): F_req = m * max|a - g| * SF,  SF = 2 (고속 수평 이동)
data = dyn.analyze(robot.design, robot.backend.frames)
worst = max(math.sqrt(f["a"][0] ** 2 + f["a"][1] ** 2 + (f["a"][2] + 9.81) ** 2)
            for f in data if f["tool"] == 1)                      # 부품을 든 동안만
need = design.payload * worst * 2.0
have = design.tool_spec["force"]
print("흡착 유지력: 필요 %.1f N (max|a-g| %.1f m/s^2), 카탈로그 %.1f N -> %s" % (
    need, worst, have, "통과" if have >= need else "부족"))
```

```text
집음 30, 놓침 0, 흘려보냄 0, 평균 사이클 0.909 s -> 최대 66.0 사이클/분
분류 결과: {'per_bin': {'A': 15, 'B': 15}, 'correct': 30, 'total': 30}
피크 0.49  RMS 0.38  속도 0.22  관성비 4.5  ->  통과
흡착 유지력: 필요 59.9 N (max|a-g| 59.9 m/s^2), 카탈로그 75.4 N -> 통과
```

(최종 설계의 결과입니다. 1초 간격 공급 30개를 모두 맞는 상자에 넣었고, 로봇의 평균 사이클 0.909 s는 공급 간격 1.0 s보다 짧습니다.)

:::warning 시뮬레이터의 "잡기"는 순간적입니다
`tool_on()`은 호출한 순간 TCP 아래에 있는 부품을 붙입니다. 실제 흡착은 진공이 차오르는 동안(여기서는 50 ms) **컨베이어와 같은 속도로 따라가야**
부품이 컵 아래에서 미끄러지지 않습니다. 그 동안 부품은 87.8 mm/s × 0.05 s ≈ 4.4 mm 움직입니다. 컨베이어와 동기해 따라가는 트래킹은 R08 캡스톤에서 다룹니다.
:::

## 3단계 — 설계 반복

위 프로그램의 설정 블록만 바꿔 실행한 결과입니다.

| 안 | 설정 (모터 · 감속비 · 툴 · 속도/가속도 · 모서리 반지름) | 사이클/분 | 피크 / RMS / 속도 비 | 관성비 | 유지력 필요 / 카탈로그 | 판정 |
|---|---|---|---|---|---|---|
| v0 | 200 W · 10:1 · `suction_20` · 2 m/s, 20 m/s² · 12.5 mm | **56.2** ✖ | **1.76 / 1.22** / 0.08 ✖ | 32.7 | **58.3 / 18.8 N** ✖ | ✖ |
| v1 | 200 W · 10:1 · `suction_40` · 3 m/s, 30 m/s² · 25 mm | 66.0 ✔ | **1.88 / 1.43** / 0.11 ✖ | 33.3 | 59.9 / 75.4 N ✔ | ✖ |
| v2 | 200 W · **20:1** · `suction_40` · 3 m/s, 30 m/s² · 25 mm | 66.0 ✔ | 0.96 / 0.74 / 0.22 ✔ | 8.3 | 59.9 / 75.4 N ✔ | ✔ (여유 부족) |
| **v3 (최종)** | **400 W** · 20:1 · `suction_40` · 3 m/s, 30 m/s² · 25 mm | 66.0 ✔ | 0.49 / 0.38 / 0.22 ✔ | 4.5 | 59.9 / 75.4 N ✔ | ✔ |
| v3' | v3에서 모서리 반지름만 기본값(12.5 mm) | 65.5 ✔ | 0.65 / 0.42 / 0.22 ✔ | 4.5 | **76.7 / 75.4 N** ✖ | ✖ |

**v0 → v1: 사이클과 툴.** v0은 요구 사이클(60)을 못 채우고(56.2), 모터는 피크·RMS·곡선 비를 모두 넘으며, 흡착컵 Ø20은 필요 유지력의 1/3도 안 됩니다.
속도·가속도를 올리고 아치 모서리를 25 mm로 키워(D06) 사이클 66.0을 얻었고, 툴을 Ø40으로 바꿔 유지력을 해결했습니다.

**v1 → v2: 감속비.** 모터 비는 오히려 더 나빠졌습니다(1.88/1.43). 관성비 33.3이 보여 주듯 10:1에서는 부하가 로터에 비해 너무 무겁습니다.
감속비를 20:1로 올리자 모터 쪽 토크가 절반이 되어 피크 0.96, RMS 0.74로 **간신히** 통과합니다(D04의 N* 논의).

**v2 → v3: 여유.** 피크 비 0.96은 안전율 1.2를 이미 포함한 값이지만, 모델에 없는 마찰·케이블·진공 호스의 저항과 제품 무게 편차를 생각하면 여유가 없습니다.
400 W로 올려 모든 비를 0.5 이하, 관성비 4.5로 만들었습니다. 모터 질량은 0.82 → 1.2 kg(대표값)으로 늘지만 베이스에 고정되므로 이동 질량과는 무관합니다.

**v3': 모서리 반지름의 힘.** 같은 v3에서 아치 모서리만 기본값(높이의 절반 12.5 mm)으로 돌리면 사이클은 거의 같은데(65.5) 원심 가속도가 커져
필요 유지력이 76.7 N으로 Ø40 흡착컵(75.4 N)을 넘습니다. **궤적 설정도 설계의 일부**입니다.

:::mission 팀 미션 — 라인 증속 대응
공장이 라인 속도를 올려 **0.8초 간격(75 사이클/분)** 으로 공급합니다(`s["t"] = 1.0 + 0.8 * n`). 흘려보내는 부품 없이 따라가도록
속도·가속도·아치 높이/반지름·구동계를 조정하세요. 조건: 유지력 SF 2, 관성비 ≤ 10, 모든 비 ≤ 0.8. 흡착컵은 카탈로그에서만 고릅니다.
탐색 기록과 최종 판정 출력, 그리고 "이 이상 빨라지면 무엇이 먼저 막히는가"에 대한 팀의 예측을 제출하세요.

## 자주 나는 오류와 해결

| 증상·메시지 | 원인 | 해결 |
|---|---|---|
| `놓침` 이 생김 (`tool_on()`이 `None`) | 예측 x가 틀림 — 반복 대입 없이 현재 x로 이동 | `plan_pick()`처럼 T(x)를 반복 계산, 로봇과 같은 `H`·`RAD`·프로파일 사용 |
| `흘려보냄` 이 생김 | 로봇 사이클이 공급 간격보다 김 | 속도·가속도↑, 모서리 반지름↑, 대기 시간↓, 상자를 컨베이어 가까이 |
| `WorkspaceError: 작업영역 밖: ... — 팔 길이로 닿지 않음` | 예측 x가 도달 경계 밖(너무 하류) | `robot.reachable()`로 걸러내고 다음 부품 선택 |
| `피크 토크 초과 (안전율 1.2 포함)`, `RMS(연속) 토크가 정격을 넘습니다 — 과열 위험` | 감속비가 작거나 모터가 작음 | D04: 감속비를 N* 쪽으로, 모터 용량↑ |
| `흡착 유지력: ... -> 부족` | 아치 모서리 원심 가속도, 작은 컵 | 모서리 반지름↑, 컵 Ø↑, 가속도↓ |
| `RuntimeError: 가상 시간 600 s 제한을 넘었습니다 (무한 루프인가요?)` | 부품이 없는데 대기 루프가 끝나지 않음 | `while robot.time < 종료시각` 처럼 시간 조건 두기 |

## 과제

1. 컨베이어 속도를 `conv["speed"]`가 아니라 **두 시점의 부품 x 차이**로 추정하도록 `plan_pick()`을 바꾸고, 결과가 같은지 확인하세요(실제 셀에서는 속도를 재야 합니다).
2. 상자 위치를 컨베이어 쪽으로 100 mm 옮긴 장면(`scene["bins"]`의 `y` 수정)을 만들어 평균 사이클과 피크 비가 얼마나 좋아지는지 측정하세요.
3. 프로파일을 `quintic`으로 바꾸면(`robot.set_profile("quintic")`, `move_time()`도 같이) 사이클·피크·유지력이 어떻게 바뀌는지 표로 정리하세요.
