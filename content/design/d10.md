## 학습 목표

- 모터 분해능과 감속기 백래시를 야코비안으로 **TCP 오차(mm)** 로 환산하고, 요구 정밀도와 비교할 수 있습니다.
- A5 용지가 작업영역에 들어가는지 확인하고, 들어가지 않거나 정밀도가 부족할 때 **무엇을 바꿔야 하는지**(치수·작업 높이) 숫자로 결정할 수 있습니다.
- `move_path()`와 `move_to()`의 차이를 속도 균일성·모서리 가속도로 비교하고, 원·별·글자를 그리는 프로그램을 완성할 수 있습니다.

## 과제 소개

A5 종이에 도형과 글자를 그리는 **펜 드로잉 델타**를 만듭니다. 같은 기구에 펜 대신 디스펜서(접착제·크림 짜기)를 달면
**선 굵기 = 토출량 / 이동 속도**이므로, 그리기와 똑같이 **속도가 일정해야** 합니다. 예산을 위해 구동은 **NEMA17 스테퍼 + 타이밍 벨트 감속**입니다.

|---|---|---|

| 백래시 | 백래시로 인한 TCP 최악 오차 **≤ 0.3 mm** | 되돌아 그리는 선이 겹쳐 보일 것 |

## 정밀도 계산: 분해능과 백래시를 TCP로

T06의 속도 관계 $v = Jθ̇$ 는 작은 변위에도 그대로 성립합니다: $δ p = J·δθ$.

- **모터 분해능** — NEMA17은 1.8°/스텝, 드라이버 1/16 마이크로스텝이면 0.1125°(카탈로그 `resolution_deg`, 대표값).
   벨트 4:1을 거치면 출력축에서 $δθ = 0.1125°/4 = 0.0281°$.
- **백래시** — 벨트 감속의 대표 백래시 6′(arcmin)은 **출력축 기준**입니다. 방향이 바뀌면 ±절반(3′)씩 헛돌 수 있다고 보고 계산합니다.
   감속비를 바꿔도 이 값은 줄지 않습니다.
- **최악 오차** — 세 모터가 각각 $±δθ$ 틀리는 8가지 조합 중 $|J·δθ|$가 가장 큰 값을 씁니다.

:::warning 마이크로스텝은 "분해능"이지 "정확도"가 아닙니다
1/16 마이크로스텝으로 명령은 0.1125° 단위로 줄 수 있지만, 실제 스테퍼 축이 그 위치에 정확히 서는 것은 아닙니다(부하·전류 파형에 따라 오차).
위 계산은 **낙관적인 하한**이라고 생각하고, 실물에서는 반복 그리기로 확인해야 합니다.
:::

## 2단계 — 설계 반복

```python run
import math, itertools
from deltarobot import DeltaDesign, DeltaRobot
from deltarobot import kinematics as kin

def tcp_error(d, p, dtheta):
    """세 모터가 모두 ±dtheta 만큼 틀릴 때 TCP 최악 오차 [m] (미소 변위 dp = J·dθ)"""
    J = kin.jacobian(d, kin.ik(d, p), p)
    return max(math.sqrt(sum(sum(J[r][c] * s[c] * dtheta for c in range(3)) ** 2 for r in range(3)))
               for s in itertools.product((-1, 1), repeat=3))

def a5_report(d, z_tcp, W=0.210, H=0.148, n=8):
    step = math.radians(d.motor_spec["resolution_deg"]) / d.ratio      # 출력축 분해능
    lash = math.radians(d.gearbox_spec["backlash_arcmin"] / 60.0)      # 출력축 백래시
    z = z_tcp + d.tool_length                                          # 이펙터 중심 높이
    res, bl, outside = [], [], 0
    for i in range(n + 1):
        for j in range(n + 1):
            p = (-W / 2 + W * i / n, -H / 2 + H * j / n, z)
            if not kin.reachable(d, p):
                outside += 1
                continue
            res.append(tcp_error(d, p, step))
            bl.append(tcp_error(d, p, lash / 2))                       # 백래시는 ±절반
    line = "  z=%4.0f mm  A5 밖 %2d/%d점" % (z_tcp * 1000, outside, (n + 1) ** 2)
    if res:
        line += " | 분해능 %.3f~%.3f mm | 백래시 오차 %.3f~%.3f mm" % (
            min(res) * 1e3, max(res) * 1e3, min(bl) * 1e3, max(bl) * 1e3)
    print(line)

base = DeltaDesign.preset("printer_stepper").copy(tool="pen", payload=0.0)
small = base.copy(base_radius=0.08, effector_radius=0.03, upper_arm=0.1, forearm=0.22)
print("출력축 분해능 %.4f° (1.8°/16 마이크로스텝 ÷ 벨트 %g:1), 백래시 %g′" % (
    base.motor_spec["resolution_deg"] / base.ratio, base.ratio, base.gearbox_spec["backlash_arcmin"]))
print("v0 (R80 L100 l220), 그리기 장면의 종이 면")
a5_report(small, DeltaRobot(small, scene="drawing").scene.surface_z)
print("v1 (printer_stepper 치수), 종이 높이를 바꿔 가며")
for z in (-0.405, -0.36, -0.32, -0.28):
    a5_report(base, z)
```

(벨트 5:1 행은 같은 `a5_report()`에 `base.copy(gear_ratio=5)`를 넣어 얻은 값입니다.)

핵심은 **로봇을 바꾸지 않고 작업대 높이만 바꿔** 정밀도 요구를 맞췄다는 것입니다. 작업영역 아래쪽으로 갈수록 팔이 늘어져
같은 모터 각도 변화에도 TCP가 크게 움직입니다(야코비안↑). z = −320 mm는 백래시 오차 0.251 mm(요구 0.3 mm)와 A5 여유(−280 mm에서 처음 벗어남)
사이의 균형점입니다.

:::design 다른 해결책과 비교
- **감속기 교체**: 사이클로이드(1′)나 하모닉(0.5′)은 백래시를 1/6~1/12로 줄이지만 무겁고 비쌉니다. 이 과제의 "벨트" 조건에 맞지 않습니다.
- **예압**: 벨트 장력을 높이거나 스프링으로 팔을 한쪽으로 눌러 두면 백래시가 드러나지 않습니다. 델타는 **중력이 이미 예압** 역할을 합니다 — 아래 프로그램에서 토크 부호로 확인합니다.
- **소프트웨어 보정**: 방향이 바뀔 때 백래시만큼 더 돌리는 보정. 백래시 값이 일정해야 효과가 있습니다.
:::

## 3단계 — 등속 그리기: move_path vs move_to

`move_to()`는 **점마다 멈추는** 직선 이동이고, `move_path(points, speed, accel)`는 여러 점을 잇는 꺾은선 전체를 **하나의 속도 프로파일**로 움직입니다.
기본 그리기 장면(종이 z = −405 mm)에서 반지름 40 mm 원(72각형)과 별을 50 mm/s, 0.5 m/s²로 그려 비교했습니다.

| 도형 | 방법 | 그리는 시간 | 등속 구간(±5 %) | 수평 가속도 최대 |
|---|---|---|---|---|
| 원 | `move_to` 72번 | 17.01 s | 0 % | 0.48 m/s² |
| 원 | `move_path` | 5.22 s | 94 % | 0.49 m/s² |
| 별 | `move_to` 5번 | 8.61 s | 81 % | 0.49 m/s² |
| 별 | `move_path` | 7.81 s | 95 % | **4.35 m/s²** |

- 원을 `move_to`로 그리면 3.5 mm짜리 변마다 가속·감속하느라 **한 번도 50 mm/s에 도달하지 못하고** 3배 넘게 오래 걸립니다. 디스펜서라면 점선처럼 뭉친 선이 됩니다.
- 별을 `move_path`로 그리면 꼭짓점에서 멈추지 않고 방향만 확 꺾여, 가속도 한계 0.5 m/s²의 약 9배가 순간적으로 걸립니다(경로의 꺾인 점에서는 곡률 반지름이 0).
- 결론: **매끈한 곡선**은 `move_path`, **날카로운 꼭짓점**은 꼭짓점마다 멈추는 `move_to`. (꼭짓점을 작은 원호로 둥글린 뒤 `move_path`를 쓰는 방법도 있습니다 — 과제 3.)

## 4단계 — 응용 프로그램: A5에 테두리·원·별·글자 그리기

최종 설계(printer_stepper 치수 + NEMA17 + 벨트 4:1 + 펜, 종이 면 z = −0.320 m)로 그리기 장면을 만들고, 한 획 글꼴로 "DELTA"까지 씁니다.
장면은 `default_scene(design, "drawing")`으로 만든 뒤 `surface_z`만 바꿔 작업대를 올렸습니다.

```python run
import math
from deltarobot import DeltaDesign, DeltaRobot, default_scene
from deltarobot import dynamics as dyn

# D10 최종 설계: printer_stepper 치수 + NEMA17 + 벨트 4:1 + 펜, 종이 면을 z = -0.320 m 로 올림
design = DeltaDesign.preset("printer_stepper").copy(tool="pen", payload=0.0)
scene = default_scene(design, "drawing")
scene["surface_z"] = -0.320                  # 작업대(종이) 높이 — 백래시 오차 검토로 정한 값
robot = DeltaRobot(design, scene=scene)

Z = robot.scene.surface_z                    # 펜 끝이 종이에 닿는 높이
LIFT = 0.010                                 # 펜 들어 올리는 높이 [m]
DRAW_V, DRAW_A = 0.05, 0.5                   # 그리기 속도 50 mm/s, 가속도 0.5 m/s^2

def stroke(points, smooth=False):
    """펜을 내려 한 획을 그린 뒤 펜을 든다.
    smooth=True : 곡선(원) — move_path 로 꼭짓점에서 멈추지 않고 등속으로
    smooth=False: 꺾인 선(별·글자) — 꼭짓점마다 멈추는 move_to (모서리 가속도 튐 방지)"""
    x0, y0 = points[0]
    robot.move_to(x0, y0, Z + LIFT)              # 펜 든 채 이동 (기본 속도)
    robot.move_to(x0, y0, Z, speed=0.05)         # 천천히 내려 찍기
    robot.pen_down()
    if smooth:
        robot.move_path([(x, y, Z) for x, y in points[1:]], speed=DRAW_V, accel=DRAW_A)
    else:
        for x, y in points[1:]:
            robot.move_to(x, y, Z, speed=DRAW_V, accel=DRAW_A)
    robot.pen_up()
    robot.move_by(dz=LIFT)

def circle(cx, cy, r, n=72):
    return [(cx + r * math.cos(2 * math.pi * k / n), cy + r * math.sin(2 * math.pi * k / n))
            for k in range(n + 1)]

def star(cx, cy, r):
    return [(cx + r * math.sin(4 * math.pi * k / 5), cy + r * math.cos(4 * math.pi * k / 5))
            for k in range(6)]

# 한 획 글꼴: 글자 칸 (0..1) x (0..1)
FONT = {"D": [[(0, 0), (0, 1), (0.6, 1), (1, 0.7), (1, 0.3), (0.6, 0), (0, 0)]],
        "E": [[(1, 1), (0, 1), (0, 0), (1, 0)], [(0, 0.5), (0.7, 0.5)]],
        "L": [[(0, 1), (0, 0), (1, 0)]],
        "T": [[(0, 1), (1, 1)], [(0.5, 1), (0.5, 0)]],
        "A": [[(0, 0), (0.5, 1), (1, 0)], [(0.25, 0.5), (0.75, 0.5)]]}

def text(s, x0, y0, w=0.018, h=0.025, pitch=0.028):
    for i, ch in enumerate(s):
        for line in FONT[ch]:
            stroke([(x0 + i * pitch + u * w, y0 + v * h) for u, v in line])

W, H = 0.210, 0.148                              # A5 가로 놓기
robot.home()
stroke([(-W / 2, -H / 2), (W / 2, -H / 2), (W / 2, H / 2), (-W / 2, H / 2), (-W / 2, -H / 2)])  # 테두리
stroke(circle(-0.050, 0.020, 0.040), smooth=True)
stroke(star(0.055, 0.020, 0.040))
text("DELTA", -0.066, -0.060)
robot.home()

res = robot.analyze()
print("총 시간 %.1f s" % robot.time)
print("피크 %.2f  RMS %.2f  속도 %.2f  속도-토크 %.2f  ->  %s" % (
    res["peak_ratio"], res["rms_ratio"], res["speed_ratio"], res["curve_ratio"],
    "통과" if res["ok"] else res["problems"]))

# 백래시: 그리는 동안 토크 부호가 바뀌면 기어 이가 반대편으로 넘어간다
data = dyn.analyze(design, robot.backend.frames)
for i in range(3):
    tau = [f["tau"][i] for f in data if f["tool"] == 1]
    print("모터%d 그리는 중 τ %.3f ~ %.3f N·m  %s" % (
        i + 1, min(tau), max(tau), "부호 유지" if min(tau) * max(tau) > 0 else "부호 반전!"))
```

```text
총 시간 47.8 s
피크 0.19  RMS 0.12  속도 0.11  속도-토크 0.30  ->  통과
모터1 그리는 중 τ -0.200 ~ -0.044 N·m  부호 유지
모터2 그리는 중 τ -0.203 ~ -0.033 N·m  부호 유지
모터3 그리는 중 τ -0.205 ~ -0.033 N·m  부호 유지
```

- 모터 검증은 모두 여유가 큽니다(스테퍼 여유 1.5를 나눈 곡선 비도 0.30). 그리기는 느린 작업이라 **정밀도가 설계를 결정**합니다.
- 그리는 동안 세 모터의 출력축 토크가 **항상 음수**(팔 무게·이동판 무게를 들어 올리는 방향)입니다. 기어 이가 늘 같은 쪽 면에 닿아 있으므로
   이 동작에서는 **중력이 백래시를 예압**해 백래시 오차가 드러나지 않습니다. 최소 |τ| = 0.033 N·m가 그 여유입니다.
- 반대로 꼭짓점에서 급가속하는 경로(별을 `move_path`로)는 순간 토크 부호를 바꿀 수 있습니다. 개발 초기에 모든 획을 `move_path`로,
   종이 z = −405 mm에서 그렸을 때는 모터 2의 토크가 그리는 도중 +0.039 N·m까지 올라가 부호가 바뀌었습니다.

## 자주 나는 오류와 해결

| 증상·메시지 | 원인 | 해결 |
|---|---|---|
| `WorkspaceError: 작업영역 밖: ... — 팔 길이로 닿지 않음` (A5 모서리에서) | 종이가 작업영역보다 큼, 또는 종이 높이가 너무 높음 | `a5_report()`로 높이를 다시 고르거나 치수를 키움 |
| `WorkspaceError: 경로 중간 작업영역 밖: ...` | 펜을 든 채 이동하는 직선이 작업영역 경계를 스침 | 이동 높이(`LIFT`)를 줄이거나 경유점 추가 |
| 원이 느리고 선이 뭉침 | 원을 `move_to` 여러 번으로 그림 (변마다 정지) | `move_path()`로 한 번에 |
| 별 꼭짓점에서 선이 튀거나 흔들림 | `move_path`는 꼭짓점에서 감속하지 않음 → 순간 가속도 급증 | 꼭짓점마다 `move_to`, 또는 꼭짓점을 원호로 둥글림 |
| 그림이 조금씩 밀려 있음 (실물) | 스테퍼 탈조 — 시뮬레이터는 탈조를 재현하지 않음 | `curve_ratio`(1.5 여유 포함) 확인, 가속도↓, 원점 복귀 |
| `ValueError: 설계 오류: belt 의 감속비는 [2, 3, 4, 5] 중에서 고르세요` | 없는 벨트 감속비 | 2~5 중 선택 |

## 과제

1. 종이 높이를 −320 mm로 고정하고 `upper_arm`을 0.12~0.16 m로 바꿔 가며 `a5_report()`를 돌려, 백래시 오차가 가장 작은 L을 찾으세요. 작업영역은 어떻게 되나요?
2. 그리기 프로그램에서 펜을 든 채 이동하는 구간(`move_to(..., Z + LIFT)`)의 속도를 올리면 총 시간이 얼마나 줄어드는지, `analyze()`가 여전히 통과하는지 확인하세요.
3. 별의 꼭짓점을 반지름 2 mm 원호(점 8개)로 둥글린 경로를 만들어 `move_path` 한 번으로 그리고, 등속 구간과 최대 가속도를 위 표와 비교하세요.
