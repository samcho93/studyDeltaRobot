## 학습 목표

- 베이스 좌표계(원점·축 방향·단위)와 팔의 방위각 φᵢ, 모터각 θᵢ의 **부호 규약**을 정확히 말할 수 있습니다.
- 설계 파라미터 R, r, L, l, w가 각각 무엇을 재는 길이인지 그림으로 설명하고 `DeltaDesign` 필드 이름과 연결할 수 있습니다.
- 팔 좌표계로 회전 변환하는 식과 팔꿈치 위치 $E = (R + L·cos θ, 0, −L·sin θ)$를 유도할 수 있습니다.
- 기구학에는 R과 r이 **R − r**로만 들어간다는 사실(등가 반지름)을 보이고 코드로 확인할 수 있습니다.
- 이펙터 중심과 TCP(툴 끝)를 구분하고, 어떤 함수가 어느 좌표를 쓰는지 알 수 있습니다.

## 베이스 좌표계

이 강의·라이브러리·시뮬레이터·ROS 2 드라이버가 **모두 같은 규약**을 씁니다. 한 번 정하면 바꾸지 않습니다.

| 항목 | 규약 |
|---|---|
| 원점 | 베이스 중심, 세 모터축이 놓인 평면 위 |
| 축 | 오른손 좌표계, **z 위쪽**. 로봇은 천장에 매달려 아래를 향하므로 작업은 **z < 0** |
| 단위 | SI: m, rad, kg, s (각도를 도(°)로 넣지 않습니다) |
| 팔 번호 | 팔 1·2·3의 방위각 $φᵢ$ = 0°, 120°, 240°. **팔 1이 +x 방향** |
| 모터각 | $θᵢ$ = 0이면 위팔이 **수평**, 팔이 **아래로 내려가면 +** |

@fig[t03-top-view] 위에서 본 베이스(점선 원, 반지름 R)와 이펙터(삼각형). 굵은 선은 θ = 0.35 rad일 때 위팔의 위쪽 투영입니다. edu_dynamixel 치수.

## 설계 파라미터

| 기호 | `DeltaDesign` 필드 | 의미 | 기본값 (= edu_dynamixel) |
|---|---|---|---|
| R | `base_radius` | 베이스 중심 → 모터축(위팔 회전 중심)까지 거리 | 0.1 m |
| r | `effector_radius` | 이펙터 중심 → 볼조인트 **쌍의 중심**까지 거리 | 0.035 m |
| L | `upper_arm` | 위팔 길이 (모터축 → 팔꿈치 볼조인트 쌍 중심) | 0.13 m |
| l | `forearm` | 아래팔 로드 길이 (볼조인트 중심 사이) | 0.3 m |
| w | `forearm_spacing` | 평행사변형 두 로드 사이 간격 | 0.05 m |
| θmin, θmax | `theta_min`, `theta_max` | 모터각 한계 | −0.7, 1.5 rad |
| — | `ball_joint_limit` | 로드가 팔 평면 밖으로 기울 수 있는 최대각 | 0.6 rad |

R과 r은 모두 **"중심에서 볼조인트 쌍의 가운데까지"** 잰 값입니다. 베이스 판의 바깥 반지름이나 이펙터 판의 크기가 아닙니다.
w는 기구학(위치 계산)에는 들어가지 않고, 평행사변형의 비틀림 강성과 질량(팔꿈치 막대 길이)에 영향을 줍니다.

## 팔 좌표계와 팔꿈치 위치

팔 i 하나만 떼어 보면 위팔은 **φᵢ 방향의 수직 평면(팔 평면)** 안에서만 돕니다. 그래서 계산할 때는 좌표를 팔 i 기준으로 돌려 놓는 것이 편합니다.
z축을 중심으로 −φᵢ만큼 돌리면 팔 i가 x′축 위에 놓입니다.

```text
x′ =  x·cos φᵢ + y·sin φᵢ        (팔 방향, 바깥이 +)
y′ = −x·sin φᵢ + y·cos φᵢ        (모터축 방향, 팔 평면에 수직)
z′ =  z
```

팔 좌표계에서 각 점은 다음과 같습니다.

- 모터(위팔 회전 중심): $M = (R, 0, 0)$
- 팔꿈치: 위팔이 θ만큼 **아래로** 돌면 $E = (R + L·cos θ, 0, −L·sin θ)$. θ > 0이면 z가 음수(아래)가 됩니다.
- 이펙터 쪽 볼조인트 쌍: 이펙터 중심이 $P′ = (x′, y′, z)$이면 $B = (x′ + r, y′, z)$
- 제약 조건: 로드 길이는 변하지 않으므로 $|B − E| = l$

@fig[t03-arm-plane] 팔 1의 팔 평면(x–z). θ는 수평에서 아래로 잰 각이고, TCP는 이펙터 중심에서 툴 길이만큼 아래입니다. 아래팔은 팔 평면 밖으로 기울 수 있으므로 여기 보이는 길이는 l의 투영입니다.

라이브러리 `kinematics.elbow()`는 이 식을 베이스 좌표로 돌려서 계산합니다.

```python
def elbow(design, i, theta):
    rho = design.base_radius + design.upper_arm * math.cos(theta)
    c, s = math.cos(PHI[i]), math.sin(PHI[i])
    return (rho * c, rho * s, -design.upper_arm * math.sin(theta))
```

## 등가 반지름 R − r

제약식의 차이 벡터를 팔 좌표계에서 써 보면

```text
B − E = (x′ + r − R − L·cos θ,  y′,  z + L·sin θ)
```

R과 r이 **항상 `r − R` 한 덩어리로만** 나타납니다. 즉 이펙터를 점으로 줄이고(r = 0) 베이스 반지름을 R − r로 줄여도
역기구학·순기구학·야코비안 결과가 완전히 같습니다. 실제 교과서와 논문에서도 "(R − r)만 설계 변수로 둔다"는 표현을 자주 씁니다.
T04에서 쓰는 `a = x′ + r − R`이 바로 이 덩어리입니다.

그렇다고 r을 아무렇게나 정해도 되는 것은 아닙니다. r은 이펙터 판의 크기(툴·흡착컵을 달 공간), 볼조인트끼리의 간섭,
이펙터의 회전 강성(볼조인트가 멀리 떨어질수록 비틀림에 강함)에 영향을 줍니다.

:::design 파라미터가 형상에 주는 영향 (정성적)
- **L을 키우면**: 팔꿈치가 크게 움직여 작업영역이 위아래·옆으로 넓어지고 속도가 빨라지지만, 같은 힘에 필요한 모터 토크가 커집니다(T08).
- **l을 키우면**: 이펙터가 더 아래로 내려가고 작업영역이 넓어지지만, 로드가 무거워지고 휘기 쉬워집니다. 보통 l ≈ 2~2.5 L.
- **R − r을 키우면**: 팔 사이가 벌어져 가운데 부근의 강성·조건수가 좋아지지만, 로봇이 커지고 작업영역 중심이 얕아집니다.
- 설계 트랙 D03에서 이 비율을 파라미터 스윕으로 정량 비교합니다.
:::

## TCP와 이펙터 중심

| 좌표 | 뜻 | 쓰는 곳 |
|---|---|---|
| 이펙터 중심 P | 이펙터 판의 중심(볼조인트 쌍 3개의 중심) | `deltarobot.kinematics`의 모든 함수(`ik`, `fk`, `jacobian`, `limit_report`, `workspace_points`, `work_cylinder`) |
| TCP | 툴 끝(흡착컵 입구, 펜 끝) = $P − (0, 0, 툴 길이)$ | `DeltaRobot`의 모든 위치 인자와 속성(`move_to`, `ik`, `fk`, `reachable`, `position`) |

툴 길이는 카탈로그의 툴(`tool`)마다 정해져 있고 `d.tool_length`로 읽습니다. 예를 들어 edu_dynamixel의 `gripper_servo`는 0.07 m이므로
TCP는 이펙터 중심보다 7 cm 아래입니다. 이펙터는 기울지 않으므로(T02) 이 오프셋은 항상 −z 방향입니다.

## 실습

### 실습 A — 규약을 코드로 확인

아래 코드는 edu_dynamixel 설계의 모터·팔꿈치 위치를 출력하고, 등가 반지름과 TCP 오프셋을 확인합니다.

```python run
import math
from deltarobot import DeltaDesign, DeltaRobot
from deltarobot import kinematics as kin

d = DeltaDesign.preset("edu_dynamixel")
print("R=%.3f r=%.3f L=%.3f l=%.3f w=%.3f [m]" % (d.R, d.r, d.L, d.l, d.forearm_spacing))
print("theta range [%.2f, %.2f] rad = [%.1f, %.1f] deg" % (
    d.theta_min, d.theta_max, math.degrees(d.theta_min), math.degrees(d.theta_max)))
print("tool %s, length %.3f m" % (d.tool, d.tool_length))

# 1) motor points and elbows at the home angle (all three arms equal)
th = d.home_theta
for i in range(3):
    m = kin.motor_point(d, i)
    e = kin.elbow(d, i, th)
    print("arm %d phi=%5.1f deg  motor=(%+.4f, %+.4f, %+.4f)  elbow=(%+.4f, %+.4f, %+.4f)"
          % (i + 1, math.degrees(kin.PHI[i]), m[0], m[1], m[2], e[0], e[1], e[2]))

# 2) only R - r matters for the kinematics
p = (0.03, -0.02, -0.26)                       # effector centre [m]
d_eq = d.copy(base_radius=d.R - d.r, effector_radius=0.0)
print("ik with (R, r)   :", [round(t, 6) for t in kin.ik(d, p)])
print("ik with (R-r, 0) :", [round(t, 6) for t in kin.ik(d_eq, p)])

# 3) TCP (robot API) vs effector centre (kinematics module)
robot = DeltaRobot(d)
tcp = (p[0], p[1], p[2] - d.tool_length)
print("robot.ik(TCP)    :", [round(t, 6) for t in robot.ik(*tcp)])
print("home: effector centre", [round(v, 4) for v in robot.effector],
      " TCP", [round(v, 4) for v in robot.position])
```

```text
R=0.100 r=0.035 L=0.130 l=0.300 w=0.050 [m]
theta range [-0.70, 1.50] rad = [-40.1, 85.9] deg
tool gripper_servo, length 0.070 m
arm 1 phi=  0.0 deg  motor=(+0.1000, +0.0000, +0.0000)  elbow=(+0.2221, +0.0000, -0.0446)
arm 2 phi=120.0 deg  motor=(-0.0500, +0.0866, +0.0000)  elbow=(-0.1111, +0.1924, -0.0446)
arm 3 phi=240.0 deg  motor=(-0.0500, -0.0866, +0.0000)  elbow=(-0.1111, -0.1924, -0.0446)
ik with (R, r)   : [0.07697, 0.416756, 0.232582]
ik with (R-r, 0) : [0.07697, 0.416756, 0.232582]
robot.ik(TCP)    : [0.07697, 0.416756, 0.232582]
home: effector centre [0.0, 0.0, -0.2791]  TCP [0.0, 0.0, -0.3491]
```

읽는 법

- 팔꿈치 z가 모두 −0.0446 m: $−L·sin 0.35 = −0.13 × 0.3429$. θ > 0이면 팔꿈치가 모터축 평면보다 **아래**에 있습니다.
- 팔 1의 팔꿈치 x = 0.2221 = $R + L·cos 0.35$ = 0.1 + 0.1221.
- (R, r)과 (R − r, 0)의 IK 결과가 소수점 여섯째 자리까지 같습니다.
- `robot.ik()`에는 TCP를 넣었는데 `kin.ik()`에 이펙터 중심을 넣은 것과 같은 각도가 나옵니다. 둘의 z 차이는 정확히 툴 길이 0.07 m입니다.

### 실습 B — 파라미터를 바꾸면 높이가 어떻게 변하나

```python run
from deltarobot import DeltaDesign
from deltarobot import kinematics as kin

# how each parameter changes the home height and the reach
base = DeltaDesign.preset("edu_dynamixel")
cases = [("base", {}), ("L +20%", {"upper_arm": base.L * 1.2}),
         ("l +20%", {"forearm": base.l * 1.2}), ("R-r +20%", {"base_radius": base.R + 0.2 * (base.R - base.r)})]
print("case        home z [m]   centre z range [m] (theta limits)")
for name, ch in cases:
    d = base.copy(**ch)
    zh = kin.fk(d, (d.home_theta,) * 3)[2]
    z_top = kin.fk(d, (d.theta_min,) * 3)[2]
    z_bot = kin.fk(d, (d.theta_max,) * 3)[2]
    print("%-10s  %8.4f     %8.4f .. %8.4f" % (name, zh, z_top, z_bot))
```

```text
case        home z [m]   centre z range [m] (theta limits)
base         -0.2791      -0.1672 ..  -0.4204
L +20%       -0.2662      -0.1362 ..  -0.4458
l +20%       -0.3521      -0.2365 ..  -0.4819
R-r +20%     -0.2681      -0.1582 ..  -0.4167
```

세 모터를 같은 각도로 두면 이펙터는 z축 위를 오르내립니다. 모터각 한계 [θmin, θmax]에서의 두 높이가 **중심축 위의 z 범위**입니다.
L을 늘리면 범위가 위아래로 모두 넓어지고(0.253 → 0.310 m), l을 늘리면 범위 전체가 아래로 내려갑니다.
R − r을 늘리면 홈 위치가 조금 올라가고 범위는 약간 좁아집니다. (옆 방향 작업영역은 T07에서 봅니다.)

## 자주 나는 오류와 해결

### 1) 모터각 부호가 반대 (팔이 올라가야 할 때 내려감)

- 원인: "위로 +"(수학에서 흔한 반시계 방향) 규약을 쓴 코드나 실물 서보 방향을 그대로 섞었습니다.
- 해결: 이 강의는 **아래로 +**입니다. 팔꿈치 식 $E = (R + L·cos θ, 0, −L·sin θ)$의 **마이너스**를 확인하세요.
  실물 서보는 설치 방향에 따라 부호가 반대일 수 있으므로 펌웨어/캘리브레이션에서 방향 계수로 맞춥니다(R07).

### 2) 각도를 도(°)로 넣음

```text
deltarobot.robot.WorkspaceError: 모터 1 각도 1145.9° 가 한계 [-40.1°, 85.9°] 밖입니다
```

- 원인: `robot.move_joints(20, 20, 20)`처럼 도 단위 숫자를 라디안 자리에 넣었습니다(20 rad = 1145.9°).
- 해결: `math.radians(20)`으로 바꾸거나 `robot.move_joints(20, 20, 20, degrees=True)`를 씁니다. 라이브러리 내부는 모두 rad입니다.

### 3) 팔 2·3의 위치가 뒤바뀜

- 원인: φ를 시계 방향(0°, −120°, −240°)으로 두었거나, 팔 2를 −y 쪽에 두었습니다.
- 해결: z 위쪽 오른손 좌표계에서 φ는 **반시계**로 0°, 120°, 240°입니다. 팔 2의 모터는 (−0.05, +0.0866, 0)처럼 **+y** 쪽에 있습니다.

### 4) TCP와 이펙터 중심을 섞어서 7 cm 차이

- 원인: `kin.ik(d, p)`에 TCP 좌표를 넣었거나, `robot.move_to()`에 이펙터 중심 좌표를 넣었습니다.
- 해결: `kinematics` 모듈 = 이펙터 중심, `DeltaRobot` = TCP. 변환은 `p_effector = (x, y, z + d.tool_length)`.

### 5) R과 r을 판의 바깥 크기로 입력

- 원인: 베이스 판·이펙터 판의 외곽 반지름을 R, r로 넣었습니다.
- 해결: R은 모터축(위팔 회전 중심)까지, r은 볼조인트 **쌍의 중심**까지 거리입니다. CAD에서 볼조인트 중심점을 찍어 재세요.
  r ≥ R이면 `DeltaDesign.validate()`가 "effector_radius(r)는 base_radius(R)보다 작아야 합니다"를 돌려줍니다.

## 과제
