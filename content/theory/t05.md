## 학습 목표

- 모터각 $(θ₁, θ₂, θ₃)$에서 이펙터 중심 위치를 구하는 문제가 **세 구의 교점 문제**로 바뀌는 과정을 설명할 수 있습니다.
- 구 중심을 $Cᵢ = Eᵢ − r·uᵢ$로 옮기는 "가상 구 중심" 기법이 왜 성립하는지 보일 수 있습니다.
- 삼변측량(trilateration) 공식을 국소 좌표계(ex, ey, ez)로 유도하고, 두 해 중 **아래(z가 작은) 해**를 고르는 이유를 설명할 수 있습니다.
- FK를 Python으로 구현하고 `deltarobot.kinematics.fk`와 비교하며, IK와 왕복(round-trip) 검증을 할 수 있습니다.

## 왜 FK가 IK보다 어려운가

IK에서는 P를 알면 팔 세 개가 **각자** 풀렸습니다. FK에서는 반대로 θ를 알면 팔꿈치 $Eᵢ$ 세 개는 바로 나오지만,
이펙터 위치 P는 **세 팔의 조건을 동시에** 만족해야 정해집니다. 직렬로봇의 FK(행렬 곱)와 달리 연립 방정식을 풀어야 하고,
해가 두 개 나오며, 해가 없는 경우(조립 불가)도 있습니다. 병렬로봇에서는 이것이 일반적인 성질입니다.

## 세 구로 바꾸기

팔 i의 조건은 로드 길이 제약입니다. 베이스 좌표로 쓰면

```text
|Bᵢ − Eᵢ| = l,     Bᵢ = P + r·uᵢ,     uᵢ = (cos φᵢ, sin φᵢ, 0)
Eᵢ = ((R + L·cos θᵢ)·cos φᵢ,  (R + L·cos θᵢ)·sin φᵢ,  −L·sin θᵢ)
```

이펙터가 회전하지 않으므로 $r·uᵢ$는 상수 벡터입니다. 그래서 식을 다음처럼 바꿀 수 있습니다.

```text
|P + r·uᵢ − Eᵢ| = l   ⇔   |P − (Eᵢ − r·uᵢ)| = l   ⇔   |P − Cᵢ| = l,    Cᵢ = Eᵢ − r·uᵢ
```

즉 **P는 중심이 Cᵢ이고 반지름이 l인 구 세 개의 교점**입니다. 팔꿈치를 이펙터 반지름만큼 안쪽으로 옮긴 점이 구 중심이 되는 것이고,
T03의 등가 반지름(R − r)과 같은 아이디어입니다. 세 구의 반지름이 **모두 l로 같다**는 점이 공식을 단순하게 만듭니다.

@fig[t05-trilateration] 왼쪽: 팔꿈치 Eᵢ를 r만큼 안쪽으로 옮긴 가상 구 중심 Cᵢ(위에서 본 그림). 오른쪽: 세 모터각이 모두 0.35 rad일 때 옆에서 본 두 구와 두 교점. 교점은 세 중심의 평면에 대해 대칭입니다. edu_dynamixel 실제 치수.

## 삼변측량 유도

세 중심 C₁, C₂, C₃를 기준으로 편한 직교 좌표계를 만듭니다.

```text
ex = (C₂ − C₁) / |C₂ − C₁|,        d = |C₂ − C₁|
t  = C₃ − C₁,                       i = ex · t
ey = (t − i·ex) / |t − i·ex|,       j = ey · t
ez = ex × ey
```

이 좌표계에서 C₁ = (0, 0, 0), C₂ = (d, 0, 0), C₃ = (i, j, 0)이고 구하는 점을 (X, Y, Z)라고 하면

```text
X² + Y² + Z²             = l²      (구 1)
(X − d)² + Y² + Z²       = l²      (구 2)
(X − i)² + (Y − j)² + Z² = l²      (구 3)
```

구 1 − 구 2: $2dX − d² = 0$ → **$X = d/2$** (반지름이 같으므로 두 중심의 수직이등분면)

구 1 − 구 3: $2iX + 2jY − i² − j² = 0$ → **$Y = (i² + j² − 2iX) / (2j)$**

구 1에 대입: **$Z² = h² = l² − X² − Y²$**, $Z = ±h$

베이스 좌표로 되돌리면

```text
P = C₁ + X·ex + Y·ey ± h·ez
```

라이브러리 `fk()`는 이 식을 그대로 씁니다(`# equal radii (l) simplify the classic trilateration formulas`).
세 반지름이 다른 일반 삼변측량 공식에서 $r₁ = r₂ = r₃ = l$을 넣으면 위 식이 됩니다.

### 두 해와 해 선택

- $h² > 0$: 해 두 개. 세 중심이 이루는 평면에 대해 **거울 대칭**입니다(± h·ez).
- $h² = 0$: 해 하나(두 해가 만남). T06에서 보듯 이 자리가 **2형 특이점**입니다.
- $h² < 0$: 해 없음. 세 구가 한 점에서 만나지 않음 → 이 모터각 조합으로는 **조립할 수 없음**. 라이브러리는 `Unreachable`을 던집니다.

로봇은 베이스 아래에 매달려 있으므로 **z가 작은(아래) 해**를 고릅니다. 위 해는 이펙터가 베이스 위로 뒤집혀 올라간 자세로,
실제로 조립된 로봇이 연속적으로 넘어갈 수 없는 다른 "조립 모드"입니다. `ez`의 방향(위/아래)은 C₁, C₂, C₃의 순서에 따라 달라질 수 있으므로
코드에서 `+h`, `−h` 중 하나를 고정해서 쓰지 말고 **두 점의 z를 비교**해 고릅니다.

:::tip 두 번째 비교 방법 — 연립 1차 + 2차
교재에 따라 구 방정식 두 쌍을 빼서 1차식 두 개를 만들고, x·y를 z의 1차식으로 표현한 뒤 구 하나에 넣어 z의 2차방정식을 푸는 방법도 씁니다.
결과는 같지만, 특정 팔 배치(예: 두 중심의 z가 같을 때)에서 나눗셈이 0이 되는 경우를 따로 처리해야 합니다.
위의 국소 좌표계 방법은 세 중심이 **한 직선 위에 있을 때만** 실패하므로 더 안정적입니다.
:::

## 풀이 예제 (라이브러리로 계산)

edu_dynamixel, $θ = (0.2, 0.6, 0.4)$ rad의 이펙터 위치를 구합니다. 아래 코드는 유도한 식을 한 줄씩 옮긴 FK입니다.

```python run
import math
from deltarobot import DeltaDesign
from deltarobot import kinematics as kin

def sub(a, b): return tuple(u - v for u, v in zip(a, b))
def add(a, b): return tuple(u + v for u, v in zip(a, b))
def mul(a, k): return tuple(u * k for u in a)
def dot(a, b): return sum(u * v for u, v in zip(a, b))
def cross(a, b): return (a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0])
def norm(a): return math.sqrt(dot(a, a))

def my_fk(d, theta, verbose=False):
    """Forward kinematics by trilateration. Returns (lower, upper) solutions."""
    C = []
    for i, phi in enumerate(kin.PHI):
        u = (math.cos(phi), math.sin(phi), 0.0)
        rho = d.R + d.L * math.cos(theta[i])
        E = (rho * u[0], rho * u[1], -d.L * math.sin(theta[i]))   # elbow
        C.append(sub(E, mul(u, d.r)))                             # sphere centre
    ex = sub(C[1], C[0]); dd = norm(ex); ex = mul(ex, 1 / dd)
    t = sub(C[2], C[0]); i_ = dot(ex, t)
    ey = sub(t, mul(ex, i_)); ey = mul(ey, 1 / norm(ey))
    ez = cross(ex, ey); j = dot(ey, t)
    x = dd / 2
    y = (i_ * i_ + j * j - 2 * i_ * x) / (2 * j)
    h2 = d.l ** 2 - x * x - y * y
    if verbose:
        for k in range(3):
            print("C%d = (%+.4f, %+.4f, %+.4f)" % (k + 1, *C[k]))
        print("d=%.4f i=%.4f j=%.4f  x=%.4f y=%.4f h^2=%.6f" % (dd, i_, j, x, y, h2))
    if h2 < 0:
        raise ValueError("no solution: spheres do not meet (h^2 = %.5f)" % h2)
    h = math.sqrt(h2)
    base = add(C[0], add(mul(ex, x), mul(ey, y)))
    p1, p2 = add(base, mul(ez, h)), sub(base, mul(ez, h))
    return (p1, p2) if p1[2] < p2[2] else (p2, p1)

d = DeltaDesign.preset("edu_dynamixel")
theta = (0.2, 0.6, 0.4)
low, up = my_fk(d, theta, verbose=True)
print("lower solution:", [round(v, 5) for v in low])
print("upper solution:", [round(v, 5) for v in up])
print("library fk    :", [round(v, 5) for v in kin.fk(d, theta)])
```

```text
C1 = (+0.1924, +0.0000, -0.0258)
C2 = (-0.0861, +0.1492, -0.0734)
C3 = (-0.0924, -0.1600, -0.0506)
d=0.3196 i=0.1772 j=0.2755  x=0.1598 y=0.0920 h^2=0.056012
lower solution: [0.04004, -0.02428, -0.28311]
upper solution: [-0.02077, 0.01143, 0.18494]
library fk    : [0.04004, -0.02428, -0.28311]
```

읽는 법

- C₁ = (0.1924, 0, −0.0258): 팔꿈치 $E₁ = (0.1 + 0.13·cos 0.2, 0, −0.13·sin 0.2) = (0.2274, 0, −0.0258)$에서 x를 r = 0.035만큼 뺀 값입니다.
- 팔 2의 θ가 가장 커서(0.6) C₂가 가장 낮습니다(z = −0.0734).
- $X = d/2 = 0.1598$, $h = √0.056012 ≈ 0.2367$. 아래 해의 z = −0.283 m, 위 해는 z = +0.185 m(베이스 위)입니다.
- 이펙터가 팔 2의 반대쪽(+x, −y)으로 치우쳤습니다. 팔 2가 가장 많이 내려가 이펙터를 밀어낸 결과입니다. T04 예제와 방향이 비슷한 것도 확인해 보세요.

## 실습 — 왕복 검증과 조립 불가 각도

```python run
import math, random
from deltarobot import DeltaDesign, DeltaRobot, WorkspaceError
from deltarobot import kinematics as kin

d = DeltaDesign.preset("edu_dynamixel")

# 1) round trip: theta -> fk -> ik -> theta
random.seed(1)
worst, n, fail = 0.0, 0, 0
while n < 2000:
    th = [random.uniform(d.theta_min, d.theta_max) for _ in range(3)]
    try:
        p = kin.fk(d, th)
    except kin.Unreachable:
        fail += 1
        continue
    back = kin.ik(d, p)
    worst = max(worst, max(abs(a - b) for a, b in zip(th, back)))
    n += 1
print("round trip on %d samples: max error %.2e rad  (%d theta sets could not be assembled)" % (n, worst, fail))

# 2) a design whose rods are too short to assemble at theta = (0, 0, 0)
d_bad = d.copy(forearm=0.1)            # l = 0.1 m < circumradius of the C_i triangle
try:
    kin.fk(d_bad, (0.0, 0.0, 0.0))
except kin.Unreachable as e:
    print("kin.fk:", type(e).__name__, e)
robot_bad = DeltaRobot(d_bad)          # l < L only gives a warning in validate()
try:
    robot_bad.move_joints(0.0, 0.0, 0.0)
except WorkspaceError as e:
    print("robot :", e)

# 3) FK on the robot API returns the TCP, not the effector centre
th = (0.35, 0.35, 0.35)
print("kin.fk   (effector centre):", [round(v, 4) for v in kin.fk(d, th)])
print("robot.fk (TCP)            :", [round(v, 4) for v in DeltaRobot(d).fk(*th)])
```

```text
round trip on 2000 samples: max error 2.22e-15 rad  (0 theta sets could not be assembled)
kin.fk: Unreachable no forward kinematic solution for theta=(0.0, 0.0, 0.0)
설계 경고: forearm(l)이 upper_arm(L)보다 짧으면 작업영역이 매우 좁아집니다 (보통 l ≈ 2~2.5 L)
robot : 이 관절각 조합은 조립될 수 없습니다: no forward kinematic solution for theta=(0.0, 0.0, 0.0)
kin.fk   (effector centre): [0.0, 0.0, -0.2791]
robot.fk (TCP)            : [0.0, 0.0, -0.3491]
```

읽는 법

- 모터각 한계 안의 무작위 θ 2000개에서 FK → IK로 돌아온 각의 오차가 $10⁻¹⁵$ 수준입니다. 부동소수점 반올림뿐이라는 뜻입니다.
- edu_dynamixel에서는 한계 안의 모든 θ 조합이 조립 가능했습니다(`0 theta sets could not be assembled`). 구 중심 Cᵢ는 모두 z축에서
   $R − r + L = 0.195$ m 안쪽에 있는데 구 반지름 l = 0.3 m가 충분히 커서, 세 구가 언제나 만나기 때문입니다.
- 로드를 l = 0.1 m로 줄인 `d_bad`에서는 θ = (0, 0, 0)일 때 세 중심이 z축에서 0.195 m 떨어진 정삼각형을 이루고,
   그 외접원 반지름(0.195 m)이 l보다 커서 $h² < 0$ → `Unreachable`입니다. `DeltaRobot`은 같은 상황을 `WorkspaceError`로 알려 줍니다.
   (`설계 경고:` 줄은 l < L인 설계를 만들 때 라이브러리가 출력하는 경고입니다.)
- `robot.fk()`는 TCP를 돌려줍니다. 이펙터 중심과 z가 정확히 툴 길이(0.07 m)만큼 다릅니다.

:::check 스스로 점검
edu_dynamixel에서 FK 예외가 나지 않았다고 해서 모든 θ가 "좋은 자세"는 아닙니다. 예를 들어 θ = (−0.7, 1.5, 1.5)도 조립은 되지만
`kin.limit_report(d, kin.fk(d, (-0.7, 1.5, 1.5)))`를 실행해 보면 볼조인트·팔꿈치 한계 검사 결과를 확인할 수 있습니다. 결과를 해석해 보세요.

## 자주 나는 오류와 해결

### 1) 이펙터가 베이스 위(z > 0)로 나옴

- 원인: 두 해 중 `+h` 해를 고정으로 골랐습니다. ez의 방향은 중심 순서·배치에 따라 위를 향할 수도 아래를 향할 수도 있습니다.
- 해결: 두 점을 모두 계산하고 **z가 작은 쪽**을 고릅니다(`p1 if p1[2] < p2[2] else p2`).

### 2) FK 결과가 r만큼 어긋남 (중심에서 0.035 m)

- 원인: 구 중심을 팔꿈치 Eᵢ 그대로 두었습니다. 그러면 구하는 점이 이펙터 중심이 아니라 **볼조인트 쌍**이 되며, 세 팔에 대해 서로 다른 점이라 결과가 엉뚱해집니다.
- 해결: $Cᵢ = Eᵢ − r·uᵢ$로 옮깁니다. 이 한 줄이 델타 FK의 핵심입니다.

### 3) `Unreachable: no forward kinematic solution for theta=(...)`

- 원인: $h² < 0$ — 이 모터각 조합으로는 세 로드가 한 이펙터에 동시에 닿지 못합니다(조립 불가).
   `DeltaRobot.move_joints()`는 이것을 `WorkspaceError: 이 관절각 조합은 조립될 수 없습니다: ...`로 바꿔 알려 줍니다.
- 해결: 모터각을 독립적으로 마구 정하지 말고, 목표 위치를 정한 뒤 IK로 구합니다. l이 R − r + L에 비해 짧은 설계일수록
   한 모터만 크게 돌릴 때 이 오류가 잘 생깁니다(edu_dynamixel처럼 l이 충분히 길면 한계 안에서는 생기지 않습니다).

### 4) `Unreachable: sphere centres are collinear` / `ZeroDivisionError`

- 원인: 세 중심이 한 직선 위에 있어 ey를 만들 수 없습니다(직접 구현 시 `j = 0`으로 나눔). 실제 델타 치수에서는 거의 생기지 않지만,
   잘못된 설계값(예: R − r ≈ 0에 θ가 특수한 값)에서 나올 수 있습니다.
- 해결: `norm(t − i·ex)`가 아주 작으면 예외를 던지도록 방어 코드를 넣습니다(라이브러리처럼 `1e-12` 기준).

### 5) 각도를 도(°)로 넣어서 엉뚱한 위치

- 원인: `kin.fk(d, (20, 30, 10))`처럼 도 단위를 넣었습니다. 함수는 rad로 해석합니다(20 rad ≈ 1146°).
- 해결: `[math.radians(v) for v in (20, 30, 10)]`로 바꿉니다. `robot.move_joints(..., degrees=True)`는 변환을 대신해 줍니다.
