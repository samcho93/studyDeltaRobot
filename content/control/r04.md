## 학습 목표

- ROS 2 Humble(Ubuntu 22.04) 또는 Jazzy(Ubuntu 24.04)를 설치하고 환경을 `source`하는 이유를 설명합니다.
- `deltarobot` 라이브러리와 `delta_robot` 패키지를 설치·빌드합니다(`pip install -e`, `colcon build`).
- `display.launch.py`로 가상 모터(mock) 로봇을 띄우고, 노드·토픽·파라미터 구조를 `ros2` 명령으로 확인합니다.
- `/joint_states`에 모터 3개뿐 아니라 **수동 관절과 가상 이펙터 관절**까지 들어 있는 이유를 R05와 연결해 이해합니다.

## ROS 2를 쓰는 이유

R01~R03의 `DeltaRobot`은 한 프로그램 안에서 계획부터 전송까지 다 합니다. 실제 셀에는 카메라, 컨베이어 엔코더, PLC, 화면 등 여러 프로그램이 함께 돌아가고, 이들이 **표준 메시지로 느슨하게 연결**되어야 합니다. ROS 2는 그 연결을 맡습니다.

| 개념 | 뜻 | 이 패키지에서 |
|---|---|---|
| 노드(node) | 하나의 역할을 하는 프로세스 | `delta_driver`, `delta_commander`, `delta_web_bridge` |
| 토픽(topic) | 발행/구독 메시지 통로 | `/joint_states`, `/delta/goal`, `/delta/estop` |
| 서비스(service) | 요청-응답 호출 | `/delta/tool` (`std_srvs/SetBool`) |
| 파라미터(parameter) | 노드 설정값 | `preset`, `hardware`, `speed` |
| launch 파일 | 여러 노드를 인자와 함께 한 번에 실행 | `display.launch.py`, `bringup.launch.py` |

## 설치

### 1단계: ROS 2

공식 문서대로 설치합니다. 이 강의는 두 배포판을 모두 지원합니다.

| 배포판 | Ubuntu | 설치 문서 |
|---|---|---|
| Humble Hawksbill (LTS) | 22.04 | https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html |
| Jazzy Jalisco (LTS) | 24.04 | https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html |

`ros-<배포판>-desktop`(RViz 포함)을 설치하고, 빌드 도구도 함께 설치합니다.

```bash
sudo apt install python3-colcon-common-extensions python3-pip
sudo apt install ros-$ROS_DISTRO-robot-state-publisher ros-$ROS_DISTRO-rviz2 python3-serial
```

`$ROS_DISTRO`는 `source /opt/ros/humble/setup.bash`(또는 jazzy)를 한 터미널에서만 채워집니다. **새 터미널마다 source**해야 `ros2` 명령이 보입니다. 매번 하기 싫으면 `~/.bashrc` 끝에 한 줄 추가합니다.

:::info Windows 사용자
Windows 11에서는 **WSL2 + Ubuntu 22.04/24.04**에 설치하는 것이 가장 간단합니다. WSLg 덕분에 RViz 창도 뜨고, WSL2는 기본적으로 `localhost` 포트를 Windows와 공유하므로 R06의 웹 브리지(127.0.0.1:8765)에 Windows 브라우저로 접속할 수 있습니다. 실물 아두이노(USB)는 WSL2에서 `usbipd`로 연결해야 하므로, R07은 Windows 파이썬의 `serial` 백엔드로 하는 편이 쉽습니다.
:::

### 2단계: deltarobot 라이브러리

ROS 노드들은 기구학·URDF·궤적 계산을 복사하지 않고 **저장소의 `deltarobot`을 import**합니다. 그래서 라이브러리를 ROS가 쓰는 시스템 파이썬에 설치해야 합니다.

```bash
source /opt/ros/$ROS_DISTRO/setup.bash
git clone https://github.com/samcho93/studyDeltaRobot.git ~/studyDeltaRobot
cd ~/studyDeltaRobot

pip install -e "python[websim,serial]"                          # Ubuntu 22.04 (Humble)
pip install -e "python[websim,serial]" --break-system-packages  # Ubuntu 24.04 (Jazzy)

python3 -c "import deltarobot, websockets; print(deltarobot.__version__, websockets.__version__)"
```

`websockets`는 **12 이상**이어야 합니다. apt의 `python3-websockets`는 22.04에서 9.x, 24.04에서 10.x라 웹 브리지가 동작하지 않으므로 pip 버전을 씁니다.

:::warning Ubuntu 24.04의 시스템 파이썬
24.04는 시스템 파이썬에 pip 설치를 막습니다(`externally-managed-environment`). `--break-system-packages` 대신 ROS 패키지가 보이는 가상환경을 쓸 수도 있습니다: `python3 -m venv --system-site-packages ~/delta_venv && source ~/delta_venv/bin/activate` 후 설치. 이 경우 빌드·실행하는 **모든 터미널에서 venv를 activate**해야 합니다.
:::

### 3단계: 워크스페이스 빌드

ROS 2 워크스페이스는 `src/` 아래에 패키지를 두는 폴더입니다. 저장소에 이미 `ros2_ws/src/delta_robot`이 있으므로 그대로 빌드합니다.

```bash
cd ~/studyDeltaRobot/ros2_ws
colcon build --symlink-install
source install/setup.bash
ros2 pkg executables delta_robot
```

- `--symlink-install`은 파이썬 파일을 복사하지 않고 링크하므로, 노드 코드를 고친 뒤 다시 빌드하지 않아도 됩니다(launch·설정 파일을 새로 추가했을 때는 다시 빌드).
- 빌드 결과는 `build/`, `install/`, `log/`에 생깁니다. 이상하면 세 폴더를 지우고 다시 빌드합니다.
- 마지막 명령은 실행 파일 목록(`delta_commander`, `delta_driver`, `delta_pick_place_demo`, `delta_web_bridge`)을 보여 줍니다.

직접 새 워크스페이스를 만들고 싶다면 `mkdir -p ~/delta_ws/src`, `ln -s ~/studyDeltaRobot/ros2_ws/src/delta_robot ~/delta_ws/src/`로 링크한 뒤 `~/delta_ws`에서 빌드해도 됩니다.

## delta_robot 패키지 구조

```text
ros2_ws/src/delta_robot/
├── package.xml, setup.py, setup.cfg     # ament_python 패키지 정의
├── delta_robot/
│   ├── driver_node.py      # delta_driver: 모터(mock | serial), 한계·속도·비상정지 강제
│   ├── commander_node.py   # delta_commander: /delta/goal → 직선 궤적 → joint_command
│   ├── web_bridge_node.py  # delta_web_bridge: ws://127.0.0.1:8765 (websim과 같은 프로토콜)
│   ├── core.py             # ROS와 무관한 로직 (pytest로 시험)
│   ├── launch_util.py      # 두 launch 파일의 공통 부분 (URDF 생성 포함)
│   └── examples/pick_place_demo.py
├── launch/display.launch.py   # mock + RViz (+ web_bridge)
├── launch/bringup.launch.py   # serial(실물), RViz 끔
├── rviz/delta.rviz
└── config/design_example.json
```

## 노드와 토픽 그래프

@fig[r04-node-graph] delta_robot 패키지의 노드와 토픽. 모든 명령은 `delta_driver`를 거치며, 한계·속도 검사는 드라이버가 강제합니다.

- **`delta_driver`** — 로봇 하드웨어를 대표하는 유일한 노드입니다. `/delta/joint_command`(모터 3개 각도, rad)를 받아 모터를 움직이고, 100 Hz로 `/joint_states`, `/delta/tool_state`, `/delta/tcp`를 발행합니다. `hardware:=mock`이면 가상 모터가 "모터 최고 속도 ÷ 감속비"로 목표를 따라가고, `serial`이면 아두이노로 `J` 명령을 보냅니다. θ 한계 밖은 잘리고, 조립될 수 없는 각도 조합은 거부됩니다.
- **`delta_commander`** — `/delta/goal`(TCP 목표, `geometry_msgs/Point`, m)을 받아 직선 궤적을 계획하고 100 Hz로 `/delta/joint_command`를 흘려보냅니다. 툴은 서비스 `/delta/tool`로 켜고 끄며, 이동 중이면 이동이 끝난 뒤에 실행합니다. 이동 중에는 `/delta/busy`가 `true`입니다.
- **`robot_state_publisher`** — URDF와 `/joint_states`로 각 링크의 좌표 변환 `/tf`를 계산합니다(R05).
- **`delta_web_bridge`** — `web_bridge:=true`일 때만 뜹니다. 웹 시뮬레이터가 ROS 로봇을 보여 주게 합니다(R06).

## 실행과 확인

터미널 1 — 가상 모터 로봇 실행(이번 장은 RViz 없이):

```bash
source ~/studyDeltaRobot/ros2_ws/install/setup.bash
ros2 launch delta_robot display.launch.py preset:=edu_servo use_rviz:=false
```

드라이버가 시작하면서 설계 요약을 로그로 남깁니다(예시, 시각·PID 부분은 다름).

```text
[delta_driver-2] [INFO] [...] [delta_driver]: delta_driver: motor=rc_servo_mg996r tool=suction_20 hardware=mock vmax=6.00 rad/s theta=[-0.70, 1.50] rad
```

터미널 2 — 구조 살펴보기(새 터미널이므로 먼저 source):

```bash
source ~/studyDeltaRobot/ros2_ws/install/setup.bash
ros2 node list
ros2 topic list
ros2 topic info /delta/joint_command --verbose
ros2 topic hz /joint_states
ros2 param get /delta_driver preset
ros2 topic echo /joint_states --once
```

`ros2 node list`에는 `/delta_driver`, `/delta_commander`, `/robot_state_publisher`가 보여야 합니다. `ros2 topic list`에는 `/delta/busy`, `/delta/estop`, `/delta/goal`, `/delta/joint_command`, `/delta/tcp`, `/delta/tool_command`, `/delta/tool_state`, `/joint_states`, `/robot_description`, `/tf`, `/tf_static`과 ROS 기본 토픽(`/parameter_events`, `/rosout`)이 보입니다. `ros2 topic hz /joint_states`는 드라이버의 `rate` 파라미터(기본 100 Hz) 근처가 나옵니다.

`ros2 topic echo /joint_states --once` 결과 예시(홈 자세, `edu_servo`; 값은 `deltarobot.urdf.joint_state()`로 계산한 것과 같고, 시각은 생략):

```text
header:
  stamp:
    sec: ...
    nanosec: ...
  frame_id: ''
name:
- motor1_joint
- motor2_joint
- motor3_joint
- elbow1a_pitch
- elbow1a_yaw
- elbow2a_pitch
- elbow2a_yaw
- elbow3a_pitch
- elbow3a_yaw
- effector_x
- effector_y
- effector_z
position:
- 0.35
- 0.35
- 0.35
- 1.934000474151466
- 3.1540426835941956e-17
- 1.934000474151466
- -5.551115123125783e-17
- 1.934000474151466
- 1.6653345369377348e-16
- 2.7755575615628914e-17
- 6.938893903907228e-18
- -0.20066905209598637
velocity: []
effort: []
---
```

모터는 3개인데 이름이 12개입니다. 3개는 **능동 관절**(모터), 6개는 팔꿈치의 **수동 관절**(위팔에 대한 로드의 pitch·yaw), 3개는 이펙터 중심 위치를 나타내는 **가상 직선 관절**입니다. 드라이버가 모터각으로 순기구학을 풀어 전부 채웁니다. `effector_z` −0.2007 m는 R01에서 본 홈 자세의 이펙터 중심 높이와 같습니다. 왜 이렇게 해야 하는지는 R05에서 다룹니다.

:::tip 그래프 그림으로 보기
`rqt_graph`(패키지 `ros-$ROS_DISTRO-rqt-graph`)를 실행하면 위 그림과 같은 노드-토픽 그래프를 실제 실행 상태로 볼 수 있습니다. 노드가 안 보이면 새로고침 버튼을 누르세요.
:::

### 한 번 움직여 보기

```bash
ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: 0.03, y: 0.0, z: -0.25}"
ros2 topic echo /delta/tcp --once
```

`/delta/tcp`가 (0.03, 0, −0.25) 근처로 바뀌면 성공입니다. 목표는 **TCP(툴 끝)** 기준, 단위는 m입니다. 자세한 제어는 R06에서 합니다.

:::check 체크포인트
- [ ] `ros2 pkg executables delta_robot`에 실행 파일 4개가 보인다.
- [ ] `ros2 node list`에 노드 3개가 보이고 `/joint_states`가 약 100 Hz로 발행된다.
- [ ] `/joint_states`의 이름 12개가 무엇인지 설명할 수 있다.
:::

## 자주 나는 오류와 해결

### `ros2: command not found` / `Package 'delta_robot' not found`

- **원인**: 이 터미널에서 `source /opt/ros/$ROS_DISTRO/setup.bash`나 `source install/setup.bash`를 하지 않았습니다. 빌드한 터미널이 아닌 새 터미널에서 흔합니다.
- **해결**: 두 파일을 순서대로 source합니다. `echo $ROS_DISTRO`로 확인합니다.

### `ModuleNotFoundError: No module named 'deltarobot'`

- **원인**: 라이브러리를 설치하지 않았거나, 다른 파이썬(venv)에 설치했습니다. 노드는 `/usr/bin/python3`로 실행됩니다.
- **해결**: `python3 -c "import deltarobot"`가 되는 환경을 만듭니다(2단계). venv를 썼다면 launch하는 터미널에서도 activate합니다.

### `error: externally-managed-environment`

- **원인**: Ubuntu 24.04가 시스템 파이썬에 대한 pip 설치를 막았습니다.
- **해결**: `--break-system-packages`를 붙이거나 `--system-site-packages` venv를 씁니다.

### `ModuleNotFoundError: No module named 'websockets.sync'` 또는 `delta_web_bridge needs websockets>=12`

- **원인**: apt의 오래된 `python3-websockets`가 쓰이고 있습니다.
- **해결**: `pip install "websockets>=12"`(24.04는 `--break-system-packages`). 버전을 다시 확인합니다.

### `colcon build`가 `setup.py` 관련 경고를 냄

- **원인**: 배포판의 setuptools 버전에 따라 `setup.py install is deprecated` 같은 경고가 나올 수 있습니다. 경고일 뿐 빌드는 성공합니다(마지막 줄 `Summary: 1 package finished`를 확인).
- **해결**: 실제 에러(`Failed`)가 있을 때만 `log/latest_build/delta_robot/stdout_stderr.log`를 읽습니다.

### `/delta/goal`을 보냈는데 움직이지 않음

- **원인**: 작업영역 밖 목표입니다. 커맨더 터미널에 `goal (...) rejected: ...` 에러 로그가 남습니다. 흔한 실수는 mm 단위, z 부호(작업은 z < 0), 다른 프리셋의 좌표입니다.
- **해결**: `edu_servo` 홈 자세의 TCP z는 약 −0.246 m입니다. 그 근처에서 조금씩 움직여 봅니다.

## 과제

:::task 개인 과제
1. `ros2 topic list -t`로 토픽과 메시지 타입을 표로 정리하고, 각 토픽의 발행 노드·구독 노드를 `ros2 topic info -v`로 확인해 그림 R04와 비교합니다.
2. `preset:=edu_dynamixel`로 다시 실행해 `ros2 topic echo /delta/tcp --once`로 홈 자세 TCP 높이를 읽고, R01 방식(Playground)으로 계산한 값과 비교합니다.
3. `ros2 param list /delta_commander`로 파라미터를 확인하고 `ros2 param set /delta_commander speed 0.1` 전후로 같은 goal의 이동 시간을 `ros2 topic echo /delta/busy`로 비교합니다.
:::
