## 학습 목표

- PC에 `deltarobot`을 설치하고 `websim` 백엔드에 필요한 `websockets`를 함께 설치합니다.
- `DeltaRobot(backend="websim")`이 **PC에 작은 WebSocket 서버**를 열고 웹 시뮬레이터가 거기에 접속하는 구조를 설명합니다.
- R02의 분류 프로그램을 **한 글자도 바꾸지 않고** 실시간으로 웹 시뮬레이터에서 돌립니다.
- 시뮬레이터의 비상정지가 파이썬에서 `EmergencyStop` 예외가 되는 흐름을 확인하고, 연결 문제를 스스로 진단합니다.

## 왜 PC 파이썬인가

Playground(`record` 백엔드)는 동작을 **먼저 계산한 뒤 재생**합니다. 실물 로봇은 그렇게 움직이지 않습니다. 명령이 시간에 맞춰 흘러가고, 중간에 비상정지가 들어올 수 있고, 프로그램이 도는 동안 센서나 다른 프로그램과 주고받아야 합니다. `websim` 백엔드는 이 **실시간 흐름**을 실물 없이 연습하게 해 줍니다.

- 모터각을 10 ms마다 **벽시계에 맞춰** 보냅니다. 6개 분류는 실제로 약 14초가 걸립니다.
- `robot.time`은 가상 시간이 아니라 로봇을 만든 뒤 흐른 **실제 시간**입니다.
- 시뮬레이터 상단의 비상정지 버튼을 누르면 파이썬 프로그램이 멈춥니다.

## 연결 구조

브라우저는 보안상 PC에 서버를 열 수 없으므로, **파이썬이 서버**(`ws://127.0.0.1:8765`)가 되고 **시뮬레이터가 클라이언트**로 접속합니다. 주소가 `127.0.0.1`(루프백)이라 같은 PC 안에서만 연결되고, 다른 컴퓨터에서는 접속할 수 없습니다.

@fig[r03-websim] 파이썬이 서버를 열고 기다리면, 시뮬레이터가 접속해 설계·장면을 주고받은 뒤 모터각 상태를 실시간으로 받습니다.

1. 파이썬이 서버를 열고 최대 `wait_connect`(기본 60 s) 동안 기다립니다.
2. 시뮬레이터 **연결** 탭의 **[PC Python 연결]** 을 누르면 접속하고 `hello`(시뮬레이터의 현재 설계·장면)를 보냅니다.
3. 파이썬은 설계를 정해(R01의 규칙과 같음: 설계를 비우면 시뮬레이터 것을 사용) `design` 메시지로 돌려보내고, 시뮬레이터는 그 설계·장면으로 바뀝니다.
4. 이후 파이썬은 `state {t, q, tool}`을 10 ms마다 보내고, 시뮬레이터는 받은 모터각으로 로봇을 그립니다.
5. 비상정지 버튼을 누르면 시뮬레이터가 `estop`을 보내고, 파이썬의 다음 동작 확인 시점에 `EmergencyStop`이 발생합니다.

같은 포트와 같은 메시지 형식을 R06의 ROS 2 `delta_web_bridge`도 씁니다. 그래서 시뮬레이터는 상대가 파이썬 스크립트인지 ROS 2인지 구분하지 않습니다.

## 설치

Python 3.9 이상이 필요합니다. 저장소를 받은 뒤 **저장소 루트**에서 설치합니다.

```bash
git clone https://github.com/samcho93/studyDeltaRobot.git
cd studyDeltaRobot
python -m venv .venv
# Windows:  .venv\Scripts\activate      Linux/macOS:  source .venv/bin/activate
pip install -e "python[websim]"       # deltarobot + websockets>=12
python -c "import deltarobot, websockets; print(deltarobot.__version__, websockets.__version__)"
```

`-e`(editable)로 설치하면 `python/deltarobot/`을 고쳤을 때 다시 설치하지 않아도 바로 반영됩니다. 따옴표는 셸이 `[websim]`을 파일 패턴으로 해석하지 않게 하려고 붙입니다.

## 실습: 분류 프로그램을 실시간으로

`sort_websim.py`로 저장합니다. R02 프로그램에서 **`backend="websim"`만 추가**하고, 비상정지 처리와 `close()`를 넣었습니다.

```python robot
# sort_websim.py — python sort_websim.py 실행 후 시뮬레이터에서 [PC Python 연결]
from deltarobot import DeltaRobot, EmergencyStop, WorkspaceError

robot = DeltaRobot("edu_servo", backend="websim")
print(robot)
try:
    robot.home()
    surface = robot.scene.data["surface_z"]
    bin_of = {b["color"]: b for b in robot.bins()}
    for part in robot.parts():
        b = bin_of[part["color"]]
        robot.arch_to(part["x"], part["y"], part["top"])
        robot.tool_on()
        robot.wait(0.1)
        robot.arch_to(b["x"], b["y"], surface + b["h"] + part["h"] + 0.005)
        robot.tool_off()
        print("%s -> %s  (%.1f s)" % (part["id"], b["id"], robot.time))
    robot.home()
    print("점수:", robot.scene.score())
except EmergencyStop as e:
    print("비상정지:", e)
finally:
    robot.close()
```

순서:

1. 터미널에서 `python sort_websim.py`를 실행합니다. 대기 메시지가 나옵니다.
2. 브라우저에서 시뮬레이터를 열고 **연결** 탭 → **[PC Python 연결]** 을 누릅니다(60초 안에).
3. 시뮬레이터가 `edu_servo` 설계와 분류 장면으로 바뀌고 로봇이 움직입니다.

@btn[~/sim/index.html] 시뮬레이터 열기

콘솔 출력(초 단위 시각은 실행마다 조금씩 다릅니다):

```text

p1 -> A  (2.3 s)
```

Playground의 가상 시간(R02: 2.30 s, 4.79 s, …)과 거의 같은 시각에 사이클이 끝납니다. 계획한 궤적 시간을 실제 시간에 맞춰 내보내기 때문입니다. 약간 늦는 것은 계산·전송 지연입니다.

:::info 설계를 시뮬레이터에서 가져오기
`DeltaRobot(backend="websim")`처럼 설계를 비우면 시뮬레이터 설계 탭에서 만든 설계와 현재 장면을 그대로 씁니다. 설계 탭에서 암 길이를 바꾼 뒤 같은 스크립트를 다시 실행하면, 코드 수정 없이 **새 설계로 같은 작업**을 검증할 수 있습니다. 단, `analyze()`는 `record` 백엔드 전용이므로 모터 검증은 Playground나 시뮬레이터 분석 탭에서 합니다.
:::

:::tip Chrome의 로컬 네트워크 접근 허용
GitHub Pages(https)의 페이지가 `127.0.0.1`에 접속하면, 최근 Chrome은 이 사이트가 **이 기기의 다른 앱·서비스(로컬 네트워크)에 접근하도록 허용할지** 묻습니다. **허용**을 눌러야 연결됩니다. 실수로 차단했다면 주소창 왼쪽 사이트 정보 아이콘 → 사이트 설정에서 해당 권한을 허용으로 바꾸고 새로고침합니다. `http://localhost:8000`(`python build.py --serve`)으로 연 로컬 미리보기에서는 이 창이 뜨지 않을 수 있습니다.
:::

## 비상정지 확인

위 스크립트를 다시 실행하고, 로봇이 움직이는 중에 시뮬레이터 상단의 **비상정지** 버튼을 누릅니다.

```text
[websim] ws://127.0.0.1:8765 에서 대기 중 — 시뮬레이터 '연결' 탭에서 [PC Python 연결]을 누르세요
[websim] 시뮬레이터 연결됨
DeltaRobot(motor=rc_servo_mg996r, tool=suction_20, backend=WebSimBackend)
p1 -> A  (2.3 s)
[websim] 비상정지 수신!
비상정지: 비상정지 요청을 받았습니다 — 프로그램을 멈춥니다
[websim] 시뮬레이터 연결 끊김
```

- 백엔드는 모터각 샘플을 보내기 **직전마다** 비상정지 플래그를 확인합니다. 그래서 늦어도 다음 10 ms 샘플에서 멈춥니다.
- 비상정지 뒤에는 그 `robot` 객체의 모든 동작 명령이 계속 `EmergencyStop`을 냅니다. 원인을 없앤 뒤 **프로그램을 다시 시작**하는 것이 규칙입니다. 실물에서도 같은 습관이 필요합니다.
- `except EmergencyStop`에서 로봇을 다시 움직이는 코드를 넣지 마세요. 비상정지는 "정지"만 해야 합니다.

:::warning 시뮬레이터의 비상정지는 실물 안전장치가 아닙니다
이 버튼은 **소프트웨어 신호**입니다. R07의 실물 실습에서는 서보 전원을 직접 끊는 하드웨어 비상정지(전원 스위치)를 반드시 따로 둡니다.
:::

## 자주 나는 오류와 해결

### `RuntimeError: websim 백엔드에는 websockets>=12 가 필요합니다: pip install "websockets>=12"`

- **원인**: `pip install -e python`만 하고 `[websim]` 옵션을 빠뜨렸거나, 가상환경이 다릅니다.
- **해결**: 같은 가상환경에서 `pip install -e "python[websim]"`. `python -m pip ...`으로 실행하면 인터프리터가 섞이지 않습니다.

### `OSError: [Errno 10048] 각 소켓 주소(프로토콜/네트워크 주소/포트)는 하나만 사용할 수 있습니다 (while attempting to bind on address ('127.0.0.1', 8765))`

- **원인**(Windows): 8765 포트를 이미 누가 쓰고 있습니다. 앞에서 실행한 스크립트가 아직 대기 중이거나, R06의 ROS 2 `delta_web_bridge`가 떠 있습니다. Linux에서는 `OSError: [Errno 98] Address already in use (while attempting to bind on address ('127.0.0.1', 8765))`로 나옵니다.
- **해결**: 이전 프로그램을 `Ctrl+C`로 끕니다. 누가 쓰는지는 Windows `netstat -ano | findstr :8765`, Linux `ss -ltnp | grep 8765`로 찾습니다. 시뮬레이터는 8765번으로 접속하므로 포트를 바꾸기보다 **이전 프로그램을 끄는 것**이 해결책입니다.

### `TimeoutError: 60 초 안에 시뮬레이터가 연결되지 않았습니다`

- **원인**: 60초 안에 [PC Python 연결]을 누르지 않았거나, 브라우저가 접속하지 못했습니다(아래 403, Chrome 권한 거부).
- **해결**: 시뮬레이터를 먼저 열어 두고 스크립트를 실행합니다. 더 기다리려면 `DeltaRobot(..., backend="websim", wait_connect=180)`을 씁니다.

### 시뮬레이터가 접속하지 못함 (브라우저 콘솔에 HTTP 403)

- **원인**: 백엔드는 허용된 출처(`https://samcho93.github.io`, `http://localhost`, `http://127.0.0.1`)의 페이지만 받아들이고, 나머지는 `403 origin not allowed`로 거절합니다. 시뮬레이터 HTML을 **파일로 직접 연 경우**(`file://...`) 출처가 `null`이라 거절됩니다.
- **해결**: 강의 사이트에서 열거나, 저장소 루트에서 `python build.py --serve` 후 `http://localhost:8000/sim/index.html`로 엽니다.

### 로봇이 끊기며 움직임 / `경고: 관절 속도 ...`

- **원인**: PC가 바쁘면 10 ms 간격을 못 지켜 화면이 끊깁니다. 경고는 R02와 같은 속도 초과입니다.
- **해결**: 다른 무거운 프로그램을 닫고, 속도 경고는 `set_speed()`로 없앱니다. `websim`은 경고만 하지만 실물 백엔드는 거부합니다.

## 과제

:::task 개인 과제
1. `DeltaRobot(backend="websim")`(설계 생략)으로 바꾸고, 시뮬레이터 설계 탭에서 `edu_dynamixel` 프리셋을 고른 뒤 실행해 봅니다. 콘솔의 `DeltaRobot(motor=...)` 출력과 사이클 시간이 어떻게 바뀌는지 기록합니다.
2. 사이클마다 `robot.time`으로 측정한 실제 시간과, 같은 코드를 `record` 백엔드로 돌린 가상 시간을 표로 비교하고 차이의 원인을 설명합니다.
3. `with DeltaRobot("edu_servo", backend="websim") as robot:` 형태로 바꿔 `finally: robot.close()` 없이도 연결이 정리되는지 확인합니다.
:::
