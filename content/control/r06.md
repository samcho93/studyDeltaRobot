## 학습 목표

- `/delta/goal` 토픽과 `/delta/tool` 서비스로 명령줄과 rclpy 노드에서 로봇을 움직입니다.
- 같은 `DeltaRobot` 코드를 `backend="ros2"`로 바꿔 ROS 2 드라이버에서 실행하고, 커맨더 경로와의 차이를 설명합니다.
- `delta_web_bridge`로 웹 시뮬레이터를 ROS 2 로봇의 화면으로 씁니다.
- `/delta/estop`의 동작(드라이버 정지·커맨더 큐 비움·파이썬 `EmergencyStop`·해제 절차)을 확인합니다.

## 로봇을 움직이는 세 가지 길

@fig[r06-paths] 명령줄의 goal 토픽과 tool 서비스, 또는 파이썬 `ros2` 백엔드. 어느 길이든 마지막에는 `delta_driver`가 한계를 검사합니다.

| 방법 | 누가 궤적을 계획하나 | 좋은 점 | 한계 |
|---|---|---|---|
| `/delta/goal` + `/delta/tool` | `delta_commander` (직선) | 어떤 언어·도구로도 보낼 수 있음 | 직선 이동만, 아치·관절 이동 없음 |
| `DeltaRobot(backend="ros2")` | 파이썬 라이브러리 (아치·직선·관절) | R01~R03 코드를 그대로 사용 | 파이썬 필요, 커맨더와 동시에 쓰면 안 됨 |
| 직접 `/delta/joint_command` 발행 | 여러분의 노드 | 완전한 자유 | 궤적·IK를 직접 만들어야 함 |

어느 길이든 `delta_driver`가 θ 한계, 조립 가능 여부, 모터 속도 제한을 **다시** 강제합니다. 클라이언트가 실수해도 드라이버에서 막히도록 한 것이 CLAUDE.md의 안전 원칙입니다.

## 실습 1: 명령줄로 제어

터미널 1:

```bash
source ~/studyDeltaRobot/ros2_ws/install/setup.bash
ros2 launch delta_robot display.launch.py preset:=edu_servo
```

터미널 2 — 목표 이동, 툴, 상태:

```bash
source ~/studyDeltaRobot/ros2_ws/install/setup.bash
ros2 topic echo /delta/busy &          # 이동 중 true
ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: -0.0617, y: -0.0336, z: -0.25}"
ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: -0.0617, y: -0.0336, z: -0.276}"
ros2 service call /delta/tool std_srvs/srv/SetBool "{data: true}"
ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: -0.0617, y: -0.0336, z: -0.25}"
ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: 0.0561, y: -0.0404, z: -0.25}"
ros2 service call /delta/tool std_srvs/srv/SetBool "{data: false}"
ros2 topic echo /delta/tool_state --once
```

좌표는 R02의 부품 p1과 상자 A 위치입니다(TCP 기준, m). 커맨더의 동작 규칙:

- goal은 **직선**으로 갑니다. 아치 동작은 "위로 → 수평 → 아래로" goal 세 개로 나눠 보냅니다.
- 이동 중에 들어온 goal은 **큐에 쌓여** 앞 동작이 끝난 위치에서 이어서 계획됩니다.
- `/delta/tool` 서비스는 이동 중이면 큐에 넣어 **이동이 끝난 뒤** 실행하고 `tool on queued after current motion` 메시지로 응답합니다. 멈춰 있으면 바로 실행합니다.
- 목표나 경로 중간이 한계를 넘거나 관절 속도가 모터 한계를 넘으면 goal 전체를 **거부**하고 커맨더 터미널에 `goal (...) rejected: ...` 에러 로그를 남깁니다.

속도와 프로파일은 커맨더 파라미터로 바꿉니다(0이면 설계 기본값).

```bash
ros2 param set /delta_commander speed 0.1
ros2 param set /delta_commander profile quintic
```

## 실습 2: rclpy 노드로 순서 제어

명령줄에서 goal과 서비스를 연달아 보내면, 토픽과 서비스는 서로 다른 통로라 **도착 순서가 보장되지 않습니다.** 노드에서 `/delta/busy`가 `false`가 될 때까지 기다리며 보내면 확실합니다.

```python robot
# delta_sequence.py — source install/setup.bash 후 python3 delta_sequence.py
import time
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Point
from std_msgs.msg import Bool
from std_srvs.srv import SetBool


class Sequence(Node):
    def __init__(self):
        super().__init__("delta_sequence")
        self.busy = False
        self.pub = self.create_publisher(Point, "/delta/goal", 10)
        self.create_subscription(Bool, "/delta/busy", self.on_busy, 10)
        self.tool = self.create_client(SetBool, "/delta/tool")
        while not self.tool.wait_for_service(timeout_sec=1.0):
            self.get_logger().info("waiting for /delta/tool ...")

    def on_busy(self, msg):
        self.busy = msg.data

    def spin_for(self, seconds):
        end = time.monotonic() + seconds
        while time.monotonic() < end:
            rclpy.spin_once(self, timeout_sec=0.02)

    def goto(self, x, y, z):
        self.pub.publish(Point(x=x, y=y, z=z))
        self.spin_for(0.3)                       # 커맨더가 받아 busy=true가 될 시간
        while self.busy:
            rclpy.spin_once(self, timeout_sec=0.05)

    def set_tool(self, on):
        fut = self.tool.call_async(SetBool.Request(data=on))
        rclpy.spin_until_future_complete(self, fut)
        self.get_logger().info(fut.result().message)


def main():
    rclpy.init()
    n = Sequence()
    part, box, up, z_pick, z_place = (-0.0617, -0.0336), (0.0561, -0.0404), -0.25, -0.276, -0.264
    n.goto(part[0], part[1], up)
    n.goto(part[0], part[1], z_pick)
    n.set_tool(True)
    n.spin_for(0.3)                              # 흡착 안정
    n.goto(part[0], part[1], up)
    n.goto(box[0], box[1], up)
    n.goto(box[0], box[1], z_place)
    n.set_tool(False)
    n.goto(0.0, 0.0, up)
    n.destroy_node()
    rclpy.shutdown()


if __name__ == "__main__":
    main()
```

`/delta/busy`는 값이 바뀔 때와 10 Hz 주기로 발행되므로, goal 직후 잠깐 기다린 뒤 `false`가 될 때까지 도는 방식이 간단하고 튼튼합니다.

## 실습 3: 같은 파이썬 코드를 ROS 2에서 — backend="ros2"

`ros2` 백엔드는 라이브러리가 아치·직선·관절 궤적을 계획해 `/delta/joint_command`로 100 Hz 스트리밍하고, `/delta/tool_command`로 툴을 켜고 끕니다. **커맨더를 거치지 않습니다.** R02의 분류 프로그램에서 한 줄만 바꿉니다.

```python robot
# sort_ros2.py — source install/setup.bash 후 python3 sort_ros2.py
from deltarobot import DeltaRobot, EmergencyStop, WorkspaceError

robot = DeltaRobot("edu_servo", backend="ros2", scene="pick_place")   # launch와 같은 preset!
try:
    robot.home()
    surface = robot.scene.data["surface_z"]
    bin_of = {b["color"]: b for b in robot.bins()}
    for part in robot.parts():
        b = bin_of[part["color"]]
        try:
            robot.arch_to(part["x"], part["y"], part["top"])
            robot.tool_on()
            robot.wait(0.3)
            robot.arch_to(b["x"], b["y"], surface + b["h"] + part["h"] + 0.005)
            robot.tool_off()
            robot.wait(0.2)
            print("%s -> %s  (%.1f s)" % (part["id"], b["id"], robot.time))
        except WorkspaceError as e:
            print(part["id"], "건너뜀:", e)
    robot.home()
    print("점수(파이썬 쪽 장면):", robot.scene.score())
except EmergencyStop as e:
    print("비상정지:", e)
finally:
    robot.close()
```

패키지에 들어 있는 예제도 같은 방식입니다: `ros2 run delta_robot delta_pick_place_demo --preset edu_servo --cycles 3`.

:::warning ros2 백엔드 사용 규칙
- **launch와 같은 설계**(`preset`/`design_file`)를 씁니다. 다르면 같은 모터각이 다른 위치를 뜻합니다.
- 라이브러리는 로봇이 **홈 자세에서 시작한다고 가정**합니다(모터 피드백을 읽지 않음). 앞에서 goal로 로봇을 옮겨 두었다면 먼저 `ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: 0.0, y: 0.0, z: -0.2457}"`로 홈(`edu_servo`의 홈 TCP)에 돌려놓고 실행합니다. 그렇지 않으면 첫 명령에서 드라이버가 속도 제한으로 천천히 따라가긴 하지만 계획과 다른 경로로 움직입니다.
- 스크립트가 도는 동안 `/delta/goal`을 보내지 않습니다. 두 곳에서 동시에 `/delta/joint_command`를 발행하게 됩니다.
- `record`·`websim`과 달리 관절 속도가 모터 한계를 넘는 동작은 **`WorkspaceError`로 거부**됩니다. R02의 속도 분석을 먼저 통과한 설정을 쓰세요.
- `robot.parts()`와 `score()`는 파이썬 안의 장면 모델입니다. 실물 부품을 보는 것이 아닙니다.
:::

## 실습 4: 웹 브리지 — 웹 시뮬레이터를 ROS 2 화면으로

`delta_web_bridge`는 R03의 `websim` 백엔드와 **같은 포트(127.0.0.1:8765), 같은 메시지 형식**의 WebSocket 서버입니다. 그래서 시뮬레이터의 **[PC Python 연결]** 버튼으로 ROS 로봇에 붙습니다.

```bash
ros2 launch delta_robot display.launch.py preset:=edu_servo web_bridge:=true scene:=pick_place
```

1. 브라우저에서 시뮬레이터를 열고 **연결** 탭 → **[PC Python 연결]** 을 누릅니다.
2. 브리지가 launch의 설계와 장면(`scene` 인자)을 보내므로 시뮬레이터가 `edu_servo`와 분류 장면으로 바뀌고, 브리지 터미널에 `simulator connected` 로그가 남습니다.
3. 실습 1~3의 명령을 다시 실행하면 RViz와 웹 시뮬레이터가 **같은 움직임**을 보여 줍니다. 브리지는 `/joint_states`의 모터각과 `/delta/tool_state`를 최대 50 Hz로 보냅니다.

@btn[~/sim/index.html] 시뮬레이터 열기

브리지가 하는 일은 번역뿐입니다.

| 방향 | 웹 시뮬레이터 메시지 | ROS 2 |
|---|---|---|
| 브라우저 → 브리지 | `{"type":"hello", ...}` | 설계·장면을 `design` 메시지로 응답 |
| 브리지 → 브라우저 | `{"type":"state","t","q","tool"}` | `/joint_states`(모터 3개) + `/delta/tool_state` |
| 브라우저 → 브리지 | `{"type":"estop"}` | `/delta/estop` ← `Bool(true)` |
| 브라우저 → 브리지 | `{"type":"goal","xyz":[x,y,z]}` | `/delta/goal` ← `Point` (TCP, m) |

:::info websim 스크립트와 동시에 쓸 수 없습니다
둘 다 8765 포트에 서버를 엽니다. 브리지가 떠 있는 상태에서 R03 스크립트를 실행하면 `OSError: [Errno 98] Address already in use ...`가 납니다. 한 번에 하나만 씁니다.
:::

## 비상정지

```bash
ros2 topic pub --once /delta/estop std_msgs/msg/Bool "{data: true}"    # 정지
ros2 topic pub --once /delta/estop std_msgs/msg/Bool "{data: false}"   # 해제
```

`true`를 받으면:

- **드라이버**: 현재 자세에서 멈추고(목표 = 현재 위치), 툴을 끄고, 이후 명령을 무시하며 `e-stop active: command ignored (publish False on /delta/estop)` 경고를 남깁니다. `hardware:=serial`이면 아두이노에 `E`를 보냅니다(R07).
- **커맨더**: 남은 이동 큐를 비웁니다(`e-stop: motion queue cleared`).
- **파이썬 `ros2` 백엔드**: 다음 샘플을 보내기 전에 `EmergencyStop`이 발생해 프로그램이 멈춥니다.
- **웹 시뮬레이터**의 비상정지 버튼도 브리지를 통해 같은 `true`를 발행합니다.

해제는 `false`를 **사람이 직접** 발행합니다. 드라이버는 해제 시 현재 자세를 유지한 채 명령을 다시 받기 시작하고, 파이썬 프로그램은 다시 실행해야 합니다. 시뮬레이터에서 비상정지를 눌렀다면 해제는 터미널에서 합니다.

:::check 체크포인트
- [ ] 명령줄 goal·tool로 부품 p1을 상자 A 위로 옮겼다.
- [ ] rclpy 노드가 동작을 순서대로 끝냈다.
- [ ] `sort_ros2.py`가 RViz와 웹 시뮬레이터에서 같은 동작을 보였다.
- [ ] 비상정지 후 goal이 무시되고, `false` 발행 후 다시 움직였다.
:::

## 자주 나는 오류와 해결

### 커맨더 로그 `no /joint_states yet — is delta_driver running?`

- **원인**: 드라이버가 없거나 아직 시작 중입니다. 커맨더는 현재 모터각을 `/joint_states`에서 받아야 계획할 수 있습니다.
- **해결**: launch 전체를 다시 띄우고 `ros2 topic hz /joint_states`를 확인합니다.

### 커맨더 로그 `goal (...) rejected: ... exceeds motor limit ... — lower 'speed'`

- **원인**: 직선 경로 중 관절 속도가 모터 한계를 넘습니다(작업영역 가장자리, 큰 이동).
- **해결**: `ros2 param set /delta_commander speed 0.1`처럼 낮춥니다.

### 드라이버 로그 `e-stop active: command ignored (publish False on /delta/estop)`

- **원인**: 비상정지 상태입니다(시뮬레이터 버튼을 눌렀을 수도 있습니다).
- **해결**: 원인을 확인한 뒤 `ros2 topic pub --once /delta/estop std_msgs/msg/Bool "{data: false}"`.

### 파이썬 `RuntimeError: ros2 백엔드는 ROS 2 환경(source /opt/ros/<distro>/setup.bash)에서 실행하세요`

- **원인**: ROS를 source하지 않은 터미널이라 `rclpy`를 import할 수 없습니다.
- **해결**: `source /opt/ros/$ROS_DISTRO/setup.bash`와 `source install/setup.bash` 후 실행합니다.

### 파이썬 `WorkspaceError: 관절 속도 ... rad/s 가 모터 한계 ... rad/s(감속 후)를 넘습니다 — set_speed()로 속도를 낮추세요`

- **원인**: `ros2` 백엔드는 속도 초과를 거부합니다. Playground에서 경고만 보고 넘어간 설정입니다.
- **해결**: `robot.set_speed()`로 낮추고, Playground의 `analyze()`로 먼저 검증합니다.

### 시뮬레이터가 연결되지 않음

- **원인**: `web_bridge:=true`를 빠뜨렸거나, 8765 포트를 다른 프로그램(R03 스크립트)이 쓰고 있거나, 브라우저 권한·출처 문제입니다(R03 참고).
- **해결**: 브리지 터미널에 `web bridge on ws://127.0.0.1:8765` 로그가 있는지 봅니다. 다른 출처에서 접속하면 `rejected connection from origin ...` 경고가 남습니다.

## 과제

:::task 개인 과제
1. rclpy 노드를 고쳐 R02의 부품 6개를 모두 색에 맞는 상자로 옮기는 명령 시퀀스를 만들고, 사이클 시간을 `sort_ros2.py`(아치 궤적)와 비교합니다.
2. `/delta/tcp`를 구독해 TCP 궤적을 CSV로 저장하는 노드를 작성하고, 커맨더 goal(직선 세 번)과 `arch_to`(둥근 모서리 아치)의 경로 모양을 그래프로 비교합니다.
3. `sort_ros2.py` 실행 중 웹 시뮬레이터의 비상정지 버튼을 눌러 드라이버·커맨더·파이썬 세 곳의 로그를 캡처하고, 해제 절차를 순서대로 적습니다.
:::
