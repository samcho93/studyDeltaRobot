## 학습 목표

- `edu_servo` 설계(3D 프린팅 + MG996R)의 부품을 준비하고, 서보 전원과 신호를 **공통 접지**로 안전하게 배선합니다.
- `firmware/delta_servo` 스케치를 올리고 시리얼 모니터에서 `J`·`T`·`E`·`R`·`?` 프로토콜을 직접 시험합니다.
- 영점(위팔 수평 = 0°)·방향(아래로 +)·펄스 기울기를 캘리브레이션해 **라이브러리의 θ와 실물 팔의 각도**를 일치시킵니다.
- Playground 드라이런으로 검증한 코드를 `backend="serial"`로 바꿔 실물에서 실행합니다.

## 배선

@fig[r07-wiring] 신호는 아두이노 D9·D10·D11(서보), D7(툴). 서보 전원은 별도 6 V로 공급하고 GND를 반드시 공통으로 묶습니다.

| 신호 | 아두이노 핀 | 연결 |
|---|---|---|
| 서보 1 (팔 1, +x 방향, φ = 0°) | D9 | MG996R 주황(신호) |
| 서보 2 (팔 2, φ = 120°) | D10 | MG996R 주황 |
| 서보 3 (팔 3, φ = 240°) | D11 | MG996R 주황 |
| 툴 출력 | D7 | MOSFET 게이트(220 Ω 직렬, 10 kΩ 풀다운) 또는 릴레이 모듈 IN |
| 서보 전원 + | — | 6 V 전원 → 서보 빨강 (전원 스위치 경유) |
| GND | GND | 서보 전원 GND ↔ 아두이노 GND ↔ 툴 전원 GND **공통** |

- **팔 번호와 핀 순서를 지킵니다.** 팔 1이 +x 방향이고, 위에서 볼 때 반시계 방향으로 팔 2(120°), 팔 3(240°)입니다. 순서가 바뀌면 IK가 엉뚱한 팔을 움직입니다.
- MG996R은 멈춰서 힘을 받을 때(stall) 한 개에 2 A 이상 흐를 수 있어, USB 전원으로는 아두이노가 리셋됩니다.
- 펌프·전자석은 유도성 부하라 끌 때 역기전력이 생깁니다. 다이오드를 부하 양단에 **캐소드를 + 쪽으로** 답니다.
- active-LOW 릴레이 모듈이면 스케치의 `TOOL_ACTIVE_HIGH = false`로 바꿉니다.

## 펌웨어 올리기와 프로토콜 시험

1. Arduino IDE에서 `firmware/delta_servo/delta_servo.ino`를 열고 보드(Uno/Nano)와 포트를 고른 뒤 업로드합니다. 표준 `Servo` 라이브러리만 씁니다.
2. 시리얼 모니터를 **115200 baud, 줄 끝 "새 줄(Newline)"** 로 엽니다. 부팅하면 `READY delta_servo`가 나오고 서보가 20°(홈, 0.35 rad)로 갑니다.
3. 아래 명령을 한 줄씩 보냅니다.

| 명령 | 뜻 | 응답 |
|---|---|---|
| `J d1 d2 d3` | 모터 목표각[°] (0 = 수평, + = 아래) | 없음 |
| `T 1` / `T 0` | 툴 켬 / 끔 | 없음 |
| `?` | 상태 | `OK d1 d2 d3 tool` |
| `E` | 비상정지: 서보 힘 풀림(detach), 툴 끔, 이후 `J`·`T` 무시 | `ESTOP` |
| `R` | 비상정지 해제: 마지막 각도로 다시 힘을 줌 | `READY` |

- 잘못된 명령에는 `ERR ...`(예: `ERR J needs 3 numbers`, 비상정지 중 `ERR estop (send R)`)로 답합니다.
- 줄 맨 앞의 `E`는 줄바꿈을 기다리지 않고 **즉시** 실행됩니다.
- 펌웨어는 θ를 **−40°~+85°** 로 자르고(설계 한계 −0.7~1.5 rad), 10 ms마다 각 서보를 목표 쪽으로 최대 **200°/s**만 움직입니다(슬루율 제한). 명령이 튀거나 끊겨도 팔이 휘두르지 않게 하는 장치입니다.

## 캘리브레이션: 라이브러리의 θ = 실물의 θ

라이브러리는 "위팔이 수평이면 θ = 0, 아래로 내려가면 +"라고 가정합니다(CLAUDE.md 좌표 규약). 서보는 펄스 폭(µs)만 알 뿐이라, 펌웨어가 각도를 펄스로 바꿉니다.

@fig[r07-calib] 영점은 위팔 수평, 방향은 아래로 +. 펌웨어는 팔마다 영점 펄스·방향·기울기로 각도를 펄스로 바꿉니다.

펌웨어 상단의 배열 세 개가 보정값입니다.

```text
pulse_us = ZERO_US[i] + DIR[i] * US_PER_DEG[i] * theta_deg
float ZERO_US[3]    = {1500.0, 1500.0, 1500.0};   // 위팔이 정확히 수평일 때 펄스
int8_t DIR[3]       = {+1, +1, +1};               // 펄스↑일 때 팔이 아래로 가면 +1, 위로 가면 -1
float US_PER_DEG[3] = {10.3, 10.3, 10.3};         // 1°당 펄스 (MG996R 약 10~11, 개체차 큼)
```

절차(펌웨어 README와 같음):

1. **위팔을 빼고** 혼만 단 상태에서 업로드합니다. `J 0 0 0`을 보내면 기본 영점 1500 µs로 갑니다.
2. 수평 지그를 베이스에 대고 위팔을 혼에 끼웁니다. 스플라인 한 칸 오차는 `ZERO_US`로 보정하므로 최대한 수평에 가깝게만 끼우면 됩니다.
3. **방향 확인**: `J 10 10 10`에서 세 팔이 모두 **아래로** 내려가야 합니다. 올라가는 팔은 `DIR[i] = -1`로 바꿉니다. 서보를 베이스에 거울 대칭으로 달면 흔히 생깁니다.
4. **영점**: 팔마다 `J 1.5 0 0`처럼 조금씩 바꿔 가며 지그와 정확히 맞는 각도 aᵢ를 찾고 `ZERO_US[i] += DIR[i] * US_PER_DEG[i] * aᵢ`로 고칩니다. 다시 올린 뒤 `J 0 0 0`에서 세 팔이 모두 수평인지 확인합니다.
5. **기울기**: `J 45 45 45`에서 각도기로 실제 각도 bᵢ를 재고 `US_PER_DEG[i] *= 45 / bᵢ`로 고칩니다.
6. 로드와 이펙터를 조립하고 `J 20 20 20` → `J 40 40 40`으로 천천히 움직이며 걸림을 확인합니다. 세 팔이 같은 각도면 이펙터는 베이스 **정중앙 아래**에 수평으로 있어야 합니다. 자로 베이스 가장자리에서 이펙터까지 거리를 세 방향에서 재 대칭을 확인합니다.
7. 보정값을 스케치와 실험 노트에 적어 둡니다. 서보를 교체하면 그 팔만 다시 합니다.

:::tip 캘리브레이션 결과 확인
TCP 높이로 검증할 수 있습니다. 홈(세 팔 20°)에서 라이브러리가 계산한 TCP는 베이스(모터축 평면) 아래 **245.7 mm**입니다(R01). 실측값이 몇 mm 이상 다르면 영점이나 로드 길이를 다시 확인합니다. 세 팔이 같은 오차로 틀어지면 이펙터가 위아래로, 한 팔만 틀어지면 옆으로 치우칩니다.
:::

## 드라이런: Playground에서 먼저

실물에 보내기 전에 **같은 동작을 `record` 백엔드로 돌려** 모터 부하, 각도 범위, 최대 모터 속도를 확인합니다. 펌웨어 슬루율(200°/s ≈ 3.5 rad/s)은 카탈로그의 MG996R 최고 속도(대표값 6 rad/s)보다 낮으므로, **최대 모터 속도가 200°/s 아래인지**를 따로 봅니다. 넘으면 펌웨어가 따라가지 못해 경로가 계획과 달라집니다.

@btn[~/tools/playground.html] Playground 열기

```python run
import math
from deltarobot import DeltaRobot

FIRMWARE_DEG_S = 200.0       # 펌웨어 슬루율 제한 MAX_SPEED_DEG_S

def first_motion(robot):
    robot.set_speed(0.05, 0.5)                   # 처음에는 느리게
    robot.home()
    z = -0.25
    for x, y in [(0.0, 0.0), (0.03, 0.0), (0.0, 0.03), (-0.03, 0.0), (0.0, -0.03), (0.0, 0.0)]:
        robot.move_to(x, y, z)
    robot.move_joints(20, 20, 20, degrees=True)  # 홈 = 20°
    robot.tool_on(); robot.wait(0.5); robot.tool_off()

robot = DeltaRobot("edu_servo", scene="empty")   # 드라이런: record 백엔드
first_motion(robot)
rep = robot.analyze()
w = max(rep["max_speed_motor"])
print("동작 시간 %.1f s" % robot.time)
print("최대 모터 속도 %.2f rad/s = %.0f °/s (펌웨어 제한 %.0f °/s)" % (w, math.degrees(w), FIRMWARE_DEG_S))
print("peak %.2f rms %.2f ok=%s" % (rep["peak_ratio"], rep["rms_ratio"], rep["ok"]))
print("모터각 범위 [deg]:", [round(math.degrees(min(f["q"][i] for f in robot.backend.frames)), 1) for i in range(3)],
      "~", [round(math.degrees(max(f["q"][i] for f in robot.backend.frames)), 1) for i in range(3)])
```

```text
동작 시간 5.6 s
최대 모터 속도 0.72 rad/s = 41 °/s (펌웨어 제한 200 °/s)
peak 0.19 rms 0.47 ok=True
모터각 범위 [deg]: [11.2, 12.8, 12.8] ~ [34.5, 33.1, 33.1]
```

모터각이 11°~35° 안에서만 움직이고, 속도는 펌웨어 제한의 5분의 1 수준이라 첫 실물 시험으로 알맞습니다.

## 실습 (실물)

:::safety
- [ ] **교수 입회** 하에 진행하고, 로봇 주변(반경 50 cm)에 손·공구·케이블이 없도록 정리합니다.
- [ ] 서보 전원 + 라인의 **물리 전원 스위치**(하드웨어 비상정지) 위치를 모두가 알고, 한 명은 스위치에 손을 둡니다. 소프트웨어 `E`와 시뮬레이터 비상정지는 보조 수단입니다.
- [ ] 첫 전원 투입은 **로드를 뺀 상태**에서 합니다. 부팅 순간 서보가 홈 각도(20°)로 튑니다.
- [ ] 비상정지(`E`)나 전원 차단 후에는 팔이 **중력으로 떨어집니다.** 아래에 손·부품을 두지 말고, `R` 전에는 팔을 손으로 홈 근처로 받쳐 둡니다(`R`은 마지막 명령 각도로 다시 힘을 줍니다).
- [ ] 작업 영역에 손을 넣기 전에는 반드시 서보 전원을 끕니다.
- [ ] 펌웨어의 각도 한계(−40°~+85°)·슬루율(200°/s)과 라이브러리의 속도 검사를 **완화하지 않습니다.**
- [ ] 서보나 전원부가 뜨거워지면 즉시 멈추고 식힙니다(정지 상태에서도 중력을 버티느라 전류가 흐릅니다).
- [ ] 첫 실행은 `set_speed(0.05)` 이하, 작업대에서 충분히 위(z = −0.25 m)에서 합니다.
:::

### 1단계: PC 준비와 포트 찾기

```bash
pip install -e "python[serial]"          # 저장소 루트에서 (pyserial 설치)
python -m serial.tools.list_ports        # 포트 목록: Windows COM3 등, Linux /dev/ttyACM0 등
```

Linux에서는 `sudo usermod -aG dialout $USER` 후 다시 로그인해야 포트를 열 수 있습니다. **시리얼 모니터는 닫습니다.** 포트는 한 프로그램만 열 수 있습니다.

### 2단계: 같은 코드를 serial 백엔드로

드라이런한 `first_motion()`을 그대로 쓰고, 로봇 생성 줄만 바꿉니다.

```python robot
# first_motion_serial.py — python first_motion_serial.py
from deltarobot import DeltaRobot, WorkspaceError

def first_motion(robot):
    robot.set_speed(0.05, 0.5)
    robot.home()
    z = -0.25
    for x, y in [(0.0, 0.0), (0.03, 0.0), (0.0, 0.03), (-0.03, 0.0), (0.0, -0.03), (0.0, 0.0)]:
        robot.move_to(x, y, z)
        print("TCP (%.3f, %.3f, %.3f)  t=%.1f s" % (robot.position + (robot.time,)))
    robot.move_joints(20, 20, 20, degrees=True)
    robot.tool_on(); robot.wait(0.5); robot.tool_off()

robot = DeltaRobot("edu_servo", backend="serial", port="COM3")   # Linux: port="/dev/ttyACM0"
try:
    first_motion(robot)
except WorkspaceError as e:
    print("거부됨:", e)
except KeyboardInterrupt:
    print("Ctrl+C — 스트림 중단, 서보는 마지막 각도 유지")
finally:
    robot.close()                                # 툴 끄기(T 0) 후 포트 닫기
```

`serial` 백엔드의 동작:

- 포트를 열면 대부분의 아두이노가 **리셋**되므로 2초 기다린 뒤 시작합니다. 리셋된 펌웨어는 홈(20°)에 있고, 라이브러리도 홈에서 시작한다고 가정하므로 둘이 맞습니다.
- 모터각을 도(°)로 바꿔 `J d1 d2 d3`를 최대 50 Hz(`rate=50`)로 보내고, 각 동작의 마지막 목표는 항상 보냅니다. 툴은 `T 0|1`입니다.
- 관절 속도가 모터 한계를 넘는 동작은 보내기 전에 `WorkspaceError`로 **거부**합니다.
- 필요하면 `robot.backend.estop()`(→ `E`)과 `robot.backend.reset()`(→ `R`)을 직접 부를 수 있습니다. 다만 `E`는 팔이 떨어지므로 Ctrl+C 처리에서 자동으로 보내지 않았습니다. 스트림이 멈추면 서보는 마지막 각도를 유지합니다.

### 3단계: 부품 옮기기

첫 동작이 계획대로 되면 R02의 분류 프로그램을 **속도 0.1 m/s**로 실행합니다. 실제 부품(사탕·지우개 등 10~20 g)을 R02의 `robot.parts()` 좌표에 놓아야 합니다. 라이브러리는 카메라가 없으므로 **장면 모델의 좌표를 믿고** 움직입니다. 작업대 높이(`surface_z` = −0.285 m)도 실물과 맞춰야 흡착컵이 부품 윗면에 닿습니다. 높이가 다르면 작업대 밑에 판을 대서 맞추거나 `scene`을 dict로 만들어 `surface_z`를 실측값으로 바꿉니다.

### ROS 2로 실물 구동 (선택)

R06의 모든 명령은 드라이버만 `serial`로 바꾸면 실물에서 그대로 동작합니다. 드라이버는 시작할 때 `R`과 `T 0`을 보내고, `J`를 최대 50 Hz로 보냅니다. 서보는 위치 피드백이 없어 `/joint_states`는 **명령한 각도**입니다.

```bash
ros2 launch delta_robot bringup.launch.py preset:=edu_servo port:=/dev/ttyACM0
```

`/delta/estop`에 `true`가 오면 드라이버는 아두이노에 `E`를 보내고, `false`면 `R`을 보냅니다.

:::check 체크포인트
- [ ] `J 0 0 0`에서 세 위팔이 모두 수평이고, `J 10 10 10`에서 모두 아래로 내려간다.
- [ ] 홈 자세 TCP 높이 실측값이 계산값(245.7 mm)과 몇 mm 안에서 맞는다.
- [ ] 드라이런에서 최대 모터 속도가 200°/s 아래임을 확인했다.
- [ ] 같은 `first_motion()`이 Playground와 실물에서 같은 모양으로 움직였다.
:::

## 자주 나는 오류와 해결

### `serial.serialutil.SerialException: could not open port 'COM3': PermissionError(13, '액세스가 거부되었습니다.', None, 5)`

- **원인**(Windows): 아두이노 IDE 시리얼 모니터 등 다른 프로그램이 포트를 열고 있습니다. 포트 이름이 틀리면 `FileNotFoundError(2, ...)`가 납니다.
- **해결**: 시리얼 모니터를 닫고, `python -m serial.tools.list_ports`로 포트 이름을 확인합니다.

### `serial.serialutil.SerialException: [Errno 13] could not open port /dev/ttyACM0: [Errno 13] Permission denied: '/dev/ttyACM0'`

- **원인**(Linux): 사용자가 `dialout` 그룹에 없습니다.
- **해결**: `sudo usermod -aG dialout $USER` 후 **다시 로그인**합니다.

### `RuntimeError: serial 백엔드에는 pyserial이 필요합니다: pip install pyserial`

- **해결**: `pip install -e "python[serial]"`.

### 서보가 떨거나 아두이노가 계속 리셋됨 (시리얼에 `READY delta_servo`가 반복)

- **원인**: 서보 전원이 약하거나 USB에서 서보 전원을 끌어왔습니다. 전압이 떨어지며 아두이노가 리셋됩니다.
- **해결**: 6 V 5 A 이상 별도 전원, GND 공통, 1000 µF 커패시터를 확인합니다.

### 팔 하나가 반대로 움직이거나 이펙터가 한쪽으로 쏠림

- **원인**: 그 팔의 `DIR`가 틀렸거나, 서보 핀 순서(D9·D10·D11 = 팔 1·2·3)가 바뀌었습니다.
- **해결**: `J 10 0 0`, `J 0 10 0`, `J 0 0 10`으로 한 팔씩 움직여 번호와 방향을 확인합니다.

### 시리얼에 `ERR estop (send R)`

- **원인**: 비상정지 상태에서 `J`·`T`를 보냈습니다.
- **해결**: 팔을 홈 근처로 받친 뒤 `R`을 보냅니다(파이썬은 `robot.backend.reset()`).

### 파이썬 `WorkspaceError: 관절 속도 ... rad/s 가 모터 한계 ...`

- **원인**: 실물 백엔드는 속도 초과를 거부합니다.
- **해결**: 드라이런에서 `analyze()`로 확인하고 `set_speed()`를 낮춥니다. 펌웨어 슬루율(200°/s)도 함께 고려합니다.

## 과제

:::task 개인 과제
1. 캘리브레이션 전후로 `J 0 0 0`, `J 45 45 45`의 실측 각도를 표로 남기고, 최종 `ZERO_US`, `DIR`, `US_PER_DEG` 값을 제출합니다.
2. 홈 자세와 (±0.03, 0, −0.25), (0, ±0.03, −0.25)에서 TCP 위치를 자로 재어 계산값과의 오차를 표로 정리하고, 가장 큰 오차의 원인을 추정합니다.
3. R02의 분류 프로그램을 실물에서 0.1 m/s로 실행하고 성공 개수와 사이클 시간을 Playground 결과와 비교합니다.
:::

:::mission 팀 미션
팀별로 속도를 0.05 → 0.1 → 0.2 m/s로 올리며 흡착 실패가 처음 생기는 속도를 찾고, 그때의 `peak_ratio`·가속도와 함께 원인(흡착력 부족, 진동, 슬루율 지연)을 보고합니다.
:::
