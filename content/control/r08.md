## 학습 목표

- 컨베이어 위 부품의 위치를 $x(t) = x₀ + v·(t − t₀)$로 예측하고, 로봇 이동 시간과 맞물린 **만남 지점(intercept)** 을 반복 계산으로 구합니다.
- 이동 시간을 `deltarobot.trajectory.Profile`과 `arch_path`로 **움직이기 전에** 추정합니다.
- 흡착하는 동안 컨베이어 속도로 따라가는 트래킹 pick, 색깔 분류, 예외 처리를 갖춘 프로그램을 완성합니다.
- 같은 프로그램을 Playground → 웹 시뮬(websim) → ROS 2 → 실물 순으로 옮기며 단계마다 달라지는 점을 검증합니다.

## 문제 정의

`scene="conveyor"`는 설계 크기에 맞춘 컨베이어 셀입니다. 부품 30개가 2초 간격으로 벨트 왼쪽 끝(`x_start`)에 나타나 +x 방향으로 흘러가고, 오른쪽 끝(`x_end`)을 지나면 사라집니다. 빨강은 상자 A, 파랑은 상자 B에 넣어야 합니다.

```python run
from deltarobot import DeltaRobot

robot = DeltaRobot("edu_servo", scene="conveyor")
conv = robot.scene.conveyor()
print("컨베이어: y=%.4f m, 폭 %.4f m, x %.4f → %.4f m, 속도 %.4f m/s" % (
    conv["y"], conv["width"], conv["x_start"], conv["x_end"], conv["speed"]))
print("부품 %d개, 첫 부품 t=%.1f s, 간격 %.1f s" % (
    len(conv["spawn"]), conv["spawn"][0]["t"], conv["spawn"][1]["t"] - conv["spawn"][0]["t"]))
print("상자:", [(b["id"], b["color"], b["x"], b["y"]) for b in robot.bins()])

robot.home()
robot.wait(4.0)
for p in robot.parts():
    print("t=%.1f s  %s %-5s x=%.4f y=%.4f" % (robot.time, p["id"], p["color"], p["x"], p["y"]))
robot.wait(1.0)
print("1초 뒤:", [(p["id"], round(p["x"], 4)) for p in robot.parts()])

# 예측 없이 '지금 보이는 위치'로 가면?
part = robot.parts()[0]
robot.arch_to(part["x"], part["y"], part["top"])
got = robot.tool_on()
now = [p for p in robot.parts() if p["id"] == part["id"]]
print("이동 시간 동안 부품이 %.4f m 이동 → tool_on 결과: %s" % (now[0]["x"] - part["x"] if now else float("nan"), got))
```

```text
부품 30개, 첫 부품 t=1.0 s, 간격 2.0 s

이동 시간 동안 부품이 0.0229 m 이동 → tool_on 결과: None
```

두 가지를 알 수 있습니다.

1. `robot.parts()`는 **호출한 순간**(`robot.time`)의 위치를 줍니다. 1초에 22.4 mm씩 움직입니다.
2. 보이는 위치로 가면 도착하는 약 1초 사이에 부품이 23 mm 떠내려가, 흡착 판정 범위(수평 12 mm)를 벗어나 **놓칩니다.** 도착할 때 부품이 **있을** 곳으로 가야 합니다.

시간 예산도 계산해 둡니다. 부품이 2초마다 오므로 한 사이클(집기 + 상자 + 복귀)이 평균 2초 안에 끝나야 모두 잡을 수 있습니다. R02에서 기본 속도(0.19 m/s)의 한 사이클은 약 2.3초였습니다. 속도를 올려야 합니다.

## 만남 지점 계산

@fig[r08-intercept] 부품의 직선 x(t)와 로봇 도착 시각이 만나는 점을 반복 계산으로 찾습니다. 로봇이 컨베이어보다 훨씬 빨라서 몇 번 만에 수렴합니다.

지금 시각을 $t₀$, 부품 위치를 $x₀$, 컨베이어 속도를 $v$라고 하면, 로봇이 $Δt$ 뒤에 도착할 때 부품은 $x₀ + v·Δt$에 있습니다. 그런데 $Δt$는 **어디로 가느냐**에 따라 달라집니다. 그래서 번갈아 계산합니다.

1. $Δt = 0$에서 시작합니다.
2. 목표 $x_hit = x₀ + v·Δt$
3. 현재 위치 → $x_hit$의 아치 경로 길이를 `arch_path(...).length`로 구합니다.
4. `Profile(robot.profile, 길이, robot.speed, robot.accel).T`로 이동 시간 $Δt$를 새로 구합니다.
5. 2~4를 3~5번 반복합니다.

`arch_to`가 실제로 쓰는 것과 **같은 경로 함수와 같은 프로파일**로 계산하므로 추정 시간이 실제 이동 시간과 같습니다. 반복할 때마다 $Δt$ 변화가 대략 (컨베이어 속도 ÷ 로봇 속도) 배로 줄어드는데, 로봇이 컨베이어보다 10배 이상 빨라서 금방 수렴합니다.

:::info arch_path는 이펙터 중심 좌표
`deltarobot.trajectory`의 경로 함수는 라이브러리 내부 함수라 **이펙터 중심** 좌표를 씁니다(R01). TCP 목표에 툴 길이를 더해 넘기고, 시작점은 `robot.effector`를 씁니다. 경로 길이는 평행 이동이라 어느 좌표든 같지만, 아치의 높이 계산을 `arch_to`와 똑같이 맞추려는 것입니다.
:::

## 1단계: Playground에서 완성

@btn[~/tools/playground.html] Playground 열기

```python run
import math
from deltarobot import DeltaRobot, WorkspaceError
from deltarobot.trajectory import Profile, arch_path

robot = DeltaRobot("edu_servo", scene="conveyor")
robot.set_speed(0.25, 2.5)                   # R02에서 검증한 범위, 펌웨어 200°/s 안쪽
conv = robot.scene.conveyor()
v = conv["speed"]                            # 컨베이어 속도 [m/s], +x 방향
surface = robot.scene.data["surface_z"]
HEIGHT = 0.03                                # 아치 높이 [m]
X_MIN, X_MAX = -0.09, 0.08                   # 집을 x 구간 (작업영역 안쪽 여유)
TRACK = 0.1                                  # 흡착하며 컨베이어를 따라가는 시간 [s]
bin_of = {b["color"]: b for b in robot.bins()}
END = conv["spawn"][-1]["t"] + (conv["x_end"] - conv["x_start"]) / v

def move_time(x, y, z):
    """현재 위치에서 TCP (x, y, z)까지 arch_to에 걸릴 시간 추정 [s]."""
    p0 = robot.effector
    p1 = (x, y, z + robot.design.tool_length)          # arch_path는 이펙터 중심 좌표
    length = arch_path(p0, p1, HEIGHT).length
    return Profile(robot.profile, length, robot.speed, robot.accel).T

def intercept(part):
    """도착 시각에 부품이 있을 x와 이동 시간 dt를 반복 계산으로 구한다."""
    dt = 0.0
    for _ in range(5):
        x_hit = part["x"] + v * dt
        dt = move_time(x_hit, part["y"], part["top"])
    return part["x"] + v * dt, dt

robot.home()
picked, missed, log = 0, 0, 0
while robot.time < END:
    best = None
    for part in robot.parts():
        if part["on"] != "conveyor":
            continue
        x_hit, dt = intercept(part)
        if X_MIN <= x_hit <= X_MAX and (best is None or part["x"] > best[0]["x"]):
            best = (part, x_hit, dt)             # 가장 앞(하류)에 있는 부품부터
    if best is None:
        robot.wait(0.1)                          # 잡을 부품이 들어올 때까지 대기
        continue
    part, x_hit, dt = best
    try:
        robot.arch_to(x_hit, part["y"], part["top"], height=HEIGHT)
        got = robot.tool_on()
        robot.move_by(dx=v * TRACK, speed=v, accel=10 * v)   # 컨베이어와 같은 속도로 따라가며 흡착
        if got is None:
            missed += 1
            robot.tool_off()
            continue
        b = bin_of[part["color"]]
        robot.arch_to(b["x"], b["y"], surface + b["h"] + part["h"] + 0.005, height=HEIGHT)
        robot.tool_off()
        picked += 1
        if log < 3:
            log += 1
            print("%s %-4s x %.4f → 예측 %.4f (Δt %.2f s), 상자 %s, t=%.2f s" % (
                got, part["color"], part["x"], x_hit, dt, b["id"], robot.time))
    except WorkspaceError as e:
        print("건너뜀:", e)
        robot.tool_off()

robot.home()
s = robot.scene.score()
rep = robot.analyze()
print("집기 %d, 놓침 %d, 끝난 시각 %.1f s" % (picked, missed, robot.time))
print("점수:", s, "/ 흘러온 부품", len(conv["spawn"]))
print("peak %.2f rms %.2f 최대 모터 속도 %.0f °/s ok=%s" % (
    rep["peak_ratio"], rep["rms_ratio"], math.degrees(max(rep["max_speed_motor"])), rep["ok"]))
```

```text
c2 blue x -0.1075 → 예측 -0.0883 (Δt 0.86 s), 상자 B, t=6.91 s
c3 red  x -0.1030 → 예측 -0.0782 (Δt 1.11 s), 상자 A, t=9.24 s
집기 30, 놓침 0, 끝난 시각 72.5 s

```

**30개 모두 색에 맞게 분류**했고(`correct 30 / total 30`), 모터 검증도 통과했습니다. 프로그램의 핵심:

- **부품 고르기**: 만남 지점이 작업 구간(`X_MIN`~`X_MAX`) 안에 있는 부품 중 가장 하류(x가 큰) 것부터 잡습니다. 놓치면 곧 사라질 부품이 먼저입니다.
- **대기**: 잡을 부품이 없으면 `robot.wait(0.1)`로 기다립니다. Playground에서는 가상 시간이라 금방 끝납니다.
- **트래킹 pick**: 흡착은 `tool_on()` 순간에 판정되지만, 실물 진공은 압력이 차는 데 시간이 걸립니다. 그동안 `move_by(dx=v·TRACK, speed=v)`로 **컨베이어와 같은 속도**로 따라가 부품과 컵이 미끄러지지 않게 합니다.
- **예외 처리**: 계산이 틀려 작업영역 밖을 겨누면 `WorkspaceError`로 그 부품만 건너뛰고, 혹시 잡은 것이 있으면 `tool_off()`로 놓습니다.

속도를 바꿔 보면 시간 예산이 보입니다. 같은 프로그램을 `set_speed(0.30, 3.0)`으로 돌려도 30개를 모두 잡지만(최대 모터 속도 약 194°/s로 펌웨어 한계 200°/s에 너무 가깝습니다), `set_speed(0.20, 2.0)`에서는 사이클이 2초를 넘어 **26개**만 잡습니다. 이 셀에서는 0.25 m/s가 여유 있는 선택입니다.

:::check 1단계 체크포인트
- [ ] 예측 없이 가면 `tool_on()`이 `None`인 것을 확인했다.
- [ ] 트래킹 프로그램이 `correct` 28개 이상, `ok=True`를 얻었다.
- [ ] 반복 계산 횟수(1, 2, 5회)를 바꿔 결과가 어떻게 달라지는지 확인했다.
:::

## 1-2단계: 벨트와 속도를 맞추는 트래킹 pick (`track_pick`)

위 프로그램은 만남 지점에 **멈춰 서서** 부품을 기다렸다가 잡습니다. 계산상으로는 잡는 순간 위치가 정확히 맞지만,
툴은 정지(속도 0)해 있고 부품은 벨트 속도로 움직이므로 **상대 속도가 v인 채로 접촉**합니다. 화면에서는 부품이 툴 밑으로
미끄러져 들어와 "착" 붙는 것처럼 보이고, 실물에서는 흡착컵이 부품을 긁거나 놓칩니다. 실제 컨베이어 트래킹은
**부품 위에서 벨트와 같은 속도로 함께 움직이며** 내려가 잡습니다. 라이브러리의 `robot.track_pick(part)`가 이 동작입니다.

1. 부품이 도착할 곳보다 `v·T_d/2`만큼 **앞쪽 상공**(`hover`, 기본 20 mm)으로 아치 이동합니다.
2. `T_d`(기본 0.3 s) 동안 내려가면서 x속도를 $ẋ = v(1 − cos(πτ/T_d))/2$로 0 → v까지 부드럽게 올립니다.
   이 곡선을 적분하면 이동 거리가 정확히 `v·T_d/2`라서, 접촉 순간 **위치와 속도가 모두** 부품과 같습니다.
3. `tool_on()` 후 `dwell`(기본 0.1 s) 동안 벨트 속도로 따라가며 흡착(진공 형성 시간)합니다.
4. 올라가면서 x속도를 v → 0으로 줄입니다. 그다음 상자로 아치 이동합니다.

```python run
import math
from deltarobot import DeltaRobot, WorkspaceError, kinematics as kin

robot = DeltaRobot("edu_servo", scene="conveyor")
robot.set_speed(0.25, 2.5)
robot.home()
conv = robot.scene.conveyor()
v = conv["speed"]
X_MAX = 0.9 * robot.scene.data["work_radius"]
tried = set()
speed_at_contact = []

while robot.time < 70:
    cands = [p for p in robot.parts() if p["on"] == "conveyor" and p["id"] not in tried]
    cands.sort(key=lambda p: -p["x"])                       # most downstream first
    target = next((p for p in cands
                   if p["x"] + v * 1.2 < X_MAX and robot.reachable(p["x"] + v * 1.2, p["y"], p["top"])), None)
    if target is None:
        robot.wait(0.1)
        continue
    tried.add(target["id"])
    n0 = len(robot.backend.frames)
    try:
        got = robot.track_pick(target)                      # velocity-matched pick
    except WorkspaceError as e:
        print("건너뜀:", e)
        continue
    if got is None:
        robot.tool_off()
        continue
    # how fast was the tool moving along x when it touched the part?
    fr = robot.backend.frames
    k = next(i for i in range(n0, len(fr)) if fr[i]["tool"] == 1)
    a, b = kin.fk(robot.design, fr[k - 2]["q"]), kin.fk(robot.design, fr[k - 1]["q"])
    speed_at_contact.append((b[0] - a[0]) / (fr[k - 1]["t"] - fr[k - 2]["t"]))
    box = next(b for b in robot.bins() if b["color"] == target["color"])
    robot.arch_to(box["x"], box["y"], robot.scene.surface_z + box["h"] + target["h"] + 0.02)
    robot.tool_off()

print("점수:", robot.scene.score())
print("잡는 순간 툴 x속도 / 벨트 속도: 평균 %.3f, 최소 %.3f" % (
    sum(speed_at_contact) / len(speed_at_contact) / v, min(speed_at_contact) / v))
rep = robot.analyze()
print("peak %.2f rms %.2f 최대 모터 속도 %.0f °/s ok=%s" % (
    rep["peak_ratio"], rep["rms_ratio"], math.degrees(max(rep["max_speed_motor"])), rep["ok"]))
```

```text
점수: {'per_bin': {'A': 13, 'B': 14}, 'correct': 27, 'total': 27}
잡는 순간 툴 x속도 / 벨트 속도: 평균 0.999, 최소 0.999
peak 0.31 rms 0.52 최대 모터 속도 169 °/s ok=True
```

잡는 순간 툴은 벨트와 같은 속도(0.999배)로 움직입니다 — 멈춰서 기다리는 방식은 0배입니다. 대신 한 번 잡을 때
하강·동행·상승 시간(약 0.7 s)이 더 들어서 70초 동안 **27개**를 잡았습니다(멈춤 방식 30개). 실물에서는 흡착 실패·부품
손상이 줄어드는 대가로 사이클이 늘어나는 것이므로, `descent_time`·`dwell`·`hover`를 줄여 시간을 되찾는 것이 튜닝 과제입니다.
시뮬레이터 **작업** 탭의 "컨베이어 트래킹 데모"도 같은 방식(JS 구현, 파이썬과 같은 궤적임을 테스트로 확인)으로 움직입니다.

## 2단계: 웹 시뮬레이터에서 실시간 (websim)

로봇 생성 줄만 바꿉니다. 나머지 코드는 그대로입니다.

```python robot
robot = DeltaRobot("edu_servo", backend="websim", scene="conveyor")
```

R03처럼 스크립트를 실행하고 시뮬레이터 **연결** 탭에서 **[PC Python 연결]** 을 누릅니다. 달라지는 점:

- `robot.time`이 실제 시간이므로 프로그램이 **72초 동안 실제로** 돕니다. `robot.wait(0.1)` 대기 루프도 실제 0.1초입니다.
- 부품 위치 판단은 파이썬 안의 장면 모델(`robot.parts()`, `robot.time` 기준)이 합니다. 파이썬은 연결할 때 이 장면을 시뮬레이터에 보내고, 시뮬레이터는 받은 모터각과 툴 상태로 로봇을 그립니다.
- 계획과 전송 사이에 계산 시간이 끼어도 괜찮습니다. 궤적 샘플에는 **계획한 순간의 시각**이 들어 있고, 백엔드는 그 시각에 맞춰 보냅니다. 그러나 PC가 바빠 전송이 늦어지면 도착이 늦어져 놓칠 수 있습니다. 결과는 마지막에 출력되는 `score()`로 확인합니다.
- `analyze()`는 `record` 전용이므로 마지막 줄의 분석 출력을 빼거나 `try`로 감쌉니다(R02 오류 표 참고). 3·4단계도 같습니다.
- 시뮬레이터 비상정지 → `EmergencyStop`으로 프로그램이 끝나야 합니다. `except WorkspaceError`만 쓴 이유입니다.

## 3단계: ROS 2 (mock → 웹 브리지로 관찰)

```bash
ros2 launch delta_robot display.launch.py preset:=edu_servo web_bridge:=true scene:=conveyor
```

```python robot
robot = DeltaRobot("edu_servo", backend="ros2", scene="conveyor")
```

- 로봇이 **홈 자세**에 있을 때 시작합니다(R06 주의사항). launch 직후라면 홈입니다.
- `ros2` 백엔드는 속도 초과를 **거부**합니다. 0.25 m/s 설정은 모터 최고 속도의 약 절반이라 통과합니다.
- 드라이버(mock)는 모터를 "최고 속도 ÷ 감속비"로 제한하며 따라가므로, `/delta/tcp`를 기록하면 실제 추종 경로를 확인할 수 있습니다.
- 웹 브리지를 켜면 RViz와 웹 시뮬레이터 양쪽에서 로봇 움직임을 봅니다. `DeltaRobot(backend="ros2")`가 시작할 때
  자기 장면을 `/delta/session`으로 보내면, 브리지가 **그 순간을 t = 0으로 시계를 다시 맞추고** 같은 장면을 시뮬레이터에 보냅니다.
  그래서 화면 속 컨베이어 부품과 파이썬이 계산한 부품 위치가 일치합니다. 브리지와 파이썬의 설계(preset)가 다르면 브리지 콘솔에
  경고가 나오니 같은 preset으로 시작하세요.
- `/delta/estop`을 발행해 프로그램이 `EmergencyStop`으로 멈추는지 꼭 시험합니다.

## 실습 (실물)

4단계는 실물입니다. 3단계까지 통과한 프로그램만 가져옵니다.

:::safety
- [ ] R07의 안전 확인 항목(교수 입회, 물리 전원 스위치 담당자, 첫 전원은 로드 없이, 비상정지 후 팔 낙하 주의)을 모두 다시 확인합니다.
- [ ] 컨베이어를 쓰면 **벨트·풀리에 손가락·머리카락·소매가 끼지 않도록** 덮개를 씌우고, 컨베이어 전원도 별도 스위치로 끌 수 있게 합니다.
- [ ] 첫 실행은 **부품 없이(가상 부품)**, 속도를 절반(`set_speed(0.12, 1.2)`)으로 낮춰 동작 범위를 확인합니다.
- [ ] 로봇과 컨베이어가 움직이는 동안 작업 영역에 손을 넣지 않습니다. 부품 보충·정리는 두 전원을 모두 끈 뒤에 합니다.
- [ ] 드라이런(1단계)에서 최대 모터 속도가 펌웨어 슬루율 200°/s 아래이고 `ok=True`인 설정만 실물에 보냅니다.
:::

### 4-1. 가상 부품으로 동작 확인

로봇 생성 줄만 바꿉니다. 컨베이어와 부품이 없어도 로봇은 가상 부품을 쫓아 트래킹·분류 동작을 그대로 합니다(흡착 펌프도 켜졌다 꺼집니다).

```python robot
robot = DeltaRobot("edu_servo", backend="serial", port="COM3", scene="conveyor")
robot.set_speed(0.12, 1.2)      # 첫 실행은 절반 속도 — 이때는 일부 부품을 놓치는 것이 정상
```

### 4-2. 실제 컨베이어와 맞추기 (확장)

소형 컨베이어가 있다면 장면 모델을 **실측값**으로 바꿉니다.

1. 벨트 속도 $v$를 잽니다(표시선이 30 cm를 지나는 시간, 3회 평균).
2. 컨베이어의 중심선 y, 작업대 높이(`surface_z`), 벨트가 작업영역에 들어오는 x를 로봇 좌표로 잽니다. 가장 쉬운 방법은 R07의 `first_motion` 방식으로 TCP를 천천히 벨트 위에 가져가 좌표를 읽는 것입니다.
3. `default_scene()`으로 만든 장면 dict의 `conveyor`를 고칩니다. 부품 투입은 "프로그램 시작과 동시에 벨트를 켜고, 부품은 미리 벨트 위 상류에 놓아 둔다"로 맞춥니다: `spawn` 시각 $tₙ$인 부품은 시작 순간 `x_start` − $v·tₙ$에 놓습니다.

```python robot
from deltarobot import DeltaRobot, DeltaDesign, default_scene

scene = default_scene(DeltaDesign.preset("edu_servo"), "conveyor")
c = scene["conveyor"]
c["speed"] = 0.020                       # 실측 벨트 속도 [m/s]
c["y"] = -0.050                          # 실측 벨트 중심 y [m]
scene["surface_z"] = -0.283              # 실측 벨트 윗면 높이 [m]
c["spawn"] = [{"t": 2.0 + 3.0 * n, "y_off": 0.0, "color": ("red", "blue")[n % 2],
               "material": "plastic"} for n in range(6)]
for s in c["spawn"]:
    print("시작 순간 %s 부품을 x = %.3f m 에 놓기" % (s["color"], c["x_start"] - c["speed"] * s["t"]))
input("부품을 놓고, 벨트 스위치에 손을 둔 뒤 Enter와 동시에 벨트를 켜세요 ")
robot = DeltaRobot("edu_servo", backend="serial", port="COM3", scene=scene)
```

로봇 생성 이후는 1단계 프로그램과 같습니다(설정 줄의 `set_speed`는 4-1에서 확인한 속도로). 시작 동기화 오차, 벨트 속도 변동, 부품 위치 오차가 모두 **만남 지점 오차**가 됩니다. 흡착 판정 여유가 12 mm라는 점을 기준으로, 어떤 오차가 가장 큰지 측정해 보고하세요. 실제 산업용 셀은 엔코더로 벨트 위치를 재고 카메라로 부품 위치를 찾아 이 오차를 없앱니다.

ROS 2로 실물을 구동하려면 R07처럼 `bringup.launch.py`로 드라이버를 `serial`로 띄우고 3단계의 `backend="ros2"` 코드를 씁니다.

## 자주 나는 오류와 해결

### 점수가 0이고 `tool_on()`이 항상 `None`

- **원인**: 예측 없이 현재 위치로 가거나, 컨베이어 속도의 부호·단위를 틀렸습니다(mm/s를 m/s 자리에). 이펙터 중심 좌표로 경로 길이를 구하지 않아 이동 시간이 틀린 경우도 있습니다.
- **해결**: 1단계 첫 예제처럼 이동 전후 부품 위치를 출력해, 예측한 `x_hit`과 도착 시 부품 x를 비교합니다.

### `WorkspaceError: 작업영역 밖: (-0.120, -0.051, -0.276) m — 모터 각도 한계, 볼조인트 각도 한계`

- **원인**: `X_MIN`을 너무 작게(상류 쪽으로) 잡아 벨트 입구 쪽 작업영역 밖을 겨눴습니다.
- **해결**: 벨트 y와 부품 윗면 높이에서 `robot.reachable(x, y, z)`로 x를 훑어 구간을 정합니다. `edu_servo`에서 벨트 중심선 기준 약 −0.1 m보다 상류는 닿지 않습니다.

### `RuntimeError: 가상 시간 600 s 제한을 넘었습니다 (무한 루프인가요?)`

- **원인**: `while` 조건에 끝나는 시각(`END`)이 없거나, 조건을 부품 수로 잡았는데 놓친 부품 때문에 영원히 채워지지 않습니다.
- **해결**: 마지막 부품이 벨트를 벗어나는 시각으로 루프를 끝냅니다.

### websim·ROS 2에서 Playground보다 많이 놓침

- **원인**: 실시간 백엔드에서는 PC 부하로 전송이 늦어지거나(websim), 드라이버가 속도 제한으로 목표를 늦게 따라갑니다(ROS 2 mock·실물 펌웨어 슬루율).
- **해결**: 작업 구간을 하류 쪽으로 약간 줄여 여유를 두고, `TRACK` 시간을 늘리며, 속도를 무리하게 높이지 않습니다. `/delta/tcp`로 실제 도착 시각을 측정해 비교합니다.

### ROS 2에서 `WorkspaceError: 관절 속도 ... rad/s 가 모터 한계 ...`

- **원인**: 실물 백엔드는 속도 초과를 거부합니다. `set_speed(0.30, 3.0)` 이상에서 작업영역 가장자리를 지날 때 생길 수 있습니다.
- **해결**: 1단계에서 `analyze()`로 검증한 설정(0.25 m/s)을 씁니다.
