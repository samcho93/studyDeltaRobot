D06궤적 계획

사다리꼴·S-커브·5차 다항식·사이클로이드 프로파일과 pick & place 아치 궤적이 토크와 진동에 주는 영향을 비교합니다.

선수 챕터: T08 D04
시뮬레이터Python Playground

학습 목표#

  • 궤적 = 경로(path) + 시간 스케일링(profile) 으로 나누어 생각하고, deltarobot.trajectory의 네 프로파일 식을 설명할 수 있습니다.
  • 같은 속도·가속도 한계에서 프로파일마다 이동 시간, 피크 토크, 저크(jerk) 가 어떻게 다른지 계산으로 비교할 수 있습니다.
  • pick & place 아치 궤적의 높이·모서리 반지름이 사이클 시간·토크·실제 가속도에 주는 영향을 설명할 수 있습니다.

경로와 시간 스케일링#

robot.move_to(), arch_to(), move_path()는 모두 두 단계로 궤적을 만듭니다.

  1. 경로 p(s) — 호 길이 s로 매개화한 선분·원호의 연결 (trajectory.Path, line_path, arch_path)
  2. 프로파일 s(t) — 0에서 전체 길이 d까지 정지 → 정지로 가는 시간 함수 (trajectory.Profile(kind, d, vmax, amax))

TCP 속도는 ṗ = p'(s)·ṡ, 가속도는 p̈ = p'(s)·s̈ + p''(s)·ṡ² 입니다. 두 번째 항 p''ṡ² 이 곡선 구간의 원심 가속도(v²/ρ)로, 프로파일의 가속도 한계와 별개로 생깁니다.

네 가지 프로파일#

아래 식은 python/deltarobot/trajectory.py와 같습니다(d: 거리, T: 이동 시간, x = t/T).

사다리꼴 (trapezoid) — 가속도가 ±amax 또는 0인 계단. 가속 시간 t_a = v_max/a_max, 등속 시간 t_c = (d − v_max·t_a)/v_max, T = 2t_a + t_c. 거리가 짧아 a_max·t_a² ≥ d 이면 삼각형: t_a = √(d/a_max).

S-커브 (scurve) — 가속도를 a(t) = A·sin²(πt / t_a) 로 부드럽게 올렸다 내림. 평균 가속도는 A/2라서 t_a = 2v_max/A 동안 속도가 v_max에 도달합니다(A = amax). A t_a²/2 ≥ d 이면 t_a = √(2d/A)로 줄어듭니다.

5차 다항식 (quintic) — s = d·(10x³ − 15x⁴ + 6x⁵). 시작·끝에서 속도·가속도가 0. 최고 속도 15d/(8T), 최고 가속도 10d/(√3·T²)이므로 T = max(15d/(8v_max), √(10d/(√3·a_max))).

사이클로이드 (cycloidal) — s = d(x - sin(2π x)/(2π)). 가속도가 한 주기 사인파. 최고 속도 2d/T, 최고 가속도 2π d/T²이므로 T = max(2d/v_max, √(2π d/a_max)).

저크와 진동#

저크(jerk) 는 가속도의 변화율 d³s/dt³입니다. 힘(토크)이 갑자기 바뀌면 팔·로드·프레임이 망치로 친 것처럼 떨립니다.

프로파일가속도저크특징
사다리꼴계단 (불연속)전환 순간 무한대가장 빠르지만 진동이 가장 큼
S-커브연속, 시작·끝 0연속 (최대 Aπ/t_a)부드러움. 같은 amax에서 평균 가속도가 절반이라 느림
5차 다항식연속, 시작·끝 0시작·끝에서만 유한한 계단 (60d/T³)속도·가속도 경계조건을 만족하는 표준
사이클로이드사인파, 시작·끝 0시작·끝에서만 유한한 계단 (4π² d/T³)캠 설계에서 유래, 5차와 비슷

델타로봇은 이동 질량이 가벼워 가속도가 매우 크기 때문에 저크 제한이 사이클 시간만큼 중요합니다. 3D 프린팅 팔(pla_print)처럼 강성이 낮은 재질은 특히 사다리꼴 프로파일에서 잔진동이 큽니다(이 강의의 모델은 강체라 진동을 직접 계산하지는 않습니다).

실습 (Python) — 프로파일별 사이클·토크·저크#

industrial_picker(페이로드 0.5 kg)로 Adept 사이클을 3 m/s, 30 m/s², 모서리 반지름 25 mm로 한 번 돌리며 프로파일만 바꿉니다.

python시뮬 실행 가능
from deltarobot import DeltaDesign, DeltaRobot
from deltarobot import trajectory as traj

d = DeltaDesign.preset("industrial_picker").copy(payload=0.5)
print("프로파일     사이클   피크   RMS   최대 저크[m/s^3]")
for kind in traj.PROFILES:
    robot = DeltaRobot(d, scene="empty")
    robot.set_speed(3.0, 30.0)
    robot.set_profile(kind)
    z = robot.scene.surface_z + 0.02
    robot.move_to(-0.1525, 0, z)
    t0 = robot.time
    robot.arch_to(0.1525, 0, z, height=0.025, radius=0.025)
    robot.arch_to(-0.1525, 0, z, height=0.025, radius=0.025)
    T = robot.time - t0
    r = robot.analyze()
    # 경로 방향 저크: 프로파일 s''(t)를 수치 미분
    path = traj.arch_path((-0.1525, 0, 0), (0.1525, 0, 0), 0.025, 0.025)
    p = traj.Profile(kind, path.length, 3.0, 30.0)
    dt = p.T / 2000
    jerk = max(abs(p.at((k + 1) * dt)[2] - p.at(k * dt)[2]) / dt for k in range(2000))
    print("%-10s  %.3f s  %5.2f %5.2f   %8.0f" % (kind, T, r["peak_ratio"], r["rms_ratio"], jerk))
text
프로파일     사이클   피크   RMS   최대 저크[m/s^3]
trapezoid   0.422 s   0.51  0.68     284118
scurve      0.596 s   0.36  0.46        632
quintic     0.507 s   0.37  0.53       1229
cycloidal   0.529 s   0.36  0.52        713
  • 사다리꼴은 사이클이 가장 짧지만(0.422 s) 피크 비 0.51로 가장 큽니다. 저크 284118 m/s³는 계단을 dt로 나눈 수치 미분값이라 dt를 줄이면 계속 커집니다 — 사실상 무한대입니다.
  • S-커브는 가장 느리지만(0.596 s) 피크·RMS가 가장 작고 저크도 632 m/s³로 가장 작습니다. DeltaRobot의 기본 프로파일이 scurve인 이유입니다.
  • 5차·사이클로이드는 그 사이입니다. 끝점 저크 계단 때문에 최대 저크는 S-커브보다 큽니다.
"같은 한계"와 "같은 시간"은 다른 비교입니다

위 표는 vmax·amax를 같게 준 비교라 사다리꼴이 빠르게 나옵니다. 공정하게 비교하려면 사이클 시간을 같게 맞춘 뒤(예: 사다리꼴의 amax를 낮춰 0.596 s로) 피크 토크와 저크를 보세요 — 과제 1.

아치(문) 궤적#

trajectory.arch_path(p0, p1, height, radius)는 pick & place용 "문" 모양 경로입니다.

  1. p0에서 수직으로 올라가 이동 높이 z_top = max(z_0, z_1) + height 근처까지
  2. 반지름 radius의 1/4 원으로 꺾어 수평 이동
  3. 다시 1/4 원으로 꺾어 p1까지 수직 하강

radius를 주지 않으면 height/2를 쓰고, 수직 구간·수평 거리의 절반보다 커지지 않도록 잘립니다. 경로 전체가 하나의 프로파일로 시간 스케일링되므로, 모서리에서 멈추지 않습니다.

python시뮬 실행 가능
import math
from deltarobot import DeltaDesign, DeltaRobot
from deltarobot import dynamics as dyn

d = DeltaDesign.preset("industrial_picker").copy(payload=0.5)
print("아치 높이  반지름   사이클   피크   max|a| [m/s^2]")
for h, rad in ((0.025, 0.001), (0.025, 0.0), (0.025, 0.025), (0.04, 0.04)):
    robot = DeltaRobot(d, scene="empty")
    robot.set_speed(3.0, 30.0)
    z = robot.scene.surface_z + 0.02
    robot.move_to(-0.1525, 0, z)
    n0 = len(robot.backend.frames)
    t0 = robot.time
    robot.arch_to(0.1525, 0, z, height=h, radius=rad)
    robot.arch_to(-0.1525, 0, z, height=h, radius=rad)
    T = robot.time - t0
    r = robot.analyze()
    data = dyn.analyze(d, robot.backend.frames)[n0:]
    amax = max(math.sqrt(sum(c * c for c in f["a"])) for f in data)
    print("  %2.0f mm   %4.1f mm   %.3f s  %5.2f   %6.1f" % (
        h * 1000, (rad or h / 2) * 1000, T, r["peak_ratio"], amax))
text
아치 높이  반지름   사이클   피크   max|a| [m/s^2]
  25 mm    1.0 mm   0.615 s   0.56     77.6
  25 mm   12.5 mm   0.606 s   0.44     61.8
  25 mm   25.0 mm   0.596 s   0.36     50.3
  40 mm   40.0 mm   0.612 s   0.39     54.8

가속도 설정은 30 m/s²인데 실제 TCP 가속도 최댓값은 50~78 m/s²입니다. 차이는 모서리의 원심 가속도입니다. 모서리를 25 mm로 둥글리면 경로가 짧아져 사이클도 빨라지고(0.615 → 0.596 s) 피크 비도 0.56 → 0.36으로 줄어듭니다. 아치를 40 mm로 높이면 경로가 길어져 다시 느려집니다. 결론: 장애물을 넘는 데 필요한 만큼만 높이고, 모서리는 가능한 한 크게.

궤적 설계 체크리스트
  1. 아치 높이 = 넘어야 할 가장 높은 것(상자 벽, 이웃 부품) + 여유 10 mm 정도.
  2. 모서리 반지름 = 아치 높이(최대). 수직 구간이 꼭 필요할 때만(구멍에 꽂기 등) 줄인다.
  3. 기본은 scurve. 사이클이 부족하면 amax를 먼저 올리고, 그래도 부족할 때 quintic/cycloidal을 검토.
  4. 속도·가속도를 올린 뒤에는 반드시 robot.analyze()와 유지력(D05)을 다시 확인.
  5. 여러 점을 이어 그리는 작업(그리기·도포)은 move_path()로 한 프로파일에 묶되, 날카로운 꼭짓점에서는 멈추게 한다(D10).
