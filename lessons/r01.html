R01deltarobot 라이브러리와 Playground

DeltaRobot 클래스, 백엔드 구조, 좌표·단위 규약을 익히고 브라우저 Playground에서 첫 동작을 실행합니다.

선수 챕터: T04
Python Playground

학습 목표#

  • deltarobot 패키지의 모듈 구성과 DeltaRobot 클래스가 하는 일(경로 계획 → IK·한계 검사 → 모터각 스트림)을 설명합니다.
  • 백엔드 네 가지(record, websim, ros2, serial)의 역할과 차이를 구분합니다.
  • 좌표·단위 규약, 특히 TCP(툴 끝)와 이펙터 중심의 차이를 코드로 확인합니다.
  • 브라우저 Playground에서 첫 프로그램을 실행하고, record 백엔드의 가상 시간이 어떻게 흐르는지 이해합니다.

라이브러리 한눈에 보기#

deltarobot은 이 강의의 모든 계산을 담당하는 순수 파이썬 패키지입니다. 의존성이 없어서 브라우저(Pyodide)와 PC, ROS 2 노드에서 같은 코드가 돌아갑니다.

모듈역할주요 이름
design.py설계 파라미터와 카탈로그DeltaDesign, DeltaDesign.preset(), catalog()
kinematics.py역·순기구학, 야코비안, 작업영역 (이펙터 중심 기준)ik, fk, jacobian, limit_report, Unreachable
dynamics.py모터 토크 계산과 검증joint_torques, analyze, evaluate
trajectory.py속도 프로파일과 경로Profile, line_path, arch_path, sample_path
scene.py작업대·부품·상자·컨베이어Scene, default_scene
robot.py학생이 쓰는 고수준 API (TCP 기준)DeltaRobot, WorkspaceError, EmergencyStop
urdf.py설계값으로 URDF 생성generate, joint_state
backends/모터각 스트림을 보낼 곳record, websim, serial, ros2
data/catalog.json모터·감속기·재질·툴·프리셋 카탈로그 (JS 시뮬레이터와 공용)

PC에서는 저장소 루트에서 pip install -e python으로 설치하고, Playground에서는 설치 없이 import deltarobot이 됩니다.

DeltaRobot이 하는 일#

robot.arch_to(...) 한 줄은 내부에서 네 단계를 거칩니다.

  1. 경로 계획 — 현재 위치에서 목표까지 직선(move_to) 또는 아치(arch_to) 경로를 만듭니다.
  2. 속도 프로파일 샘플링 — 기본 scurve 프로파일로 10 ms 간격의 점을 뽑습니다.
  3. IK와 한계 검사 — 모든 점에서 모터각을 구하고, 모터각·볼조인트각·팔꿈치각 한계를 검사합니다. 하나라도 넘으면 로봇을 움직이기 전에 WorkspaceError를 냅니다.
  4. 스트림 전송 — (시각, (θ1, θ2, θ3)) 목록을 백엔드로 넘깁니다.

백엔드#

이름용도시간주요 옵션속도 초과 시

실물로 가는 백엔드(serial, ros2)만 속도 초과를 거부합니다. 그래서 Playground에서 경고가 한 번이라도 나왔다면 실물에서는 그 동작이 실행되지 않습니다. 경고를 없애고 넘어가는 습관을 들이세요.

좌표·단위 규약#

  • 단위는 m, rad, kg, s입니다. 3 cm는 0.03이고, 각도를 도(°)로 쓰려면 move_joints(..., degrees=True)처럼 명시합니다.
  • 원점은 베이스 중심(모터축이 놓인 평면), z는 위쪽이라 작업 공간은 z < 0입니다.
  • 팔 1·2·3의 방위각은 0°, 120°, 240°이고 팔 1이 +x 방향입니다.
  • 모터각 θ는 위팔이 수평일 때 0, 아래로 내려가면 +입니다.
  • DeltaRobot의 위치 인자와 robot.position은 TCP(툴 끝) 좌표입니다. deltarobot.kinematics의 함수와 robot.effector는 이펙터 중심 좌표입니다. 둘의 차이는 툴 길이만큼입니다: TCP = 이펙터 중심 − (0, 0, tool.length).
TCP와 이펙터 중심을 섞지 마세요

kinematics.ik(d, p)에 부품 윗면 좌표를 그대로 넣으면 툴 길이(흡착컵 suction_20은 45 mm)만큼 부품을 파고드는 모터각이 나옵니다. 로봇을 움직일 때는 항상 robot.ik(), robot.move_to()처럼 TCP 기준 메서드를 쓰세요.

실습 1: 첫 프로그램#

Playground 열기

아래 코드를 Playground에 붙여 넣고 실행 버튼(또는 Ctrl+Enter)을 누르세요. 오른쪽 시뮬레이터가 기록된 동작을 재생합니다.

import time

robot = DeltaRobot("edu_servo", scene="empty")
print(robot)
print("TCP 위치 [m]:", [round(v, 3) for v in robot.position])
print("모터각 [rad]:", robot.joints)

robot.home()

square = [(0.04, 0.04), (-0.04, 0.04), (-0.04, -0.04), (0.04, -0.04), (0.04, 0.04)]
robot.move_to(square[0][0], square[0][1], z)
for x, y in square[1:]:
    robot.move_to(x, y, z)
    print("t=%.2f s  TCP=(%.3f, %.3f, %.3f)" % ((robot.time,) + robot.position))

time.sleep(0.5)                  # Playground에서는 가상 시간 0.5 s

robot.home()

읽어 볼 점:

  • 로봇은 홈 자세(세 모터 모두 0.35 rad)에서 시작합니다. 이때 TCP는 베이스 아래 24.6 cm입니다.
  • DeltaRobot("edu_servo")의 첫 인자는 설계입니다. 프리셋 이름, DeltaDesign, dict, "파일.json"을 받을 수 있습니다.
  • 한 변 8 cm를 가는 데 약 0.63 s가 걸립니다. 기본 속도는 0.25·(L+l)/0.43 m/s이며, edu_servo(L+l = 0.32 m)에서는 약 0.19 m/s입니다. 가속·감속 구간이 있어서 평균 속도는 이보다 낮습니다.
Playground에서 설계와 장면이 정해지는 방식
  • DeltaRobot()처럼 설계를 비우면 시뮬레이터에서 마지막으로 쓴 설계와 장면을 씁니다.
  • DeltaRobot("edu_servo")처럼 프리셋을 주면, 시뮬레이터의 설계가 같을 때만 그 장면을 그대로 쓰고, 다르면 같은 종류의 장면을 이 설계 크기에 맞게 다시 만듭니다.
  • scene="pick_place", "conveyor", "drawing", "empty"를 직접 주면 그 장면이 우선합니다. 이 트랙의 예제는 결과가 늘 같도록 설계와 장면을 모두 적습니다.

실습 2: TCP와 이펙터, IK 확인#

python시뮬 실행 가능
import math
from deltarobot import DeltaRobot, WorkspaceError

robot = DeltaRobot("edu_servo", scene="empty")
d = robot.design
print("툴 길이 %.3f m" % d.tool_length)
x, y, z = robot.position
ex, ey, ez = robot.effector
print("TCP     z = %.4f m" % z)
print("이펙터  z = %.4f m (차이 %.3f m)" % (ez, ez - z))

q = robot.ik(0.05, 0.0, -0.27)
print("ik(0.05, 0, -0.27) =", [round(math.degrees(v), 1) for v in q], "deg")
print("fk로 되돌리면     =", [round(v, 4) for v in robot.fk(*q)])

for p in [(0.0, 0.0, -0.20), (0.0, 0.0, -0.30), (0.15, 0.0, -0.27)]:
    print(p, "도달 가능" if robot.reachable(*p) else "도달 불가")
try:
    robot.move_to(0.15, 0.0, -0.27)
except WorkspaceError as e:
    print("WorkspaceError:", e)

  • +x 쪽(팔 1 방향)으로 5 cm 가면 팔 1은 덜 내려가고(15.8°) 팔 2·3은 더 내려갑니다(43.0°). T04에서 유도한 IK와 같은 결과입니다.
  • -0.0은 부동소수점 오차(약 10⁻¹⁷)가 반올림된 것이라 0과 같습니다.
  • WorkspaceError 메시지는 어떤 한계에 걸렸는지 알려 줍니다. move_to는 경로를 만들기 전에 목표점부터 검사하므로 로봇은 움직이지 않습니다.

record 백엔드와 가상 시간#

Playground의 파이썬은 브라우저 안에서 돕니다. 실제로 0.5 s를 기다리면 화면이 멈추므로, record 백엔드는 시계를 직접 넘기는 방식으로 동작합니다.

  1. 이동 명령은 10 ms 간격의 (t, q) 샘플을 만들고, record는 이를 frames 목록에 붙인 뒤 가상 시각을 마지막 샘플의 t로 즉시 옮깁니다. 계산은 순식간에 끝나지만 기록상으로는 그만큼 시간이 흐릅니다.
  2. robot.wait(s)는 같은 자세를 0.05 s 간격으로 s초 동안 기록합니다.
  3. Playground는 time.sleep, time.time, time.monotonic, time.perf_counter를 가상 시계로 바꿔 둡니다. 그래서 time.sleep(0.5)는 robot.wait(0.5)와 같습니다.
  4. 프로그램이 끝나면 기록 전체(설계, 장면, frames, 흡착 이벤트)가 내장 시뮬레이터로 넘어가 재생되고, 결과 요약(총 시간, 모터 검증)이 표시됩니다.
  5. 가상 시간이 time_limit(기본 600 s)를 넘으면 RuntimeError로 멈춥니다. while True: 무한 루프를 막는 장치입니다.

동작마다 위치를 찍어 보고 싶으면 verbose=True를 주세요. DeltaRobot의 나머지 키워드 인자는 백엔드 옵션으로 전달됩니다.

같은 코드를 PC에서

PC에서 pip install -e python 후 같은 파일을 python my_first.py로 실행해도 됩니다(백엔드 기본값이 record). 다만 PC에는 time.sleep 가상화가 없으므로, 기다릴 때는 time.sleep 대신 robot.wait()을 쓰는 습관을 들이세요. 모든 백엔드에서 올바르게 동작합니다.

체크포인트

자주 나는 오류와 해결#

KeyError: "unknown preset 'edu_sevro' (choose from edu_servo, edu_dynamixel, printer_stepper, industrial_picker)"#

  • 원인: 프리셋 이름 오타입니다.
  • 해결: 메시지에 나온 네 이름 중 하나를 씁니다.

ValueError: unknown backend 'sim' (record | websim | serial | ros2)#

  • 원인: 백엔드 이름이 틀렸습니다. 웹 시뮬레이터 실시간 연결은 "websim"입니다.

WorkspaceError: 작업영역 밖: (0.000, 0.000, -0.100) m — 팔 길이로 닿지 않음#

  • 원인: 목표가 팔 길이로 닿지 않습니다. 흔한 실수는 단위(mm를 m 자리에) 와 z 부호(작업은 z < 0)입니다. (0, 0, 0.25)를 주면 모터 각도 한계가 납니다.
  • 해결: robot.reachable(x, y, z)로 먼저 확인하고, 시뮬레이터 조그 탭에서 닿는 범위를 살펴봅니다.

WorkspaceError: 모터 3 각도 100.0° 가 한계 [-40.1°, 85.9°] 밖입니다#

  • 원인: move_joints에 한계 밖 각도를 줬거나, degrees=True 없이 도 단위를 넣었습니다(라디안 100은 한계를 크게 넘습니다).

ValueError: profile: trapezoid, scurve, quintic, cycloidal#

  • 원인: set_profile("s-curve")처럼 없는 프로파일 이름을 줬습니다. 하이픈 없이 "scurve"입니다.

RuntimeError: 가상 시간 600 s 제한을 넘었습니다 (무한 루프인가요?)#

  • 원인: while True: 안에서 time.sleep()이나 robot.wait()만 반복하는 등 끝나지 않는 루프입니다.
  • 해결: 종료 조건(시간, 남은 부품 수)을 넣습니다. 정말 긴 작업이면 DeltaRobot(..., time_limit=1200)처럼 늘립니다.

과제#

개인 과제
  1. 실습 1을 고쳐 반지름 4 cm 원을 36개 점의 move_to로 그리고, 한 바퀴 시간을 출력합니다. 같은 원을 robot.move_path(points)(점들을 한 번의 속도 프로파일로 잇는 메서드)로 그리면 시간이 얼마나 줄어드는지 비교하고 이유를 한 문장으로 씁니다.
  2. set_profile()로 네 가지 프로파일을 바꿔 가며 정사각형 사이클 시간을 표로 정리합니다.
  3. robot.reachable()로 z = −0.27 m 평면에서 x를 1 cm씩 늘려 도달 가능한 최대 x를 찾고, 시뮬레이터 분석 탭의 작업 실린더 지름과 비교합니다.
