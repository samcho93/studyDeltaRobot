T08동역학과 모터 토크

질량을 나누어 붙이는 간이 모델로 중력·관성 토크와 τ = Jᵀ F를 계산하고, 피크·RMS 토크의 의미를 이해합니다.

선수 챕터: T06 T07
시뮬레이터Python Playground

학습 목표#

  • 델타로봇의 질량을 "위팔 쪽"과 "이펙터 쪽"으로 나누어 붙이는 간이(lumped) 동역학 모델을 설명하고, 각 질량·관성 항을 계산할 수 있습니다.
  • 관절 토크 식 τᵢ = I·θ̈ᵢ − k_g·g·cos θᵢ + (Jᵀ·m_p·(a − g_vec))ᵢ의 각 항의 의미와 부호(+ = 팔을 아래로)를 설명할 수 있습니다.
  • 출력축 토크·속도를 모터축으로 바꾸고(τm = τ/(N·η), ωm = θ̇·N), 피크·RMS 토크와 속도-토크 곡선으로 모터를 검증할 수 있습니다.
  • 감속비에 따른 반사 관성과 관성비의 의미를 이해하고, static_torques()와 DeltaRobot.analyze()로 설계를 평가할 수 있습니다.

왜 간이 모델인가#

델타로봇의 정확한 강체 동역학(라그랑주 방정식 + 닫힌 사슬 구속)은 식이 길고, 볼조인트·로드의 회전 관성까지 넣으면 더 복잡해집니다. 모터 선정 단계에서는 로드의 질량을 양끝에 반씩 나눠 붙이는 근사가 널리 쓰입니다(Codourey 1998 등). 로드는 가볍고 가늘어서 자기 회전 관성이 작고, 양끝이 볼조인트라 축력만 받으므로 이 근사가 잘 맞습니다. 라이브러리 deltarobot.dynamics는 이 모델을 그대로 구현합니다(JS 버전 assets/js/delta/dynamics.js와 결과가 같도록 테스트됩니다).

모델#

질량 나누기#

기호라이브러리내용
m_armupper_arm_mass위팔 관 (L × 선밀도) + 허브 0.02 kg. 무게중심 L/2
m_elbowelbow_mass팔꿈치 가로 막대 (w × 로드 선밀도) + 피팅 0.01 kg. 위치 L
m_pairforearm_pair_mass로드 2개 (2l × 선밀도) + 볼조인트 컵 4개(각 0.004 kg)
m_pmoving_plate_mass이펙터 판 + 툴 + 페이로드 + 로드 쌍 절반 × 3

팔 쪽 (팔마다, 출력축 기준)#

text
I   = m_arm·L²/3 + (m_elbow + ½·m_pair)·L² + I_drive       (arm_inertia)
k_g = m_arm·L/2  + (m_elbow + ½·m_pair)·L                  (gravity_moment)
I_drive = N²·(J_rotor + J_gearbox)        (일체형 서보는 카탈로그의 output_inertia)

위팔은 한쪽 끝을 축으로 도는 막대(m·L²/3), 팔꿈치 쪽 질량은 반지름 L의 점질량(m·L²)으로 봅니다.

이펙터 쪽 (세 팔 공통)#

이펙터 판(질량 m_p)이 가속도 a로 움직이려면 세 팔이 판에 주어야 하는 힘은

text
F = m_p·(a − g_vec),    g_vec = (0, 0, −g)     →   F = m_p·(aₓ, a_y, a_z + g)

가만히 있어도(a = 0) 판을 떠받치려면 위로 m_p·g가 필요합니다. 이 힘을 내는 관절 토크는 T06의 가상일 원리로 τ = Jᵀ·F입니다.

관절 토크 (출력축, τ > 0 = 팔을 아래로 미는 방향)#

text
τᵢ = I·θ̈ᵢ  −  k_g·g·cos θᵢ  +  (Jᵀ·m_p·(a − g_vec))ᵢ
     관성        팔 자체 중력         이펙터 판 (중력 + 관성)

부호를 하나씩 확인합니다.

  • 팔 중력 항 −k_g·g·cos θ: 팔의 무게는 팔을 아래로(+θ) 돌리려 합니다. 모터는 이것을 버텨야 하므로 음(−)의 토크(위로 들어 올리는 방향)가 필요합니다. 수평(θ = 0)에서 가장 크고 팔이 수직에 가까워지면 줄어듭니다.
  • 판 항: J의 z 성분은 음수입니다(θ가 커지면 이펙터가 내려감, T06). 위쪽 힘 F_z = m_p·g > 0에 음수를 곱하므로 역시 음의 토크입니다.
  • 결론: 무게를 들고 있는 정지 상태의 토크는 음수가 정상입니다. 부호가 +로 나오면 모델이나 부호 규약을 의심하세요.
  • 관성 항 I·θ̈: 팔을 아래로 가속(θ̈ > 0)하려면 + 토크.

라이브러리 코드(요약):

python
m = design.moving_plate_mass
f = (m * a[0], m * a[1], m * (a[2] + G))           # force the arms must apply to the plate
jtf = [J[0][c] * f[0] + J[1][c] * f[1] + J[2][c] * f[2] for c in range(3)]   # J^T F
tau = [I * theta_dd[i] - k * G * math.cos(theta[i]) + jtf[i] for i in range(3)]

모터축으로 옮기기#

text
τm = τ / (N·η)        (N: 감속비, η: 감속기 효율 — 일체형 서보는 N = 1, η = 1)
ωm = θ̇ · N

모터 검증(evaluate())은 궤적 전체에서 다음을 봅니다. 안전율(기본 1.2)을 곱해 비교합니다.

지표계산기준의미
peak_ratiomax |τm| × 안전율 / 피크 토크≤ 1순간 최대 토크
rms_ratioRMS(τm) × 안전율 / 정격 토크≤ 1발열(연속 운전)
speed_ratiomax ωm / 최고 속도≤ 1속도 한계
curve_ratiomax(τm × 안전율 / 그 속도에서 낼 수 있는 토크)≤ 1속도-토크 곡선
inertia_ratio부하 관성(모터축 환산) / 로터 관성참고값제어 응답·안정성

RMS 토크는 √((1/T)·∫τm²dt)입니다. pick & place는 가감속이 반복되므로 피크는 커도 평균 발열(RMS)은 작을 수 있고, 반대로 긴 정지 유지(중력 부하)는 RMS를 올립니다. 스테퍼는 탈조(스텝 잃음)가 조용히 일어나므로 라이브러리가 곡선 여유를 50% 더 둡니다(STEPPER_MARGIN = 1.5).

감속비와 반사 관성#

감속비 N을 키우면 모터축 토크는 1/N로 줄지만, 모터 로터 관성은 출력축에서 N²배로 보입니다(반사 관성). 반대로 부하 관성은 모터축에서 1/N²로 보입니다.

text
관성비 = (부하 관성 / N²) / J_rotor
       (라이브러리: 부하 = 팔 관성 − 구동부 관성 + m_p·L²/3  (이펙터 판의 대략적 환산))

관성비가 너무 크면 서보 게인을 올리기 어려워 진동·오버슈트가 생기기 쉽고, 너무 작으면 모터 관성만 돌리느라 에너지를 씁니다. 권장 범위는 제조사·드라이브마다 다르므로(흔히 수 배 ~ 10배 이내를 권함) 데이터시트를 확인하세요. 일체형 서보(RC, Dynamixel)는 라이브러리가 관성비를 0으로 둡니다.

실습 A — 정적 토크 나누어 보기#

python시뮬 실행 가능
import math
from deltarobot import DeltaDesign
from deltarobot import dynamics as dyn
from deltarobot import kinematics as kin
from deltarobot.design import G

d = DeltaDesign.preset("edu_dynamixel")
print("m_arm=%.4f m_elbow=%.4f m_pair=%.4f kg" % (d.upper_arm_mass, d.elbow_mass, d.forearm_pair_mass))
print("m_p (moving plate) = %.4f kg" % d.moving_plate_mass)
print("I_arm = %.3e kg m^2 (drive part %.1e), k_g = %.5f kg m" % (d.arm_inertia, d.drive_inertia, d.gravity_moment))

# static torque split into the two terms of the model
print("\n point                arm-gravity    plate (J^T F)    total        [N m]")
for p in [(0.0, 0.0, -0.22), (0.0, 0.0, -0.28), (0.0, 0.0, -0.36), (0.12, 0.0, -0.28), (-0.12, 0.0, -0.28)]:
    th = kin.ik(d, p)
    tau = dyn.static_torques(d, p)
    grav = [-d.gravity_moment * G * math.cos(t) for t in th]
    plate = [t - g for t, g in zip(tau, grav)]
    print(" %-20s %s  %s  %s" % (p, [round(v, 3) for v in grav], [round(v, 3) for v in plate],
                                  [round(v, 3) for v in tau]))

# worst static torque over the workspace and the motor side value
worst = max(max(abs(t) for t in dyn.static_torques(d, p)) for p in kin.workspace_points(d, 0.02))
m = d.motor_spec
print("\nworst static |tau| over workspace = %.3f N m  (motor %s: rated %.2f, peak %.2f N m)"
      % (worst, d.motor, m["rated_torque"], m["peak_torque"]))

읽는 법

  • m_p = 0.4445 kg: 판 0.06 + 그리퍼 + 페이로드 0.2 + 로드 쌍 절반 × 3. 이 무게 m_p·g ≈ 4.36 N를 세 팔이 나눠 듭니다.
  • 중심축 위에서는 세 팔 토크가 같고 모두 음수입니다. 판 항이 팔 중력 항보다 약 3~5배 커서, 페이로드·툴 무게가 모터 부하를 좌우합니다.
  • 중심에서 z에 따라 토크가 변합니다(−0.28에서 가장 큼). Jᵀ가 자세에 따라 바뀌기 때문입니다. 팔 중력 항은 θ가 커질수록(cos θ↓) 줄어듭니다.
  • (0.12, 0, −0.28): 팔 1 쪽으로 치우치면 팔 1이 하중 대부분(−0.509)을 집니다.
  • (−0.12, 0, −0.28): 팔 1 반대편. 팔 1의 판 항이 양수(+0.071)입니다. 세 로드 힘의 합이 수직 하중과 평형을 이루려면 수평 성분도 상쇄돼야 해서, 멀리 떨어진 팔 1은 오히려 판을 끌어당기는(팔을 아래로 미는) 방향의 토크를 냅니다. "모든 팔이 항상 위로 든다"는 직관이 틀릴 수 있다는 예입니다.
  • 작업영역 전체의 최대 정적 토크 0.622 N·m는 XM430 정격(1.40 N·m, 카탈로그 대표값)보다 작습니다. 하지만 동작 중에는 관성 항이 더해집니다(실습 B).

실습 B — pick 사이클 검증 (DeltaRobot.analyze())#

record 백엔드(Playground 기본)는 동작을 가상 시간으로 기록합니다. analyze()는 기록된 프레임에서 속도·가속도를 중앙 차분으로 구하고, 위 모델로 토크를 계산한 뒤 evaluate()로 모터를 검증합니다. 아래 코드는 ±0.1 m를 25 mm 아치로 오가는 축소판 Adept 사이클을 속도별로 비교합니다.

python시뮬 실행 가능
from deltarobot import DeltaRobot

def cycle(speed, accel):
    robot = DeltaRobot("edu_dynamixel")
    robot.set_speed(speed, accel)                   # m/s, m/s^2 (TCP)
    robot.move_to(-0.1, 0.0, -0.34)
    t0 = robot.time
    for _ in range(3):                              # Adept-like cycle, scaled down
        robot.arch_to(0.1, 0.0, -0.34, height=0.025)
        robot.arch_to(-0.1, 0.0, -0.34, height=0.025)
    return (robot.time - t0) / 3, robot.analyze(safety_factor=1.2)

print("speed  accel | cycle[s] | peak  rms   speed curve | ok")
for v, a in [(0.3, 3.0), (0.5, 5.0), (0.6, 6.0), (1.5, 30.0)]:
    tc, res = cycle(v, a)
    print("%4.1f  %5.1f  |  %5.2f   | %4.2f  %4.2f  %4.2f  %4.2f | %s" % (
        v, a, tc, res["peak_ratio"], res["rms_ratio"], res["speed_ratio"], res["curve_ratio"], res["ok"]))
print("peak motor torque per arm at 0.6 m/s:", [round(x, 3) for x in cycle(0.6, 6.0)[1]["peak_torque_motor"]], "N m")
print("problems at 1.5 m/s:")
for p in res["problems"]:
    print(" -", p)

읽는 법

  • 0.3 → 0.5 m/s로 올리면 사이클(왕복 1회)이 2.00 → 1.36 s로 줄고 모든 지표가 1 이하입니다.
  • 0.6 m/s에서는 피크(0.33)·RMS(0.35)·속도(0.84)가 모두 여유 있는데도 실패합니다. curve_ratio = 1.45 — 스마트 서보는 빠르게 돌수록 낼 수 있는 토크가 직선으로 줄어서(그림), 최고 속도의 84%로 돌 때 남는 토크가 필요한 토크보다 작기 때문입니다. 피크 토크만 보고 모터를 고르면 안 되는 이유입니다.
  • 1.5 m/s·30 m/s²에서는 관절 속도가 모터 한계(4.8 rad/s)를 넘어 record 백엔드가 경고를 출력하고(serial·ros2는 이런 동작을 거부), 네 가지 검사가 모두 실패합니다. curve_ratio가 inf인 것은 최고 속도를 넘는 순간 낼 수 있는 토크가 0이기 때문입니다.
  • 가운데 경로(y = 0, 팔 1 방향)를 오가므로 팔 1의 피크 토크(1.122 N·m)가 팔 2·3(0.626)보다 큽니다.

감속비와 관성비 — industrial_picker#

python시뮬 실행 가능
from deltarobot import DeltaDesign
from deltarobot import dynamics as dyn

# industrial preset: gearbox, reflected inertia and inertia ratio
d = DeltaDesign.preset("industrial_picker")
m = d.motor_spec
N, eta = d.ratio, d.efficiency
print("motor %s, gearbox %s N=%g eta=%.2f" % (d.motor, d.gearbox, N, eta))
print("rotor J = %.2e, drive inertia at output N^2 (Jm + Jg) = %.3e kg m^2" % (m["rotor_inertia"], d.drive_inertia))
print("arm inertia (output side, incl. drive) = %.3e kg m^2" % d.arm_inertia)
print("inertia ratio (load / rotor, at motor) = %.1f" % dyn.inertia_ratio(d))
for n in (10, 20, 30, 50):
    dn = d.copy(gear_ratio=n)
    tau_out = max(abs(t) for t in dyn.static_torques(dn, (0.0, 0.0, -0.9)))
    print("N=%2d  static tau_out=%.2f N m -> tau_m=%.3f N m, inertia ratio=%.1f, max output speed=%.1f rad/s"
          % (n, tau_out, tau_out / (n * dn.efficiency), dyn.inertia_ratio(dn), m["max_speed"] / n))

읽는 법

  • N = 20에서 모터·감속기의 반사 관성(0.0144 kg·m²)이 출력축 전체 관성(0.0229)의 60% 이상입니다. 감속기를 쓰는 설계에서는 모터 자신의 관성이 큰 부하가 됩니다.
  • N을 키우면 모터 토크는 1/N로, 관성비는 1/N²로 줄지만 출력축 최고 속도도 1/N로 줄어듭니다. N = 50이면 출력축 10.5 rad/s밖에 못 돌아 고속 피킹에 부족할 수 있습니다.
  • 감속비 선택은 토크 여유 · 관성비 · 최고 속도의 절충입니다. 설계 트랙 D04에서 모터·감속기 조합을 이 기준으로 고릅니다.

자주 나는 오류와 해결#

1) 정지 토크가 양수로 나옴 (부호 반대)#

  • 원인: 모터각 부호(아래로 +)를 반대로 쓰거나, 중력 벡터를 +g로 넣었습니다(a − g_vec에서 g_vec = (0, 0, −g)).
  • 해결: 수평 팔이 무게를 들 때 τ = −k_g·g < 0인지 먼저 확인합니다. 라이브러리 규약은 "+ = 팔을 아래로"입니다. 실물 서보의 전류 부호는 설치 방향에 따라 또 다를 수 있습니다.

2) RuntimeError: analyze()는 record 백엔드에서 기록된 동작에만 쓸 수 있습니다#

  • 원인: websim·serial·ros2 백엔드에서 robot.analyze()를 불렀거나, 아직 아무 동작도 하지 않았습니다.
  • 해결: 같은 코드를 DeltaRobot(..., backend="record")로 먼저 돌려 검증하고(드라이런), 그다음 실제 백엔드로 실행합니다.

3) 경고: 관절 속도 6.64 rad/s 가 모터 한계 4.80 rad/s(감속 후)를 넘습니다 — set_speed()로 속도를 낮추세요#

  • 원인: 직교 좌표 속도(set_speed)가 커서 어떤 자세에서 관절 속도가 모터 최고 속도/N을 넘었습니다. 경계 근처(κ 큰 곳, T06)에서 특히 커집니다.
  • 해결: 속도를 낮추거나 경로를 작업영역 중심 쪽으로 옮깁니다. record·websim은 경고만 하지만 serial·ros2는 WorkspaceError로 거부합니다.

4) 피크·RMS는 통과인데 속도-토크 곡선 초과#

  • 원인: 고속 구간에서 모터가 낼 수 있는 토크가 줄어든 것을 고려하지 않았습니다(실습 B의 0.6 m/s).
  • 해결: 속도를 낮추거나, 감속비를 키워 모터 속도 비율을 낮추거나, 곡선이 평평한 모터(AC 서보 등)를 고릅니다.

5) 출력축 토크와 모터축 토크를 혼동#

  • 원인: joint_torques()·static_torques()는 출력축(감속 후) 값입니다. evaluate()의 peak_torque_motor는 모터축 값입니다.
  • 해결: 모터 데이터시트와 비교할 때는 τm = τ/(N·η)로 바꿉니다. 일체형 서보(RC, Dynamixel)는 카탈로그 토크가 이미 출력축 값이므로 N = 1로 둡니다.

6) KeyError: "unknown preset 'edu-servo' (choose from edu_servo, edu_dynamixel, printer_stepper, industrial_picker)"#

  • 원인: 프리셋 이름 오타(하이픈 - 대신 밑줄 _). DeltaRobot("edu-servo")도 같은 오류가 납니다.
  • 해결: 메시지에 나온 이름 중 하나를 그대로 씁니다. 값을 바꿔 비교할 때는 d.copy(payload=0.5)처럼 새 설계를 만들어 원래 프리셋과 나란히 둡니다.
