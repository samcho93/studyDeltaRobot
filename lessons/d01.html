학습 목표#

  • 시뮬레이터의 다섯 탭(설계 · 조그 · 작업 · 분석 · 연결)이 각각 무엇을 하는지 알고, 설계 → 검증 → 수정의 흐름으로 쓸 수 있습니다.
  • 분석 탭의 모터 속도 ω·토크 τ 그래프를 한계선과 비교해 읽고, "어디서 왜" 한계를 넘는지 설명할 수 있습니다.

화면 구성#

시뮬레이터 열기

시뮬레이터는 설치 없이 브라우저에서 동작합니다. 가운데 3D 화면에 로봇이 보이고, 옆 패널의 다섯 탭으로 모든 기능을 씁니다. 상단에는 비상정지 버튼(PC Python·ROS 2와 연결되어 있으면 정지 명령을 보냄), 테마 전환, 다른 도구(URDF 뷰어, Playground, 기구학 실험실)로 가는 링크가 있습니다.

탭하는 일이 트랙에서 주로 쓰는 곳

설계 탭 — [설계 검증]#

설계 탭의 [설계 검증] 은 지금 설계로 두 가지를 계산해 보여 줍니다.

  1. 작업 실린더 D×H — 어느 방향으로든 도달할 수 있는 원기둥 (T07, kinematics.work_cylinder)
  2. 표준 사이클의 모터 검증 결과 — 정해진 동작을 돌려 보고 피크 토크·RMS 토크·속도 등이 모터 한계 안에 있는지 ✔/✖

파생값 표에는 위팔 질량, 이동판 질량(이펙터 + 툴 + 페이로드 + 아래팔 절반), 팔 관성, 정적 토크가 나옵니다. 값을 하나 바꿀 때마다 이 표가 어떻게 변하는지 보는 습관이 설계 감각을 가장 빨리 키웁니다.

조그 탭 — 한계를 손으로 느끼기#

TCP 슬라이더를 움직이면 역기구학으로 모터각이 계산되고, 모터 슬라이더를 움직이면 순기구학으로 TCP가 계산됩니다. 모터각 한계, 볼조인트 각도 한계, 팔꿈치 각도 한계(20°~165°) 중 하나라도 넘으면 해당 값이 빨간색이 됩니다. 작업영역 가장자리로 갈수록 조건수가 커지는 것도 여기서 확인합니다(T06).

작업 탭과 분석 탭 — 움직이고, 재고, 판정하기#

작업 탭에서 장면과 데모 프로그램을 고르고 재생하면, 분석 탭에 그 동작의 그래프와 검증 결과가 나옵니다. Playground에서 실행한 Python 프로그램의 동작도 같은 방식으로 재생·분석됩니다.

그래프 읽는 법#

분석 탭의 그래프는 세 모터의 곡선 + 한계선으로 되어 있습니다. 아래 그림은 edu_servo(MG996R급 RC 서보)로 180 mm짜리 축소 Adept 사이클을 일부러 빠르게(0.6 m/s, 6 m/s²) 돌린 결과를 같은 방식으로 그린 것입니다.

읽는 순서는 다음과 같습니다.

  1. 속도(위) — 곡선이 빨간 최고 속도선에 닿으면 모터가 그 속도로 돌 수 없습니다. 이 예에서는 최대 5.01 rad/s로 한계 6.0 rad/s 아래입니다.
  2. 피크 토크(아래, 빨간선) — 필요 토크의 최댓값 0.46 N·m는 피크 1.08 N·m의 절반도 안 됩니다. 여기까지만 보면 "통과"처럼 보입니다.
  3. 속도-토크 곡선(아래, 점선) — RC 서보는 빨리 돌수록 낼 수 있는 토크가 직선으로 줄어듭니다(peak × (1 − ω/ω_max), D04). 빠르게 도는 바로 그 순간에 필요한 토크가 점선 위로 올라가면 불합격입니다. 이 예의 검증 결과는 curve_ratio = 2.32, 문제 목록은 속도-토크 곡선 초과: 해당 속도에서 낼 수 있는 토크보다 큰 토크가 필요합니다 입니다.
  4. 정격 토크(아래, 주황선) — 순간값이 아니라 RMS(제곱 평균) 와 비교합니다. 짧게 넘는 것은 괜찮지만 평균이 넘으면 모터가 뜨거워집니다.
피크선만 보면 속습니다

"최대 토크 < 피크 토크, 최대 속도 < 최고 속도" 두 조건을 따로 만족해도, 높은 속도와 큰 토크가 동시에 필요하면 모터는 따라가지 못합니다. 검증 결과의 속도-토크 곡선 비(curve_ratio)가 1을 넘는지 꼭 확인하세요.

설계 공유와 다른 도구로 넘기기#

  • URL 파라미터 — sim/index.html?preset=edu_servo는 프리셋으로, ?scene=conveyor는 장면을 골라 엽니다. 둘을 함께 써도 됩니다(아래 버튼).
  • 공유 링크 복사 (연결 탭) — 현재 설계 전체가 URL의 #design=... 부분에 담깁니다. 메신저로 보내면 받는 사람이 같은 설계를 엽니다.
  • 설계 JSON 내보내기/불러오기 (연결 탭) — 보고서에 첨부하거나 PC Python에서 DeltaRobot("my_design.json"), DeltaDesign.load("my_design.json")으로 읽습니다.
  • URDF 내려받기 (연결 탭) — D07에서 자세히 다룹니다.
  • 자동 공유 — 시뮬레이터에서 마지막으로 쓴 설계는 브라우저에 저장되어 URDF 뷰어와 Playground가 같은 설계로 열립니다. 단 Playground 코드에 DeltaRobot("edu_servo")처럼 설계를 적으면 코드의 설계가 우선합니다.

예: 산업용 프리셋 + 컨베이어 장면으로 열기

실습 (시뮬레이터)#

실습 A — 다섯 탭 한 바퀴
  1. 프리셋 edu_dynamixel을 고르고 [설계 검증] 을 누릅니다. 작업 실린더 D×H와 ✔/✖를 기록합니다.
  2. 조그 탭에서 TCP x를 끝까지 밀어 처음으로 빨간색이 되는 값(모터각·볼조인트·팔꿈치 중 무엇인지)을 기록합니다.
  3. 작업 탭에서 장면 "분류", 데모 "분류 데모"를 재생합니다. 재생 배속을 바꿔 보세요.
  4. 분석 탭에서 τ 그래프의 가장 큰 봉우리가 동작의 어느 순간(들어 올림 / 가로 이동 / 내려놓음)인지 찾습니다.
  5. 연결 탭에서 공유 링크를 복사해 새 탭에 붙여 넣고, 같은 설계가 열리는지 확인합니다.
실습 B — 일부러 한계 넘기기
  1. 프리셋 edu_servo, 장면 "빈 작업대", 데모 "Adept 사이클"을 고릅니다.
  2. 궤적 설정의 속도와 가속도를 조금씩 올리며 재생하고, 분석 탭 검증 결과에 처음 ✖가 뜨는 설정을 찾습니다.
  3. 그때 그래프에서 속도·토크 곡선이 한계선과 어떤 관계인지 위의 "그래프 읽는 법" 순서대로 설명합니다.

실습 (Python Playground)#

같은 설계·장면을 Python으로도 움직일 수 있습니다. Playground에서 열기를 누르면 실행 결과가 오른쪽 내장 시뮬레이터에서 재생됩니다.

python시뮬 실행 가능
from deltarobot import DeltaRobot

robot = DeltaRobot("edu_dynamixel", scene="pick_place")
print(robot)
robot.home()
print("홈 TCP 위치 [m]:", tuple(round(v, 3) for v in robot.position))
print("부품 %d개, 상자 %d개" % (len(robot.parts()), len(robot.bins())))

# 첫 부품을 집어 같은 색 상자에 놓기
p = robot.parts()[0]
b = [b for b in robot.bins() if b["color"] == p["color"]][0]
robot.arch_to(p["x"], p["y"], p["top"])
robot.tool_on()
robot.wait(0.2)
robot.arch_to(b["x"], b["y"], robot.scene.surface_z + b["h"] + 0.02)
robot.tool_off()
print("점수:", robot.scene.score(), " 경과 시간 %.2f s" % robot.time)

res = robot.analyze()
print("피크 %.2f  RMS %.2f  속도 %.2f  ->  %s" % (
    res["peak_ratio"], res["rms_ratio"], res["speed_ratio"], "통과" if res["ok"] else res["problems"]))
text
DeltaRobot(motor=dxl_xm430_w350, tool=gripper_servo, backend=RecordBackend)

analyze()의 피크·RMS 비는 (필요 토크 × 안전율 1.2) / 모터 한계, 속도 비는 최대 모터 속도 / 최고 속도(안전율 없음)입니다. 1보다 작으면 통과이고, 0.16처럼 작으면 모터가 넉넉하다는 뜻입니다.

자주 나는 오류와 해결#

증상·메시지원인해결
조그 슬라이더 값이 빨갛게 바뀌고 로봇이 따라오지 않음모터각·볼조인트·팔꿈치 한계 초과조그 탭 표시에서 어떤 한계인지 보고 반대 방향으로
경고: 관절 속도 ... rad/s 가 모터 한계 ... rad/s(감속 후)를 넘습니다 — set_speed()로 속도를 낮추세요Playground(record)는 경고만 하고 계속 실행robot.set_speed()로 낮추고, 실물용 serial·ros2 백엔드는 이 경우 WorkspaceError로 거부된다는 점을 기억
Playground에서 시뮬레이터와 다른 설계가 나옴코드의 DeltaRobot("프리셋")이 우선시뮬레이터 설계를 쓰려면 설계 인자를 비우거나 JSON으로 내보내 사용
공유 링크를 열었는데 기본 설계가 나옴#design= 뒤가 잘림(메신저 줄바꿈 등)연결 탭에서 다시 복사하거나 설계 JSON 파일로 전달
