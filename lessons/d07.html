D07URDF 모델링

닫힌 사슬을 트리로 표현하는 방법(가상 이펙터 관절 + 수동 관절 mimic)과 설계값으로 URDF를 생성·검증합니다.

선수 챕터: T02 T05 D01
URDF 뷰어

학습 목표#

  • URDF가 트리만 표현할 수 있어 델타로봇 같은 닫힌 사슬을 그대로 적을 수 없는 이유를 설명할 수 있습니다.
  • deltarobot.urdf가 쓰는 표현(능동 모터 관절 + 수동 팔꿈치 pitch/yaw 관절 + b 로드 mimic + 가상 prismatic 이펙터 관절)을 트리로 그릴 수 있습니다.
  • 설계값으로 URDF를 생성하고(CLI·Python·시뮬레이터), joint_state()로 수동 관절 값을 계산해 URDF 뷰어에서 검증할 수 있습니다.

닫힌 사슬과 URDF#

URDF(Unified Robot Description Format)는 링크(link)와 관절(joint)로 로봇을 적는 XML 형식입니다. 각 링크는 부모 관절이 하나뿐이어야 하므로 전체 구조가 반드시 트리가 됩니다. 그런데 델타로봇의 이펙터는 세 팔 모두에 매달려 있어 부모가 셋입니다(T02의 닫힌 사슬).

해결 방법은 두 가지를 섞는 것입니다.

  1. 사슬을 끊는다 — 각 팔은 아래팔 끝(볼조인트)에서 끝나고, 이펙터와 연결하지 않습니다.
  2. 이펙터를 따로 매단다 — 베이스에서 x·y·z 세 개의 가상 prismatic 관절로 이펙터를 매답니다.
  3. 값으로 닫는다 — 모터각 θ₁~θ₃가 정해지면 순기구학으로 이펙터 위치와 모든 수동 관절 각도를 계산해 넣습니다. 계산이 맞으면 끊어진 사슬이 닫혀 보입니다.

deltarobot.urdf 의 트리#

관절종류값을 정하는 방법
motor{i}_joint (i = 1, 2, 3)revolute, 능동모터각 θᵢ (위팔 수평 0, 아래로 +)
elbow{i}a_pitch, elbow{i}a_yawrevolute, 수동kinematics.passive_angles() — 아래팔 방향을 위팔 기준 pitch·yaw로 분해
elbow{i}b_pitch, elbow{i}b_yawrevolute, 수동, mimica 로드와 같은 값(평행사변형이라 두 로드는 항상 평행)
effector_x, effector_y, effector_zprismatic, 가상순기구학 fk()로 구한 이펙터 중심 위치
tool_joint, tcp_jointfixed툴 길이만큼 아래 (TCP)

아래팔 좌표계는 Rz(φᵢ)·Ry(θᵢ)·Ry(pitch)·Rz(yaw)이고 x축이 로드 방향입니다. 그래서 pitch는 위팔에 대한 상대각이고, yaw는 로드가 팔 평면 밖으로 벌어진 각도(볼조인트 각도)와 같습니다.

생성된 URDF에서 몇 개의 관절을 직접 봅시다(edu_dynamixel).

python시뮬 실행 가능
from deltarobot import DeltaDesign
from deltarobot import urdf

text = urdf.generate(DeltaDesign.preset("edu_dynamixel"))
lines = text.splitlines()
print(lines[1])
for name in ('"motor1_joint"', '"elbow1b_pitch"', '"effector_z"'):
    i = next(k for k, s in enumerate(lines) if "<joint name=" + name in s)
    j = next(k for k in range(i, len(lines)) if "</joint>" in lines[k])
    print("\n".join(lines[i:j + 1]))
text
<!-- generated by deltarobot.urdf — R=0.1 r=0.035 L=0.13 l=0.3 w=0.05 motor=dxl_xm430_w350 tool=gripper_servo -->
  <joint name="motor1_joint" type="revolute">
    <parent link="base_link"/>
    <child link="upper_arm1"/>
    <origin xyz="0.1 0 0" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="-0.7" upper="1.5" effort="4.1" velocity="4.8"/>
  </joint>
  <joint name="elbow1b_pitch" type="revolute">
    <parent link="upper_arm1"/>
    <child link="elbow1b_link"/>
    <origin xyz="0.13 -0.025 0" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="-3.141593" upper="3.141593" effort="0" velocity="0"/>
    <mimic joint="elbow1a_pitch" multiplier="1" offset="0"/>
  </joint>
  <joint name="effector_z" type="prismatic">
    <parent link="effector_y_link"/>
    <child link="effector"/>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <axis xyz="0 0 1"/>
    <limit lower="-0.43" upper="0" effort="0" velocity="0"/>
  </joint>
  • 모터 관절은 베이스 반지름 R = 0.1 m 위치에서 y축을 중심으로 돕니다. y축 둘레 +회전은 x축(위팔)을 아래(−z)로 내리므로 "아래로 +" 규약과 맞습니다.
  • limit의 effort·velocity는 설계에서 옵니다: effort = 피크 토크 × 감속비 × 효율, velocity = 최고 속도 / 감속비 (XM430 직결이라 4.1 N·m, 4.8 rad/s).
  • b 로드는 팔꿈치 축에서 −w/2(= −0.025 m) 옮긴 곳에 붙고, <mimic>으로 a 로드 값을 따라갑니다.
  • effector_z의 범위는 −(L + l) = −0.43 m ~ 0입니다.

각 링크의 <inertial>에는 설계의 질량(upper_arm_mass, forearm_pair_mass/2, effector_mass, 툴 질량)이 들어가고, <visual>은 원기둥·구·상자로 단순하게 그립니다. 재질·치수를 바꾸면 URDF도 그대로 따라 바뀝니다.

수동 관절 값 계산: joint_state()#

urdf.joint_state(design, theta)는 mimic이 아닌 모든 관절의 값을 돌려줍니다. ROS 2 드라이버(R05)와 URDF 뷰어가 이 계산을 합니다.

python시뮬 실행 가능
import re
from deltarobot import DeltaDesign
from deltarobot import urdf

d = DeltaDesign.preset("edu_dynamixel")
text = urdf.generate(d)
joints = re.findall(r'<joint name="([^"]+)" type="([^"]+)"', text)
print("링크 %d개, 관절 %d개, mimic %d개" % (
    len(re.findall(r"<link name=", text)), len(joints), text.count("<mimic ")))
for kind in ("revolute", "prismatic", "fixed"):
    names = [n for n, t in joints if t == kind]
    print("  %-9s %2d: %s ..." % (kind, len(names), ", ".join(names[:4])))

h = d.home_theta
state = urdf.joint_state(d, (h, h + 0.2, h))          # 팔 2만 0.2 rad 더 내림
for k in ("motor1_joint", "motor2_joint", "elbow1a_pitch", "elbow1a_yaw",
          "elbow2a_pitch", "elbow2a_yaw", "effector_x", "effector_y", "effector_z"):
    print("  %-14s % .4f" % (k, state[k]))
print("  (joint_state 는 %d개 값 — b 로드는 mimic 이라 없음)" % len(state))
text
링크 21개, 관절 20개, mimic 6개
  revolute  15: motor1_joint, elbow1a_pitch, elbow1a_yaw, elbow1b_pitch ...
  prismatic  3: effector_x, effector_y, effector_z ...
  fixed      2: tool_joint, tcp_joint ...
  motor1_joint    0.3500
  motor2_joint    0.5500
  elbow1a_pitch   1.8387
  elbow1a_yaw    -0.0802
  elbow2a_pitch   1.7666
  elbow2a_yaw    -0.0000
  effector_x      0.0139
  effector_y     -0.0240
  effector_z     -0.2883
  (joint_state 는 12개 값 — b 로드는 mimic 이라 없음)
  • 관절 20개 = 능동 3 + 수동 12(팔 3 × 로드 2 × pitch·yaw) + 가상 3 + 고정 2. 이 중 mimic 6개를 빼면 독립 값은 14개이고, 고정 2개를 빼면 joint_state()의 12개입니다.
  • 팔 2만 내렸더니 이펙터가 아래로 내려가면서 팔 2 방향(φ = 120°: −x, +y)의 반대쪽(+x, −y)으로 움직였습니다. 위팔이 내려가면 팔꿈치 반지름 R + L cos θ가 줄어 팔꿈치가 중심 쪽으로 들어오고, 길이가 일정한 로드가 이펙터를 반대쪽으로 밀기 때문입니다 — T05의 순기구학을 떠올려 보세요.
  • 팔 2의 yaw는 0입니다. 이펙터가 팔 2의 평면(φ = 120°) 안에서만 움직였기 때문입니다. 팔 1은 평면 밖으로 밀려 yaw = −0.08 rad(볼조인트 각도 4.6°)가 생겼습니다.
수동 관절 값을 계산하지 않으면

URDF만 로드하고 수동 관절을 0으로 두면 아래팔이 위팔과 일직선으로 뻗고 이펙터는 베이스 원점에 붙어 사슬이 산산이 흩어져 보입니다. URDF 뷰어의 [수동 관절 계산 끄기] 토글로 직접 확인하세요. RViz에서도 joint_states에 수동 관절 값을 넣어 주는 노드(R05)가 반드시 필요합니다.

URDF 만들기 — 세 가지 방법#

  1. 시뮬레이터 — 연결 탭의 URDF 내려받기. 지금 설계 그대로 파일이 됩니다.
  2. PC 명령줄 (저장소 루트에서 pip install -e python 후)
bash
python -m deltarobot.urdf --preset edu_dynamixel -o delta.urdf
python -m deltarobot.urdf --design my_design.json -o delta.urdf     # 시뮬레이터에서 내보낸 설계 JSON
python -m deltarobot.urdf --preset industrial_picker --name picker -o picker.urdf

-o를 빼면 URDF를 화면(표준 출력)으로 내보냅니다. 한국어 Windows 콘솔에서 > 파일로 돌리면 첫 줄 주석의 — 문자 때문에 인코딩 오류가 날 수 있으니 항상 -o 옵션을 쓰세요.

  1. Python — urdf.generate(design, name="delta_robot")는 문자열을 돌려줍니다(파일 쓰기는 직접). 위의 Playground 예제가 이 방법입니다.

URDF 뷰어와 Python이 똑같은 텍스트를 만들도록 JS 구현(assets/js/delta/urdf.js)과 Python 구현을 테스트로 맞춰 두었습니다.

실습 (URDF 뷰어)#

실습 A — 닫힌 사슬이 닫혀 보이는 원리
  1. 시뮬레이터에서 edu_dynamixel을 고른 뒤 URDF 뷰어를 엽니다(현재 설계가 자동으로 넘어옵니다).
  2. θ1~θ3 슬라이더를 움직여 수동 관절이 자동으로 계산되는 것을 봅니다. 링크 트리에서 effector_x/y/z 값이 바뀌는지 확인합니다.
  3. [수동 관절 계산 끄기]를 켜고 같은 슬라이더를 움직입니다. 어떤 링크가 어디로 가는지 기록합니다.
  4. URDF 텍스트 보기에서 motor1_joint의 limit을 찾아 설계 탭의 모터각 한계·모터와 비교합니다.
  5. 설계 탭에서 모터를 ac_servo_400w + 유성 20:1로 바꾸고 URDF를 다시 열어 effort·velocity가 어떻게 바뀌었는지 확인합니다.
스스로 확인
  • joint_state()가 돌려주는 12개 값 중 모터 관절이 아닌 9개는 각각 무엇인가요?
  • b 로드의 pitch·yaw가 a 로드와 같다는 가정이 성립하려면 어떤 기구 조건이 필요하나요?
  • 가상 prismatic 관절에 effort="0"이 들어간 이유는 무엇일까요? 이 관절로 로봇을 "제어"할 수 있나요?
팀 미션 — 우리 설계의 URDF 검증

D08~D10 중 하나의 최종 설계를 URDF로 만들고 (1) 링크·관절 개수, (2) 세 가지 자세(홈, 작업 실린더 가장자리 두 곳)에서의 joint_state() 값, (3) URDF 뷰어 캡처(수동 관절 계산 켬/끔)를 한 장의 검증표로 제출하세요. 이펙터 위치는 robot.effector와 비교해 1 mm 이내여야 합니다.

과제#

  1. urdf.generate() 결과에서 모든 <inertial>의 질량을 더해 보고, design.moving_plate_mass와 팔 질량 합과 비교하세요. 어디가 다르고 왜 그런가요?
  2. joint_state()로 계산한 값에서 로드 끝(볼조인트)의 위치를 직접 계산해(위팔 → pitch → yaw → 길이 l), kinematics.ball_joint()와 같은지 확인하는 코드를 작성하세요.
  3. URDF의 한계를 쓰지 않고 트리를 만드는 다른 방법(예: 이펙터를 팔 1에 매달고 팔 2·3을 끊기)의 장단점을 이 강의의 방법과 비교하세요.
