T07작업영역

관절 한계·볼조인트 각·팔꿈치 각이 작업영역을 어떻게 깎는지 보고, 실제로 쓸 수 있는 작업 실린더를 계산합니다.

선수 챕터: T06
시뮬레이터Python Playground

학습 목표#

  • 델타로봇의 작업영역이 팔 세 개의 도달 영역(토러스 모양 입체)의 교집합이라는 것을 설명할 수 있습니다.
  • 모터각 한계, 볼조인트 각 한계, 팔꿈치 각 한계(ELBOW_MIN 20°, ELBOW_MAX 165°)가 작업영역을 어디서, 왜 깎는지 설명할 수 있습니다.
  • 볼조인트 한계가 |y′| ≤ l·sin(한계각)이라는 높이와 무관한 경계를 만든다는 것을 유도할 수 있습니다.
  • 산업용 사양서의 작업 실린더(D × H) 개념을 이해하고 work_cylinder(), workspace_points()로 계산할 수 있습니다.

도달 영역 — 세 입체의 교집합#

팔 i 하나만 생각합니다. 팔꿈치 Eᵢ는 모터축을 중심으로 반지름 L인 원 위를 돌고, 볼조인트 쌍 Bᵢ는 Eᵢ에서 거리 l인 구 위에 있습니다. 원 위의 모든 점에 반지름 l인 구를 붙여 쓸어 가면 토러스(도넛)를 닮은 입체가 됩니다. 델타에서는 l > L이라 가운데 구멍이 메워진 모양입니다. 이 입체가 Bᵢ가 갈 수 있는 곳이고, 이펙터 중심은 P = Bᵢ − r·uᵢ이므로 입체를 r만큼 안쪽으로 옮긴 것이 팔 i가 허락하는 P의 영역입니다.

작업영역 = 세 팔이 모두 허락하는 영역 = 세 입체의 교집합. 120°씩 돌아간 세 입체가 겹치는 곳이라 위에서 보면 둥근 삼각형·육각형, 옆에서 보면 위가 볼록하고 아래가 둥근 버섯·돔 모양이 됩니다. 수학적으로 여기서 벗어나면 IK의 |K| > ρ가 되어 Unreachable입니다(T04).

이 "팔 길이로 닿는" 영역이 전부 쓸 수 있는 영역은 아닙니다. 실제 기구는 관절마다 움직일 수 있는 범위가 있어서, 라이브러리는 limit_report(d, p)로 네 가지를 검사합니다.

검사조건 (라이브러리)물리적 의미주로 깎는 곳
unreachableIK 해 없음 (|K| > ρ)팔 길이로 닿지 않음바깥 경계, 맨 아래
thetaNθ < θmin 또는 θ > θmax모터·기구 스토퍼, 케이블, 베이스 간섭위쪽(팔이 너무 올라감), 멀리 반대편
ballN|yaw| > ball_joint_limit볼조인트 컵이 공에서 빠지거나 부딪힘옆쪽 (팔 평면에서 먼 방향)
elbowN팔꿈치 사잇각 < 20° 또는 > 165°너무 접혀 부딪힘 / 너무 펴져 1형 특이점 근접맨 위(접힘), 경계(펴짐)

N은 팔 번호(1~3)입니다. DeltaRobot은 이 목록을 "모터 각도 한계", "볼조인트 각도 한계", "팔꿈치 각도 한계", "팔 길이로 닿지 않음"으로 바꿔 WorkspaceError: 작업영역 밖: (x, y, z) m — ... 메시지를 만듭니다.

볼조인트 한계의 닫힌 식#

라이브러리는 로드가 팔 평면 밖으로 기운 각(yaw)을 볼조인트 각으로 봅니다. 팔 좌표계에서 로드 벡터는 s = B − E = (a − L·cos θ, y′, z + L·sin θ)이고 길이가 l이므로

text
sin(yaw) = y′ / l     →    |yaw| ≤ β   ⇔   |y′| ≤ l·sin β

y′는 이펙터가 팔 i의 평면에서 옆으로 벗어난 거리일 뿐이므로 z, θ와 무관합니다. edu_dynamixel(l = 0.3 m, β = 0.6 rad)에서는 l·sin β = 0.1694 m. 세 팔에 대해 이 조건을 겹치면 위에서 볼 때 육각형 경계가 되고, 높이 방향으로는 기둥 모양이 됩니다. 그래서 그림에서 좌우 경계가 수직선이고, T06 조건수 지도가 육각형으로 잘린 것입니다. 작업 실린더의 반지름도 이 값을 넘을 수 없습니다.

실습 A — 점마다 무엇이 걸리는지 보기#

python시뮬 실행 가능
import math
from deltarobot import DeltaDesign
from deltarobot import kinematics as kin

d = DeltaDesign.preset("edu_dynamixel")
pts = [(0.0, 0.0, -0.28), (0.15, 0.0, -0.28), (0.0, 0.18, -0.28), (-0.21, 0.0, -0.28),
       (0.0, 0.0, -0.17), (0.0, 0.0, -0.43), (0.25, 0.0, -0.30)]
for p in pts:
    rep = kin.limit_report(d, p)
    if rep["theta"] is None:
        print("%-22s -> %s" % (p, rep["problems"]))
        continue
    print("%-22s -> ok=%-5s problems=%-18s theta(deg)=%s ball(deg)=%s elbow(deg)=%s" % (
        p, rep["ok"], rep["problems"],
        [round(math.degrees(v), 1) for v in rep["theta"]],
        [round(math.degrees(v), 1) for v in rep["ball"]],
        [round(math.degrees(v), 1) for v in rep["elbow"]]))

# the ball-joint limit bounds |y'| <= l * sin(limit), independent of z
print("l * sin(ball_joint_limit) = %.4f m" % (d.l * math.sin(d.ball_joint_limit)))

읽는 법

  • (0, 0.18, −0.28): 팔 1 평면(x–z)에서 옆으로 y′ = 0.18 m 벗어나 볼조인트 1이 36.9°(> 0.6 rad = 34.4°)가 됩니다. 0.18 > 0.1694이므로 식과 맞습니다.
  • (−0.21, 0, −0.28): 팔 1 반대편 멀리. 팔 1이 97°까지 내려가야 해서 θmax(85.9°)를 넘고, 팔 2·3은 |y′| = 0.866 × 0.21 = 0.182 m라 볼조인트 한계를 넘습니다.
  • (0, 0, −0.17): 너무 높아 세 팔이 −36.7°로 올라가고 팔꿈치가 18.9°로 접힙니다(ELBOW_MIN 20° 미만). 모터각은 한계(−40.1°) 안이지만 팔꿈치가 먼저 걸립니다.
  • (0, 0, −0.43)과 (0.25, 0, −0.30)은 팔 길이로 닿지 않습니다.

작업 실린더 (D × H)#

작업영역의 실제 모양은 복잡하므로 사양서에서는 보통 그 안에 들어가는 가장 큰 직립 원기둥, 즉 작업 실린더 "지름 D × 높이 H"로 표기합니다. 사용자는 "이 원기둥 안의 어디든 갈 수 있다"고 믿고 셀을 설계할 수 있습니다.

라이브러리 work_cylinder(d, height)의 계산 방법:

  1. z = 0부터 −(L + l)까지 40칸으로 나눈 높이마다, 원의 둘레 24방향이 모두 reachable()인 최대 반지름을 찾습니다(max_radius_at(): 바깥으로 걸어가다가 실패하면 이분법). 중심점 (0, 0, z)부터 안 되면 그 높이의 반지름은 0입니다.
  2. 이 반지름 프로파일 위에서 높이 H 창(window)을 위아래로 밀며, 창 안의 최소 반지름이 가장 큰 위치를 고릅니다.
  3. 결과: {"diameter", "height", "z_top", "z_bottom", "profile"} — 모두 이펙터 중심 좌표입니다. TCP로는 툴 길이만큼 아래입니다.

높이는 40칸 격자에 맞춰 반올림되므로 돌려받는 height가 요청값과 약간 다를 수 있습니다(예: 0.08 → 0.075 m).

python시뮬 실행 가능
from deltarobot import DeltaDesign
from deltarobot import kinematics as kin

for name in ("edu_servo", "edu_dynamixel"):
    d = DeltaDesign.preset(name)
    wc = kin.work_cylinder(d, 0.08)
    print("%-14s work cylinder D %.0f mm x H %.0f mm, z %.3f .. %.3f m (effector centre)"
          % (name, wc["diameter"] * 1000, wc["height"] * 1000, wc["z_top"], wc["z_bottom"]))
    print("               TCP z %.3f .. %.3f m (tool %.3f m)"
          % (wc["z_top"] - d.tool_length, wc["z_bottom"] - d.tool_length, d.tool_length))

d = DeltaDesign.preset("edu_dynamixel")
wc = kin.work_cylinder(d, 0.08)
print("radius profile (z, max radius of a full circle):")
for z, rad in wc["profile"][14:40:3]:
    print("   z=%.3f  r=%.3f" % (z, rad))
pts = kin.workspace_points(d, 0.02)
print("workspace_points(step=0.02): %d points, lowest z = %.2f" % (len(pts), min(p[2] for p in pts)))

읽는 법

  • 반지름 프로파일이 z ≈ −0.25 ~ −0.28 m에서 0.169 m로 평평합니다. 바로 볼조인트 한계 l·sin β = 0.1694 m입니다. 이 구간에서는 팔 길이가 아니라 볼조인트가 반지름을 정합니다.
  • 위(z > −0.2)에서는 팔꿈치·모터각 한계 때문에 반지름이 급히 줄고, 아래(z < −0.31)에서는 팔 길이(unreachable) 때문에 줄어듭니다.
  • H를 0.08 m로 요청하면 D 339 mm, 그림의 H = 0.1 m(실제 0.097 m)에서는 D 311 mm입니다. 높이를 크게 잡을수록 지름이 줄어드는 교환 관계입니다.
  • 사양 비교는 TCP 기준으로 합니다. 툴이 길면 같은 로봇이라도 TCP 작업 실린더가 아래로 내려갑니다.
작업 실린더를 넓히려면
  • 볼조인트가 반지름을 정하는 설계라면 l을 늘리거나 볼조인트 허용각이 큰 부품(β↑)을 씁니다. l·sin β가 곧 반지름 상한입니다.
  • 팔 길이가 정하는 구간(아래쪽)은 L과 l을 늘려야 하고, 위쪽은 모터각 하한(θmin)과 팔꿈치 접힘이 정합니다.
  • 설계 트랙 D02(요구사항), D03(암 길이 선정)에서 "필요한 D × H"로부터 역으로 치수를 고릅니다.

실습 B — 시뮬레이터 분석 탭#

시뮬레이터에서 열기

점구름과 작업 실린더
  1. 시뮬레이터 분석 탭에서 작업영역 점구름 표시와 작업 실린더 표시를 켭니다. 점구름이 버섯·돔 모양이고, 옆에서 보면 좌우가 수직으로 잘린 것을 확인합니다.
  2. 설계 탭의 [설계 검증] 버튼을 눌러 작업 실린더 D × H 표시를 기록하고, 위 코드 결과와 비교합니다(툴 기준 차이에 주의).
  3. 설계 탭에서 l을 0.3 → 0.35 m로 바꾸고 다시 검증합니다. D가 얼마나 늘었는지, l·sin 0.6 증가분과 비교합니다.
  4. 조그 탭에서 TCP를 작업 실린더의 모서리(위 가장자리, 아래 가장자리)로 옮겨 볼조인트각·팔꿈치각·모터각 표시가 한계에 얼마나 가까운지(빨간색 여부) 봅니다.

자주 나는 오류와 해결#

1) WorkspaceError: 작업영역 밖: (0.220, 0.000, -0.370) m — 모터 각도 한계, 볼조인트 각도 한계#

  • 원인: 목표가 한계 밖입니다. 팔은 닿아도(IK 해 있음) 관절 한계에 걸렸습니다.
  • 해결: kin.limit_report(d, (x, y, z + d.tool_length))로 어느 팔의 어떤 값이 넘었는지 봅니다. 작업 실린더 안으로 목표를 옮기거나 설계를 바꿉니다.

2) WorkspaceError: 경로 중간 작업영역 밖: ...#

  • 원인: 시작점과 끝점은 작업영역 안이지만 직선 경로·아치 경로 중간이 한계를 벗어났습니다. 작업영역이 볼록(convex)하지 않기 때문입니다. 아치 궤적의 높이(height)를 너무 크게 잡아 위쪽의 팔꿈치 한계에 걸리는 경우가 많습니다.
  • 해결: 아치 높이를 줄이거나, 경유점을 넣거나, move_joint_to()(관절 보간)를 씁니다.

3) 작업 실린더를 TCP로 착각해 툴 길이만큼 틀림#

  • 원인: work_cylinder()의 z_top, z_bottom은 이펙터 중심 좌표입니다.
  • 해결: TCP 기준은 z − d.tool_length. 작업대 높이·컨베이어 높이를 정할 때 반드시 TCP로 바꿔 비교합니다.

4) workspace_points()가 너무 느림#

  • 원인: 격자 간격을 작게 주면 점 수가 간격의 세제곱에 반비례해 늘어납니다(0.01 m면 0.02 m의 약 8배).
  • 해결: 탐색은 0.02 m 정도로 하고, 필요한 단면만 촘촘히 계산합니다. Playground(브라우저)는 PC보다 느립니다.

5) 반지름이 예상보다 작게 나옴 (중심은 되는데 원이 안 됨)#

  • 원인: 작업 실린더는 원 둘레 전체(24방향)가 가능해야 합니다. 한 방향이라도 한계에 걸리면 그 반지름은 실패입니다. 특히 볼조인트 한계는 육각형이라 원이 육각형 안에 내접해야 합니다.
  • 해결: kin.limit_report()로 실패 방향을 찾아보고, 필요하면 한계 자체(ball_joint_limit 등)가 실제 부품 사양과 맞는지 확인합니다. 안전 한계를 임의로 늘리지 마세요.
