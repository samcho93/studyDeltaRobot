R05ROS 2: URDF·RViz·joint_states

설계값으로 생성한 URDF를 robot_state_publisher와 RViz로 띄우고, 수동 관절을 계산해 닫힌 사슬을 표시합니다.

선수 챕터: R04 D07
URDF 뷰어

학습 목표#

  • URDF가 트리 구조만 표현할 수 있어서 델타로봇의 닫힌 사슬을 그대로 담지 못하는 이유를 설명합니다.
  • 이 강의의 해법(능동 관절 + 끝이 열린 수동 관절 + 가상 이펙터 관절 + mimic)을 URDF에서 찾아 읽습니다.
  • robot_state_publisher와 RViz로 설계값에서 생성한 로봇을 띄우고, /joint_states → /tf 흐름을 확인합니다.
  • 수동 관절 값을 계산해 로드 끝이 이펙터의 볼조인트와 정확히 만나는 것을 파이썬으로 검증합니다.

URDF는 왜 닫힌 사슬을 못 담는가#

URDF(Unified Robot Description Format)는 링크와 관절을 XML로 적습니다. 규칙은 단순합니다: 모든 관절은 부모 링크 하나와 자식 링크 하나를 잇고, 각 링크의 부모 관절은 하나뿐입니다. 그래서 URDF 로봇은 언제나 뿌리(root) 링크에서 뻗어 나가는 트리입니다.

델타로봇의 이펙터는 세 팔(각각 로드 두 개, 모두 여섯 개의 로드) 끝에 동시에 매달려 있습니다. 이펙터를 URDF로 쓰면 부모가 여러 개인 링크가 되므로 표현할 수 없습니다. 이것이 T02에서 본 닫힌 사슬(closed kinematic chain)입니다.

로봇 시뮬레이터(Gazebo 등)는 별도 제약 조건으로 사슬을 닫기도 하지만, RViz에 보여 주는 목적이라면 더 간단한 방법이 있습니다. 모든 관절 값을 기구학으로 미리 계산해서 주면, 트리의 끝이 저절로 맞물려 닫힌 것처럼 보입니다.

이 강의의 URDF 모델#

deltarobot.urdf.generate(design)이 만드는 구조입니다(D07에서 설계했고, 웹 URDF 뷰어와 같은 출력).

관절종류개수값은 누가 정하나
motor{i}_jointrevolute (능동)3모터 명령 θᵢ
elbow{i}a_pitch, elbow{i}a_yawrevolute (수동)6드라이버가 FK로 계산
elbow{i}b_pitch, elbow{i}b_yawrevolute, mimic → a6a 로드와 같은 값 (평행사변형)
effector_x, effector_y, effector_zprismatic (가상)3드라이버가 FK로 계산
tool_joint, tcp_jointfixed2툴 길이 (설계값)
  • 평행사변형 → mimic: 한 팔의 두 로드는 평행사변형이라 항상 같은 방향을 향합니다. 그래서 b 로드 관절은 <mimic joint="elbow{i}a_pitch" multiplier="1" offset="0"/>으로 a 로드를 따라 하게 하고, 발행할 값을 줄입니다. robot_state_publisher가 mimic 관절 값을 채워 /tf를 계산합니다.
  • 가상 이펙터 관절: 이펙터는 로드에 붙이지 않고 base_link에서 x·y·z 직선 관절 세 개로 매답니다. 델타로봇의 이펙터는 기울지 않고 평행 이동만 하므로(T02) 3자유도 직선 관절로 충분합니다.
  • 끝이 열린 로드: forearm{i}{a,b} 링크는 자식이 없습니다. 수동 관절 값이 정확하면 그 끝이 이펙터의 볼조인트 위치에 딱 놓입니다.

아래 코드로 생성된 URDF의 구성과, 홈 자세에서 발행해야 할 관절 값을 봅니다.

python시뮬 실행 가능
import math
from deltarobot import DeltaDesign
from deltarobot.urdf import generate, joint_state

d = DeltaDesign.preset("edu_servo")
xml = generate(d)
joints = [l.strip() for l in xml.splitlines() if l.strip().startswith("<joint ")]
print("링크 %d개, 관절 %d개" % (xml.count("<link "), len(joints)))
kinds = {}
for j in joints:
    k = j.split('type="')[1].split('"')[0]
    kinds[k] = kinds.get(k, 0) + 1
print("관절 종류:", kinds, "/ mimic", xml.count("<mimic"))

js = joint_state(d, (d.home_theta,) * 3)
print("joint_state 이름 %d개" % len(js))
for name, v in js.items():
    print("  %-14s % .4f" % (name, v))

관절 20개 중 fixed 2개와 mimic 6개를 빼면 12개가 남습니다. 이것이 R04에서 본 /joint_states의 이름 12개입니다. 홈 자세에서는 세 팔이 대칭이라 pitch가 모두 같고 yaw는 0입니다(-0.0000은 부동소수점 오차).

수동 관절 계산: 사슬이 정말 닫히는가#

joint_state()는 내부에서 다음을 합니다.

  1. 모터각 θ로 순기구학(T05)을 풀어 이펙터 중심 p를 구합니다 → effector_x/y/z.
  2. 팔마다 팔꿈치 위치와 볼조인트 위치를 구하고, 그 방향 벡터를 위팔 좌표계로 옮겨 pitch(위팔 평면 안 각도, 위팔 기준)와 yaw(평면에서 벗어난 각도)로 나눕니다 → kinematics.passive_angles().

URDF의 관절 순서(Rz(φ) → Ry(θ) → Ry(pitch) → Rz(yaw))대로 로드 방향을 다시 조립해, 로드 끝이 볼조인트와 만나는지 확인해 봅니다. 홈이 아닌 비대칭 자세에서 시험합니다.

python시뮬 실행 가능
import math
from deltarobot import DeltaDesign, kinematics as kin

def rot_y(a, v):
    c, s = math.cos(a), math.sin(a)
    return (c * v[0] + s * v[2], v[1], -s * v[0] + c * v[2])

def rot_z(a, v):
    c, s = math.cos(a), math.sin(a)
    return (c * v[0] - s * v[1], s * v[0] + c * v[1], v[2])

d = DeltaDesign.preset("edu_servo")
R, r, L, l = d.base_radius, d.effector_radius, d.upper_arm, d.forearm
theta = kin.ik(d, (0.04, -0.02, -0.22))          # 이펙터 중심 좌표
p = kin.fk(d, theta)
passive = kin.passive_angles(d, theta, p)
print("θ [deg] =", [round(math.degrees(t), 2) for t in theta])
for i in range(3):
    phi, th = kin.PHI[i], theta[i]
    pitch, yaw = passive[i]
    elbow = rot_z(phi, (R + L * math.cos(th), 0.0, -L * math.sin(th)))
    rod = rot_z(phi, rot_y(th, rot_y(pitch, rot_z(yaw, (1.0, 0.0, 0.0)))))
    end = [elbow[k] + l * rod[k] for k in range(3)]                     # 트리로 계산한 로드 끝
    ball = [p[0] + r * math.cos(phi), p[1] + r * math.sin(phi), p[2]]   # 이펙터 쪽 볼조인트
    gap = math.sqrt(sum((end[k] - ball[k]) ** 2 for k in range(3)))
    print("팔 %d: pitch %6.2f° yaw %6.2f°  로드 끝-볼조인트 거리 %.1e m" % (
        i + 1, math.degrees(pitch), math.degrees(yaw), gap))
text
θ [deg] = [16.39, 44.3, 32.52]
팔 1: pitch 102.52° yaw  -5.22°  로드 끝-볼조인트 거리 2.8e-17 m
팔 2: pitch  92.32° yaw  -6.43°  로드 끝-볼조인트 거리 3.5e-17 m
팔 3: pitch  96.98° yaw  11.71°  로드 끝-볼조인트 거리 2.1e-17 m

거리가 10⁻¹⁷ m, 즉 계산 오차 수준으로 0입니다. 트리의 끝이 볼조인트와 정확히 만나므로 화면에서는 닫힌 사슬로 보입니다. 이 코드는 로드 쌍의 중심선으로 확인했습니다. 실제 URDF의 a·b 로드는 중심선에서 ±w/2 떨어져 있지만, 이펙터 쪽 볼조인트도 같은 간격이라 결과는 같습니다. yaw가 커질수록 볼조인트가 많이 꺾이므로, 이 값이 설계의 ball_joint_limit(기본 0.6 rad ≈ 34°)를 넘지 않는지가 작업영역 한계 중 하나입니다(T07).

URDF 뷰어에서 수동 관절 계산 끄기 확인

URDF 뷰어의 [수동 관절 계산 끄기] 토글을 켜면 수동 관절이 0으로 남아 로드가 이펙터와 따로 노는 모습을 볼 수 있습니다. RViz에서 수동 관절 값을 빠뜨렸을 때와 같은 상황입니다.

실습: RViz로 띄우기#

display.launch.py는 launch 시점에 설계로 URDF를 생성해(deltarobot.urdf.generate) robot_state_publisher의 robot_description 파라미터로 넘깁니다. 별도의 .urdf 파일이 필요 없고, 설계를 바꾸면 URDF도 따라 바뀝니다.

bash
source ~/studyDeltaRobot/ros2_ws/install/setup.bash
ros2 launch delta_robot display.launch.py preset:=edu_servo

RViz 설정(rviz/delta.rviz)은 Fixed Frame base_link, RobotModel(Description Topic /robot_description), TF 표시로 되어 있습니다. 다른 터미널에서 목표를 보내며 로봇이 닫힌 사슬을 유지하는지 봅니다.

bash
ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: 0.04, y: -0.02, z: -0.265}"
ros2 topic pub --once /delta/goal geometry_msgs/msg/Point "{x: -0.04, y: 0.03, z: -0.25}"
ros2 run tf2_ros tf2_echo base_link tcp

tf2_echo가 보여 주는 base_link → tcp 변환의 위치(translation)가 보낸 목표와 같아야 합니다. tcp 링크는 이펙터에 툴 길이만큼 붙인 고정 링크라서, TF 트리에서도 TCP 좌표를 바로 읽을 수 있습니다. 첫 번째 목표 (0.04, −0.02, −0.265)는 위 파이썬 예제의 이펙터 중심 (0.04, −0.02, −0.22)에 툴 길이 0.045 m를 뺀 TCP 좌표이므로, RViz에서 같은 자세를 볼 수 있습니다.

시뮬레이터에서 만든 설계로 띄우기#

  1. 웹 시뮬레이터 설계 탭에서 치수·모터·툴을 정합니다.
  2. 연결 탭 → 설계 JSON 내보내기로 파일을 받습니다(예: my_design.json).
  3. design_file로 넘깁니다. preset보다 우선합니다.
bash
ros2 launch delta_robot display.launch.py design_file:=$HOME/my_design.json

URDF 파일이 따로 필요하면 CLI로 만들고 check_urdf(패키지 liburdfdom-tools)로 트리를 검사할 수 있습니다.

bash
python3 -m deltarobot.urdf --design ~/my_design.json -o delta.urdf
check_urdf delta.urdf
드라이버와 커맨더, 브리지는 같은 설계를 써야 합니다

launch 파일은 preset/design_file을 모든 노드에 똑같이 넘깁니다. 노드를 따로 ros2 run으로 띄울 때 설계가 서로 다르면, 커맨더가 계산한 모터각이 드라이버·URDF에서는 다른 위치가 되어 로봇이 엉뚱한 곳에 그려집니다.

체크포인트

자주 나는 오류와 해결#

RViz RobotModel에 No transform from [forearm1a] to [base_link] 같은 상태 오류#

  • 원인: 그 링크로 가는 관절 값이 /joint_states에 없어서 robot_state_publisher가 TF를 만들지 못했습니다. 드라이버가 안 떠 있거나, 직접 만든 노드가 모터 3개만 발행한 경우입니다.
  • 해결: ros2 topic echo /joint_states --once로 이름 12개가 다 있는지 봅니다. 직접 발행한다면 deltarobot.urdf.joint_state(design, theta)의 결과를 전부 넣습니다.

RViz 화면이 비어 있고 Global Status가 Fixed Frame [map] does not exist#

  • 원인: RViz를 설정 파일 없이 따로 실행해 Fixed Frame이 기본값 map입니다.
  • 해결: Fixed Frame을 base_link로 바꾸거나 launch 파일(use_rviz:=true)로 실행합니다. RobotModel의 Description Topic은 /robot_description입니다.

로드가 이펙터와 어긋나 보임#

  • 원인: 노드마다 다른 설계를 썼거나(위 참고), 웹 시뮬레이터에서 바꾼 설계를 design_file로 넘기지 않았습니다. mimic을 지원하지 않는 도구에서는 b 로드가 움직이지 않습니다.
  • 해결: 모든 노드를 한 launch로 같은 preset/design_file로 띄웁니다.

launch 중 ValueError: invalid design: ...#

  • 원인: 설계 JSON이 검증(DeltaDesign.validate())을 통과하지 못했습니다. 예를 들어 아래팔이 너무 짧아 조립이 안 되는 치수입니다.
  • 해결: 시뮬레이터 설계 탭의 [설계 검증] 으로 먼저 확인한 뒤 다시 내보냅니다.

과제#

개인 과제
  1. 생성된 URDF에서 팔 2의 관절 사슬(motor2_joint부터 forearm2b까지)을 따라가며 각 관절의 origin과 axis를 표로 정리합니다.
  2. 두 번째 파이썬 예제를 고쳐 작업영역 가장자리 목표 몇 곳에서 yaw의 최댓값을 구하고, ball_joint_limit과 비교합니다.
  3. preset:=edu_dynamixel과 preset:=edu_servo로 각각 RViz를 띄운 화면을 비교하고, 치수 차이가 화면에서 어떻게 보이는지 캡처와 함께 설명합니다.
