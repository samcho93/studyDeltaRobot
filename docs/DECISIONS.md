# 설계 결정 로그

## 2026-09-24 — 초기 구조

1. **물리 엔진 대신 기구학 + 해석적 동역학**
   델타로봇은 닫힌 사슬이라 브라우저 물리 엔진(MuJoCo WASM 등)으로 다루려면 등식 구속이 필요하고, 교육 목표(설계 검증)는
   접촉·충돌보다 **토크·속도·작업영역**에 있습니다. 그래서 시뮬레이터는 해석적 IK/FK와 간이 동역학(Codourey식 질량 분배)으로
   움직이고, 부품 집기/놓기는 규칙 기반(`scene.py`/`scene.js`)입니다. 한계: 마찰·구조 강성·진동·서보 추종 오차는 모델에 없음.

2. **Python과 JS 두 구현 + parity 테스트**
   Playground(Pyodide)·PC·ROS 2는 Python, 웹 시뮬레이터는 JS가 같은 계산을 해야 합니다. 한쪽만 고치는 실수를 막기 위해
   `tests/test_js_parity.py`가 node로 JS를 실행해 IK/FK/야코비안/토크/프로파일/작업 실린더/장면/URDF 텍스트까지 비교합니다.

3. **Playground는 가상 시간 기록 방식**
   학생 코드를 Web Worker에서 끝까지 실행하며 `record` 백엔드가 프레임을 기록하고, 끝나면 시뮬레이터가 재생합니다.
   `time.sleep`은 가상 시간으로 바뀌어 브라우저를 멈추지 않고, 결과가 결정적이라 채점·비교가 쉽습니다.
   실시간 상호작용이 필요하면 PC의 `websim` 백엔드를 씁니다. (GitHub Pages에서는 COOP/COEP를 켤 수 없어
   SharedArrayBuffer 기반 동기 통신을 쓰지 않음.) 정지는 worker를 종료하고 다시 띄웁니다.

4. **URDF 표현**
   URDF는 트리만 표현하므로 이펙터를 가상 직동 관절 `effector_x/y/z`로 베이스에 매달고, 각 로드는 팔꿈치의
   pitch·yaw 수동 관절(b 로드는 mimic)로 표현합니다. 수동 관절 값은 드라이버/뷰어가 FK로 계산합니다(`urdf.joint_state`).
   Gazebo 같은 동역학 시뮬레이션에는 이 URDF를 그대로 쓸 수 없습니다(닫힌 사슬 구속이 없음).

5. **모터 카탈로그는 대표값**
   특정 제품의 보증 사양이 아니라 교육용 대표값입니다. RC/스마트 서보는 정지토크→무부하속도의 직선 모델,
   스테퍼는 선형화한 풀아웃 곡선 + 50 % 여유, AC 서보·BLDC는 최고 속도까지 피크 토크 유지로 단순화했습니다.

6. **안전 제한**
   `serial`·`ros2` 백엔드와 `delta_driver`는 관절 속도가 모터 한계를 넘으면 거부하고, 각도는 설계 한계로 제한합니다.
   펌웨어는 별도로 −40°~+85° 클램프와 최대 회전 속도 제한을 둡니다(`firmware/README.md`).

7. **시뮬레이터 화면 = URDF 모델** (2026-09-24 추가)
   시뮬레이터는 설계값으로 생성한 URDF를 urdf-loader로 불러와 그리고 관절값만 갱신합니다. 시뮬레이터·URDF 뷰어·RViz가 같은
   모델 데이터를 쓰므로 URDF 생성기의 오류가 바로 화면에 드러납니다. URDF에는 그리퍼 손가락 관절이 없어 URDF 모델에서는
   툴 ON/OFF를 색으로만 표시합니다(기본 도형 모델은 손가락이 움직임).

## 남은 확인 사항

- ROS 2 패키지는 ROS가 없는 환경에서 순수 로직(core.py)과 구문만 테스트했습니다 — Humble/Jazzy 실제 `colcon build`·`ros2 launch` 확인 필요.
- 펌웨어는 컴파일·실물 검증 전입니다. 서보 보정값(1500 µs 영점, 10.3 µs/°)은 초기값입니다.
